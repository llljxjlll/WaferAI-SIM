# 编译产物指令集 P0 契约

> 状态：冻结
> 契约版本：NPU ISA v1 / Program Format v1
> 依据：`编译产物指令集设计计划.md`、`编译产物指令集开发计划.md` 与当前源码审计
> 配套清单：`isa_v1_manifest.md`

## 1. 目的与适用范围

本文关闭开发计划 D-01～D-32 的全部待决项，是 P1～P8 实现、测试和评审的共同输入。实现不得以当前偶然行为覆盖本文；确需改变已冻结的外部 opcode、字段含义、单位或错误语义时，必须升级 ISA 或 program format 版本并重新评审。

本文区分两层格式：

- **外部 ISA record**：编译器生成、跨构建稳定的 ABI；
- **内部 Prim wire**：loader lowering 后交给现有 WorkerCore 的 `vector<sc_bv<128>>`，只要求仓库内版本一致，不作为外部 ABI。

`visibility`、`lifecycle`、`support` 是相互独立的三个维度：

- `visibility`：`public` 或 `internal`；
- `lifecycle`：`stable`、`deprecated`、`reserved`、`tombstone`；
- `support`：`available`、`unsupported`、`experimental`。

完整 PrimId 和 Opcode 清单见 `isa_v1_manifest.md`。

## 2. 通用 ABI 规则

### 2.1 编号与演进

- 外部 `Opcode` 与内部 `PrimId` 均为 `uint8_t`，但必须使用不同强类型和不同注册表；
- `0x00` 不作为内部 PrimId；外部 `0x00` 为 `INVALID`；
- 已发布编号不得改号、复用或改变语义；删除项转为 tombstone；
- 新内部 PrimId 只能从当前最大值之后追加；
- 未知、保留、已知但不支持、能力未开启必须给出不同错误；
- `0xF0～0xFF` 永久保留给 ISA 扩展，不注册 v1 指令。

### 2.2 字节序、单位与公共字段

Program Format v1 只接受 little-endian。所有整数由无符号小端字节编码；有符号数仅在明确声明为有符号时使用二进制补码。

| 字段 | 外部宽度 | 单位与约束 |
|---|---:|---|
| opcode、mode、dtype、direction、reduce_op | `u8` | 未知枚举拒绝 |
| NPU datatype | `u8` | v1 仅 `INT8=0`、`FP16=1` |
| NPU input/data/output offset | `u16` | byte offset，超过 65535 拒绝 |
| NPU shape/param | `u32` | 有效范围 `0..2^30-1`，高两位必须为零 |
| core id、group member、rank、root、tree、phase | `u16` | global core id 或对应索引 |
| group_id、collective_id、epoch、sync_seq | `u32` | `collective_id=0xFFFFFFFF` 保留给纯同步 |
| DTE fsm/token、event tag | `u32` | 具体零值规则由指令定义 |
| HBM/SRAM/remote address、offset | `u64` | byte address/offset |
| size_bytes、length | `u64` | bytes；传输长度必须非零 |
| payload_bits、chunk_bits、stride_bits | `u64` | bits |
| element count | `u64` | elements；与 dtype 相乘必须检查溢出 |
| string/symbol index | `u32` | artifact 局部索引 |
| SRAM region | 最多 64 UTF-8 bytes | 不含 NUL |
| SRAM label | 最多 255 UTF-8 bytes | 不含 NUL |

绝对 SRAM 地址与 `region+offset` 必须恰好二选一。所有窄化转换必须先做范围检查，不允许依靠 `sc_bv` 截断。

## 3. Program Format v1

### 3.1 容器

容器使用固定 64-byte header：

- magic：8 bytes，`NPUPRG1\0`；
- format major/minor：各 `u16`；
- ISA major/minor：各 `u16`；
- header size：`u16`；
- endianness：`u8`，v1 只能为 little-endian；
- feature/capability bitmap：`u64`；
- section count：`u32`；
- section-table offset：`u64`；
- file size：`u64`；
- whole-file CRC32C：`u32`；
- 其余为零保留位。

section descriptor 固定为：

```text
type:u32, flags:u32, offset:u64, size:u64,
count:u32, entry_size:u32, crc32c:u32, reserved:u32
```

必需 section：

1. string table；
2. symbol table；
3. semantic relocation table；
4. core group table；
5. core program index；
6. external ISA record stream；
7. control envelope。

MLA/PD context 是 capability-gated 可选 section。未知必需 section、重叠 section、越界 offset、伪造 count、CRC 不匹配、尾部垃圾均在下发前失败。

### 3.2 外部 record

每条 record 以以下头开始：

```text
opcode:u8, record_version:u8, flags:u16, payload_size:u32
```

payload 使用 opcode 专属的定长头和长度前缀数组，不允许直接嵌入现有内部 128-bit segments。loader 必须执行“完整解析与校验 → 符号解析 → lowering → 全局提交”的两阶段提交，任何错误都不得向任一 core 下发半份程序。

### 3.3 符号与重定位

artifact 中禁止持久化 `g_addr_label_table` 的进程内 ID。symbol record 至少包含：

```text
name_string_id:u32, kind:u8, flags:u8, reserved:u16,
value:u64, size:u64
```

relocation 以语义操作数定位，不做裸字节 patch：

```text
core_index:u32, instruction_index:u32, operand_id:u16,
kind:u8, reserved:u8, symbol_id:u32, addend:i64
```

loader 完整验证后，收集所有标签并按 UTF-8 字节序确定性注册，再生成内部 wire。重复定义、未知符号、kind 不匹配、非法 UTF-8、addend 溢出均拒绝。

### 3.4 Core group

`core_groups` 是 artifact 静态表，不是运行时指令：

- `group_id:u32`，0 保留非法；
- 成员是升序且唯一的 `u16` global core id；
- group 非空，N=1 合法；
- 一个 core 可以属于多个 group；
- v1 同一 group 的全部成员必须位于同一 die；
- group id 不得重复，成员必须是平台上的已知 core。

### 3.5 控制 envelope

artifact 必须显式携带：

- configured core 列表及每核 record 范围；
- source/start 事件列表：目标 core、tag、count；
- terminal core 列表；
- expected CONFIG ACK 数；
- expected DONE 数；
- 空 core 是否仍参与配置 ACK；
- 失败时的统一收尾策略。

ACK/DONE 数必须能由 configured/terminal 表推导，文件中声明值必须与推导值相等。不得从“最后一条指令”或 raw segments 猜 source、terminal 或完成计数。

## 4. D-01～D-16 冻结结论

### D-01：完整 opcode 与 PrimId

- 当前 60 个 `REGISTER_PRIM` 使用 `isa_v1_manifest.md` 的固定内部 PrimId；其中 P1 冻结的 51 项保持原编号，P3～P6 只从尾部追加 `0x34～0x3C`；
- 外部 public Opcode 使用同一文档中的类别区段；
- `PrimFactory::next_id_` 不再用于生产注册；
- 工厂只维护内部 name/PrimId/creator，外部 registry 单独维护 Opcode/schema/lowering/capability；
- 重复 name、PrimId、Opcode、越界和保留号注册必须在启动期失败。

验收：随机注册顺序、release/debug、两次 clean build 产生相同 manifest 和 golden wire。

### D-02：DTE_SEND/DTE_RECV lowering

新增薄内部 `Dte_send_prim` 和 `Dte_recv_prim`，不扩大 legacy `Send_prim/Recv_prim` 的语义。原因是现有 Send 无 `src_addr/length`，Recv 无 `dst_addr/length/src_expect`，且旧路径只发送常量 payload。

新原语必须表达：fsm/token、同步或异步、mode、地址二选一、length、peer/group/tree、来源期望、reduce metadata、真实 payload 和完成点。集合 mode 在 P6 再 lowering，P2P mode 在 P5 接真实数据通路。

验收：legacy Send/Recv golden 不变，新类覆盖全部字段、同步/异步和真实字节往返。

### D-03：外部 ISA 与内部 wire

冻结第 1、3 节的两层结构。外部 ABI 不使用 `sc_bv`、内部 ID 或进程内标签 ID。内部 segment 首段和后续段都必须校验内部 PrimId；段数不符、保留位非零、未知 creator 一律抛出确定性异常。

### D-04：操作数位宽

冻结第 2.2 节单位表。所有 min/typical/max/max+1 均建立 golden；地址、size、payload 的 bit/byte 单位必须出现在字段名或 schema metadata 中。

### D-05：EVENT_SET/EVENT_WAIT

发布独立 public Opcode 和薄内部 event prim，使用专用 `MSG_TYPE::EVENT` 控制消息，不进入普通 DATA/stripe/payload 路径。

event key 为 `{source:u16,destination:u16,tag:u32}`。每次 SET 增加一个 credit；`WAIT(tag,count)` 消耗 count 个 credit，支持提前到达。count=0、未知目的、容量溢出拒绝；程序结束 mailbox 必须为空。

### D-06：core group 位置与成员规则

采用第 3.4 节静态表。允许 group 重叠，不做严格 lockstep 指令一致性运行时检查。跨 die group 在加载期拒绝。

### D-07：GROUP_SYNC key 命名空间

数据 collective 的 `collective_id` 合法范围为 `0..0xFFFFFFFE`；`0xFFFFFFFF` 永久保留为 `RESERVED_GROUP_SYNC_ID`。

`GROUP_SYNC(group_id,sync_seq)` lowering 为：

```text
key={group_id, collective_id=0xFFFFFFFF, epoch=sync_seq}
phase_id=0, release_tree_id=0
```

trace 额外记录 `domain=group_sync`。真实 collective 不能使用该保留 ID。

### D-08：历史计算计费

v1 继承当前行为，不在 ISA 接入中顺手修改：

- RMSNORM 当前 SFU 结果保持现状；
- RELU 计 EXU；
- MAXPOOL 计 SFU；
- MERGE_MATMUL 计 `B*T*C` EXU。

未来修复必须作为独立性能语义变更，重新评审和更新 golden。

### D-09：PD 成本公式

- MATMUL_PD：EXU/VEC 二选一，保留 KV、chunk、batch 和完成副作用；
- ATTENTION_PD：读取 KV，计 EXU+SFU+VEC；
- ROPE_PD：`vec_ops=3*C*sum(batch_info.token_num)` 并更新 KV。

MLA/PD Opcode 先分配，默认 capability gate 关闭；只有 program-aware batch/KV/scheduler fixture 通过后才开放。

### D-10：同 die 广播路由唯一真源

冻结 X-first XY。抽取共享纯函数 `BuildXFirstXYTree(root, sorted_targets, topology)`，返回排序后的 `(router_id, ingress, output_bitmap)`；production 树编程、冲突分析和测试共同调用该函数，不复制算法。

### D-11：ReduceScatter+DCA

v1 初始 capability `reduce_scatter_dca=false`。当前单 root reduce tree 不能证明多目标对称归约；请求该组合时加载期明确拒绝，不允许静默回落。P7 的 N=2/N=4 多目标数据、时序、tree key、FIFO 和 drain 专项通过后才能开启。

### D-12：广播树分批对象

只对实际携带 `tree_id` 并进入 `AtomicMulticastFork` 的 Broadcast 分批，包括 Broadcast、multicast AllGather 的 per-source broadcast、combined AllReduce 的结果 broadcast。Scatter 和 ReduceScatter 结果分发不分配 multicast tree。

### D-13：批大小 K

以 D-10 纯函数得到每棵树的 `(router,output)` 集合；集合相交即有冲突边。按稳定 tree key 排序，使用确定性 first-fit greedy coloring，并受每 Router 64-entry 容量约束。用户 K 只限制每批最大树数，不替代安全证明；无法证明时串行。

### D-14：兼容策略

- `--program` 与 legacy JSON 并存至少一个发布周期；
- 两者同时指定时报错，不设隐式优先级；
- 未使用 `--program` 时旧周期和关键 trace 不变；
- 未知 format major、ISA major、Opcode fail-fast；
- 内部 Prim wire 不承诺跨版本 ABI，外部 artifact 才是稳定 ABI。

### D-15：符号与重定位

采用第 3.3 节格式。不同字符串和符号插入顺序必须得到相同语义和相同 lowering 结果；外部 artifact 不受现有 Set_addr 32-bit 或 Send 12-bit 临时标签 ID 影响。

### D-16：SRAM_CLEAR

public `SRAM_CLEAR(label)` 冻结为 targeted 语义，并新增薄内部 targeted primitive。legacy 无参 `Clear_sram` 保持 clear-all 行为且仅供旧路径使用。

targeted clear 必须：定位唯一有效 label；通过 `AccessUnit{kCompute,kClear}` 清真实字节；释放 task-lifetime region allocation；删除 locator label。missing、double clear、persistent/layer lifetime、nonspillable region 均拒绝。`SRAM_FREE` 只改元数据，不能替代有数据面时序的 CLEAR。

## 5. D-17～D-32 冻结结论

### D-17：DTE_POLL

v1 不发布。外部 `0xC6` 保留为 known unsupported，loader 明确拒绝。内部 `poll_complete` 只可用于 selftest/trace，不能成为程序正确性依赖；重新发布必须先增加可消费结果和控制流机制。

### D-18：DTE_FENCE 与 FENCE_ALL

只发布无参 `DTE_FENCE`。它等待本核全部 DTE token 并完成 drain，必须拒绝携带 token。`FENCE_ALL` 只是编译器别名，不占 Opcode、不产生第二次 trace 或计费。v1 无外部异步 LSU，因此不调用 LSU fence。

### D-19：DTE_ISSUE 与 DTE_SEND/RECV 边界

public `DTE_ISSUE` 只开放三个本地方向：

- `SPM_TO_SPM`；
- `SPM_TO_DRAM`；
- `DRAM_TO_SPM`。

`SPM_TO_REMOTE`、`REMOTE_TO_SPM`、`DRAM_TO_REMOTE` 在该 Opcode 下拒绝。所有 remote 传输唯一使用 `DTE_SEND/DTE_RECV`，不得形成第二套地址、token、数据和计费路径。

### D-20：program 模式平台初始化

把现有 `InitGrid` 拆为公共 `InitPlatform(hardware,simulation,mapping)` 与 JSON workload 初始化。program 模式只调用公共平台初始化和 `config_helper_program`，不伪造 workload JSON。

program v1 明确禁用 GLOBAL_SEND/RECV/LOAD/STORE；不得进入 `GlobalMemInterface(config_helper_base*)` 的 `assert(0)`，而应旁路该组件或构造显式 disabled 实例。artifact 声明 GLOBAL capability 时加载期拒绝。

### D-21：program 控制 envelope

采用第 3.5 节显式 envelope。单源、多源、无 source、空 core、单 terminal、多 terminal 都必须由声明驱动；ACK/DONE 计数必须在仿真前闭合验证。

### D-22：树的按批 program/erase

新增 internal 批级 marker：`TREE_BATCH_BEGIN(batch_id,tree_ids[])` 和 `TREE_BATCH_END(batch_id)`。BEGIN 在本批发送前 program 所需 multicast/reduce entries；END 只能在本批 token、receive 和 barrier 全部完成后 erase。

marker 由 lowering 生成，不是 public Opcode。若实现阶段尚无 marker 生命周期，则 loader 必须按全量常驻 occupancy 检查并拒绝超容量程序，不能只对发送顺序分批。

### D-23：同步分类

新增 `SYNC_PRIM=1<<7`；`COMM_PRIM=1<<5`、`MEM_PRIM=1<<6` 保持计划定义。

- DTE_SEND/RECV 和通信数据原语：COMM；
- LSU、local DTE_ISSUE、SRAM 生命周期、数据准备：MEM；
- WAIT/FENCE/CANCEL、EVENT、GROUP_SYNC、internal barrier：SYNC；
- 每条 decoded 指令按唯一主类别统计，继承类的辅助 bit 不得导致重复计数。

### D-24：SRAM_BIND 生命周期

public `SRAM_BIND` 是 one-shot：绑定跳过其后的 MEM/SYNC 指令，只由下一条成功开始执行的 COMPUTE 消费，消费后立即失效。下一条 COMPUTE 前没有有效 binding 时 loader 或运行时失败；连续两条 COMPUTE 需要两次 binding。

legacy JSON 的 `Set_addr` 保持 persistent 行为，避免改变旧 workload。public lowering 使用独立 one-shot 状态或薄 primitive，不修改 legacy 语义。

### D-25：数据准备原语

`load_expert`、`switch_data`、`parse_input`、`parse_output` 全部保持 internal，不分配 public Opcode。它们按实际行为分类为 MEM，可由 JSON helper 或后续 compiler lowering 的基础访存序列使用，但不能直接出现在 v1 artifact。

### D-26：helper 状态

`Sram_pipeline_prim` 和 `Set_batch` 保持 internal。前者仅作 overlap/selftest oracle，后者由 program envelope/PD adapter 生成；二者不占 public Opcode。其他新增 tree batch marker同样 internal。

### D-27：COLL_BARRIER 与 GROUP_SYNC

`GROUP_SYNC` 是 v1 唯一 public barrier。`COLL_BARRIER`/`Collective_prim` 仅由 collective lowering 作为 internal phase barrier 生成，不占第二个 public Opcode。两者即使复用状态机，也必须使用 D-07 的不同 key 命名空间并分别 trace。

### D-28：collective 中 N

统一 `N=group_size`，每个成员贡献一份。本地贡献不经过网络；root/目标通常接收 `N-1` 份远端贡献，再与本地一份合成 N 份逻辑输入。N=1 时网络 send/recv 为 0，结果等于本地输入，仍可通过 barrier 完成。

所有 mode 的软件 oracle、lowering 计数和 trace 使用同一张 N 定义表。

### D-29：MLA/PD program 上下文

`MATMUL_MLA`、`MATMUL_PD`、`ATTENTION_PD`、`ROPE_PD` 编号稳定但默认 gate 关闭。artifact 必须通过可选 PD context section 表达 request、batch_info、job_type、chunk、KV 引用和生命周期；通用 helper 不得强转为 PD/PDS helper。

缺 context 或 adapter 未完成时加载期报 known but capability disabled。通过 program-aware golden 后仅切换 support/capability，不改 Opcode。

### D-30：普通 Reduce 与对称算法

普通 Reduce 固定为单 root `UNICAST_TX × REDUCE_RX`，只有 root 得到结果。ReduceScatter 和 AllReduce 才使用对称分解。文档、lowering、profile、数据 oracle 均不得把普通 Reduce 描述为多目标对称操作。

### D-31：发布与完成协议

每个 collective phase 固定为 RX-first asynchronous：

1. 所有接收方先发布 receive descriptor/state；
2. 所有发送方异步 issue send；
3. 等待 receive completion；
4. 等待本阶段 send token；
5. 进入 internal phase barrier；
6. 最后一方释放 phase state；若为批末，再执行 TREE_BATCH_END。

禁止所有核先执行可能阻塞的同步 send。正常 progress 不得依赖 watchdog；fsm、token、receive session 和 barrier state 都有唯一释放点。

### D-32：endpoint reduce 数据与整数语义

- sender staging 按升序 sender rank 排列，每份 contribution 使用相同 count/dtype；
- payload 和 SRAM 数值均为 little-endian；
- INT32/INT64 使用二进制补码解释；
- SUM 每一步按目标位宽做模 `2^32` 或模 `2^64` 截断；
- MAX 使用有符号比较，负数必须按 signed INT32/INT64 解释；
- 最终结果只在目标 `dst_addr` 可见；中间 staging 不视为完成；
- 网络写 SRAM 与 endpoint reduction 各执行一次，VEC 周期只计一次。

UINT8 SUM 按模 `2^8`，MAX 按无符号比较。FP 类型在 v1 endpoint reduce 中 unsupported。独立 oracle 必须覆盖负值、最小/最大值、溢出、奇数 count、非对齐和 N=1。

## 6. 阶段门禁

P0 完成后，后续阶段必须遵守：

- P1 不得修改已冻结 Opcode、PrimId 或字段单位；
- P2 不得把内部 segments 当外部文件格式；
- P3 未通过 program context gate 不得开放 MLA/PD；
- P4 不得发布 POLL、第二个 fence、第二个 public barrier 或 remote DTE_ISSUE；
- P5 未实现真实字节读写前，DTE_SEND/RECV 不能声明数据正确；
- P6 必须执行 RX-first async 协议与 N=group_size；
- P7 未通过专项测试不得开放 ReduceScatter+DCA；
- P8 必须证明 token、event、barrier、tree、gather/reduce session、Router residual 全部归零。

任何阶段若发现本文与可验证硬件模型冲突，必须暂停依赖开发，形成 ADR 并重新评审，不能静默修改实现或测试预期。
