# 两天可运行收口方案（S2-Lite / S3-Lite）

> 本方案以当前工作树为起点，目标不是在 48 小时内冒充完成完整 S2/S3，而是先让一个
> **可训练的 Dense 最小模型**和一个**可通信的 MoE 最小模型**通过统一前端产物在
> WaferAI-SIM 中真实结束，并为后续完整 S2/S3 保留稳定扩展点。
>
> 资源约束：最多 root + 3 workers；C++ build、finalizer、resolver 和 official runtime
> 使用唯一串行令牌；每个微阶段最多 2 小时。

## 0. 两天后的硬交付

两天内只承诺下面两个纵向闭环。

### 0.1 S2-Lite：LM-head-only Dense 训练 step

固定最小 case：

- 1 die，DP=TP=PP=EP=1；
- micro_batch_count=1，单 step，固定 shape；
- 复用当前完整 Dense/Transformer forward；
- backbone 与 embedding 冻结；
- 只训练 LM head；
- 执行 CE_FORWARD → CE_BACKWARD → LM_HEAD_WGRAD → SGD_UPDATE；
- 无 gradient bucket、DP collective、ZeRO/FSDP、PP、recompute、AdamW。

完成条件：

1. 从 typed ExperimentSpec 进入唯一 production pass 顺序；
2. forward、loss、loss gradient、LM-head weight gradient、SGD update 均在统一 DAG 中；
3. 生成单一 linked manifest、单一 artifact 和单一 runtime timeline；
4. finalizer 两次 byte-identical，actual-SHA ProgramIo 经 resolver 验证；
5. simulator 两次结束，ACK/DONE/drain、HBM/SRAM、gradient/update marker 和 makespan 稳定；
6. evidence 明确 timing=true、training_structure=true、model_functional=false。

可声明：S2-Lite LM-head training execution preview complete。

不得声明：S2-N dense full train-step complete。

### 0.2 S3-Lite：静态路由 MoE inference

固定最小 case：

- 2 dies，EP=2，其余并行度为 1；
- 1 个 MoE block，4 experts，top_k=1；
- 使用 typed、确定性的 token→expert route trace；
- route trace 无随机数、无 overflow、无 token drop；
- dispatch/combine 编译为现有 canonical P2P SEND/RECV/WAIT 流；
- expert Gate/Up/Down 复用现有 GEMM/activation 路径；
- 无 MoE backward、无 optimizer、无 PD、无动态 gate、无原生 A2A primitive。

完成条件：

1. route trace、expert histogram、capacity 和 expert ownership 可独立重算；
2. dispatch/combine 的逻辑字节、逐 hop 物理字节、request/ACK/data packet 全部闭合；
3. expert FLOPs、state bytes、buffer lifetime 和 route 均来自 typed production carrier；
4. 生成单一 linked manifest、单一 artifact 和单一 runtime timeline；
5. finalizer×2、resolver、simulator×2 全绿且所有 endpoint/drain 为 0；
6. evidence 明确 routing=STATIC_TRACE、timing=true、model_functional=false。

可声明：S3-Lite static-route MoE inference execution preview complete。

不得声明：S3-N MoE train/infer complete。

## 1. 为什么该简化版在两天内有机会完成

完整 S2/S3 的主要串行依赖仍包括：

- attention/norm/activation/embedding/RoPE/CE 的全模型 backward；
- bucket readiness/cadence、DP gradient collective；
- ZeRO-1/2/3、FSDP、optimizer state ownership；
- PP 物理映射、跨 stage P2P、1F1B、recompute；
- 动态 GateTopK、capacity/drop、原生 AllToAll；
- MoE backward、MoE PD 和共享端口竞争。

上述内容不能在 4 个槽位和唯一 runtime 通道下于两天内全部实现并验证。

本方案通过以下收缩形成两条可执行纵切：

| 原完整目标 | 两天内的收缩 |
|---|---|
| 全模型训练 backward | backbone 冻结，只反传并更新 LM head |
| AdamW + optimizer states | 单一 SGD update，无 momentum |
| DP/ZeRO/FSDP | 单 die、DP=1，显式 unsupported |
| PP/recompute | PP=1、单 microbatch，显式 unsupported |
| 动态 MoE gate | typed static route trace |
| 原生 A2A | 编译为已有 P2P transport |
| MoE train/PD | 仅 MoE inference |
| 数值正确性 | 仅结构、时序、字节与控制闭合 |

因此新增 C++ public ABI 最多只需要：

1. CROSS_ENTROPY_BACKWARD；
2. SGD_UPDATE。

MoE-Lite 不新增伪 A2A opcode，也不使用零成本 marker；它把 dispatch/combine 降为
production P2P action/record，后续可在相同 typed collective role 下替换为原生 A2A。

- 不允许用旧 SHA 或旧 report 冒充 current reload。

## 3. 扩展接口

所有 Lite 行为必须通过 typed contract 表达，禁止在 runner 中写特殊旁路。

### 3.1 训练覆盖

新增训练覆盖枚举：

- LM_HEAD_ONLY：本方案唯一支持；
- FULL_MODEL：保留值，当前 fail-closed。

backward producer 必须从 LM_HEAD_ONLY 得到唯一合法子图：

CE_BACKWARD → LM_HEAD_WGRAD → SGD_UPDATE。

不得把缺失的 backbone gradient 当作零值或已完成。

### 3.2 Optimizer

通过 optimizer strategy/typed spec 选择：

- SGD：Lite 支持，固定无 momentum；
- ADAMW：保留，当前 fail-closed。

SGD record 必须携带明确 dtype、element count、weight/gradient address 和学习率编码。
ProgramIo 必须把 update 前后的权重访问、HBM write 和 terminal update marker 闭合。

### 3.3 MoE routing

MoE routing provider 区分：

- STATIC_TRACE：Lite 支持；
- GATE_TOPK：保留，当前 fail-closed。

静态 trace 必须包含 token index、expert index、slot/capacity 位置，并满足：

- token 全覆盖且不重复；
- expert index 合法；
- top_k=1；
- 无 overflow/drop；
- trace digest 进入 plan、manifest 和 report 输入闭包。

### 3.4 Collective lowering

typed role 使用 MOE_DISPATCH / MOE_COMBINE，实现先选择 P2P decomposition。
未来增加原生 A2A 时，只替换 policy/lowerer，不修改上层 MoE graph、oracle 或 evidence 字段。

### 3.5 Capability

新增 capability 只能是：

- S2_LITE_HEAD_TRAIN_E2E_TIMING；
- S3_LITE_STATIC_MOE_E2E_TIMING。

它们不得自动提升 S2-N、S3-N、model-functional、optimized 或 online capability。

## 4. 执行规则

### 4.1 资源

- root：唯一 integrator、shared schema/version owner、C++ build/runtime token owner；
- worker A：S2 typed graph/oracle；
- worker B：C++ CE backward/SGD 与 codec/selftest；
- worker C：S3 typed MoE route/A2A oracle；
- 任一时刻最多 4 个活跃槽；
- official build/runtime 全局串行，禁止并行跑多个 simulator。

### 4.2 微阶段门禁

每个 2 小时波次预留最后 30 分钟做合并门禁。下游只消费已冻结 ABI。

每波必须具备：

- positive focused；
- 至少一个结构性 tamper negative；
- adjacent legacy regression；
- py_compile / C++ compile（按边界）；
- scoped diff/whitespace；
- 明确的 unsupported 边界。

### 4.3 禁止项

- 不扩大 SRAM、DTE、event queue 或 watchdog 掩盖失败；
- 不用 marker 替代有成本的 primitive；
- 不手造 fragment、manifest、ProgramIo 或 runtime report；
- 不修改 golden 来适配无法独立推导的变化；
- 不在 final ABI 冻结前启动 official runtime；
- 不因 Lite case 通过而提高 S2-N/S3-N capability。

## 5. 两天波次

每波严格 2 小时，采用 root + A + B + C。表中的 runtime 只有 root 可以启动。

### Day 1：S2-Lite head-only train

#### W1（0–2h）：冻结两个 Lite 合同和最终 shared ABI

- root：冻结两个新 opcode、schema/version ledger、case IDs 和 capability 名；
- A：LM-head-only backward graph + independent analytic oracle；
- B：CE backward/SGD operand、codec、published work test vectors；
- C：Static MoE trace、expert placement、dispatch/combine oracle。

退出门禁：

- old wire 明确拒绝；
- FULL_MODEL、AdamW、GATE_TOPK、top_k>1、overflow/drop 明确拒绝；
- 本波结束后禁止再次新增 shared opcode 或改 operand layout。

#### W2（2–4h）：S2 graph 到 GlobalAction

- root：集成 Train carrier provenance；
- A：CE_BACKWARD → LM_HEAD_WGRAD → SGD_UPDATE 完整 DAG；
- B：C++ CE backward/SGD codec + primitive；
- C：继续 MoE spec/oracle，禁止碰 shared ABI。

退出门禁：

- forward value、label、loss gradient、LM-head weight gradient 和 update 依赖 exact；
- 缺 CE backward、提前 update、更新冻结参数均 fail-closed；
- C++ codec/selftest 第一轮绿。

#### W3（4–6h）：S2 lowering/link/ProgramIo

- root：统一 Lowered/Linked carrier 和 manifest trust anchor；
- A：schedule/global/lowering exact；
- B：C++ record lowering、runtime marker、finalizer validation；
- C：MoE deterministic production builder 前置。

退出门禁：

- 单 manifest、单 stream/timeline；
- ProgramIo 包含 label seed、loss probe、gradient buffer、weight read/write；
- SGD 不是零成本 marker；
- legacy Train-forward/Stage4 adjacent 绿。

#### W4（6–8h）：S2 pre-runtime 与最终 ABI freeze

- root：finalizer×2、actual-SHA ProgramIo、resolver；
- A：runtime parser/report；
- B：唯一 C++ aggregate build/selftest；
- C：完成 S3-Lite graph/plan 的纯 Python focused。

退出门禁：

- S2 static counts/relocations/manifest closure exact；
- finalizer 两次 byte-identical；
- old/missing/reordered CE backward 和 SGD record 均拒绝；
- 标记 FINAL_SHARED_ABI_FROZEN。

#### W5（8–10h）：唯一 S2-Lite official runtime

- root：simulator×2；
- A/B/C：只读诊断、report/focused，不修改 shared ABI。

退出门禁：

- 两次 makespan/markers/memory/control 一致；
- CE backward、wgrad、SGD update 各执行一次；
- HBM write、ACK/DONE、全部 drain exact；
- 无 PROTO_WAIT、无残留 endpoint/session。

失败预算：

- 只允许一次根因定位和一次有界修复；
- 需要改 ABI 时 S2-Lite 降级为 pre-runtime，不消耗 Day 2 的 MoE 主线。

#### W6（10–12h）：S2-Lite evidence + S3 pre-integration

- root：冻结 s2-lite-v1 typed report/baseline；
- A：反伪造 freezer 和 capability；
- B：S2 C++ adjacent regression；
- C：S3 self-contained builder 到 GlobalAction。

退出门禁：

- S2-Lite 只有 runtime 双跑绿时才能标 E2E_TIMING；
- model-functional 仍为 false；
- S3 route histogram、expert FLOPs、P2P bytes oracle 已独立闭合。

### Day 2：S3-Lite static-route MoE inference

#### W7（12–14h）：MoE graph、placement、planning

- root：MoE carrier/provenance 集成；
- A：IR0/IR1 expansion 与 expert workload；
- B：复用已有 GEMM/P2P ABI，做无新 opcode 审计；
- C：static trace、capacity、placement 和 analytic oracle。

退出门禁：

- 4 experts 在 2 dies 上 canonical placement；
- 每 token 恰好一个 expert；
- dispatch/combine 与 expert compute 顺序 exact；
- rand()、隐式 gate 或 fixture route 禁止进入 production。

#### W8（14–16h）：IR2/schedule/GlobalAction

- root：统一 graph quotient；
- A：expert task/buffer lifetime；
- B：P2P action/route/resource 验证；
- C：dispatch/combine per-hop flow 和 bytes。

退出门禁：

- 所有 route 属于声明 EP group；
- SEND/RECV/WAIT 与 token slice 一一对应；
- expert core、state binding、flow ID 无跨 owner 碰撞；
- overflow/drop/top_k>1 明确拒绝。

#### W9（16–18h）：lower/link/ProgramIo

- root：唯一 manifest/envelope；
- A：MoE lowering/link；
- B：finalizer 对 P2P decomposition 的 strict gate；
- C：ProgramIo seeds/probes 与 marker parser。

退出门禁：

- 单 artifact，禁止各 expert 单独模拟后相加；
- input trace digest、expert state、route plan 进入 manifest；
- dispatch/combine transport bytes 与 oracle exact；
- 所有 address/runtime relocation 闭合。

#### W10（18–20h）：S3 pre-runtime

- root：finalizer×2、actual-SHA ProgramIo、resolver；
- A：typed report/negative；
- B：matching build/selftests；
- C：raw runtime parser synthetic focused。

退出门禁：

- artifact 两次一致；
- expert/action/flow/static counts exact；
- missing token、duplicate assignment、wrong expert、route/byte tamper 均拒绝；
- runtime command 使用 matching hardware/simulation。

#### W11（20–22h）：唯一 S3-Lite official runtime

- root：simulator×2；
- A/B/C：只读诊断和证据生成。

退出门禁：

- 两次 typed expert-action closure、P2P marker、makespan 和 ProgramIo digest 一致；
- dispatch/combine request/ACK/data 与 analytic bytes exact；
- 所有 endpoint、router、DTE、event、control drain 为 0；
- 无 token 丢失、重复或 capacity overflow。

#### W12（22–24h）：双 Lite 收口

- root：原子发布 s2-lite-v1 / s3-lite-v1 baseline；
- A：独立重建 spec/oracle/manifest/ProgramIo/report；
- B：C++ aggregate + legacy Stage4/Train-forward adjacent；
- C：capability/docs/unsupported matrix。

退出门禁：

- baseline no-clobber、无 npup、发布后重新打开 byte-exact 校验；
- 两个 Lite report 均能从 raw evidence 独立重建；
- S1 历史 baseline 不被改写；
- S2-N/S3-N 仍为 unsupported。

## 7. 风险与止损

### 7.1 优先级

1. 可执行且诚实的统一 artifact；
2. S2-Lite runtime；
3. S3-Lite runtime；
4. report/baseline；
5. 任何额外 case。

不得为了多一个 case 牺牲前四项。

### 7.2 降级规则

- W4 未绿：S2-Lite 停在 pre-runtime，但 Day 2 继续 S3-Lite；
- W5 runtime 失败且一次修复仍不绿：保留失败证据，不再机械重跑；
- W10 未绿：S3-Lite 停在 pre-runtime，不发布 E2E capability；
- W11 runtime 失败：不得用 synthetic parser 或 unit fixture 生成 PASS report；
- 任一修复需要新增 opcode/改 operand ABI：回到 ABI freeze，所有受影响 artifact 重建；
- 禁止通过增加容量、延长 watchdog 或删除负测制造通过。

### 7.3 两天目标的保证边界

可保证的是：

- 两个 Lite vertical slice 的代码、typed contract、oracle、negative 和 pre-runtime 闭包；
- 在 runtime 没暴露模拟器新缺陷时，完成两次 official E2E runtime。

不能无条件保证的是：

- 未知 C++ runtime 缺陷在固定时间内修复；
- 完整 S2-N/S3-N；
- 模型数值正确性或研究结论。
