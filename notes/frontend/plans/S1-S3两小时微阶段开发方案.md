# S1–S3 两小时微阶段开发方案

## 1. 目的与适用范围

本文基于当前仓库进度，把《S1-S3后续开发方案.md》中剩余的 Stage 4、Stage 6、Stage 1b、
Stage 7–14 和 optimization-ready 工作拆成 **30–120 分钟、可独立提交、可独立回滚** 的微阶段。

本文只改变开发切片和日常门禁，不改变《前端建模方案.md》的架构、精度边界和完成声明：

- S1-N、S2-N、S3-N 仍分别按原 case matrix 和退出门禁完成；
- 中间 preview、schema-only、unit-only 或 timing-only 结果不得冒充上层完成；
- 每个 case 仍须经过唯一的 IR 顺序、统一 ProgramArtifact 和一次 simulator 时间线；
- optimization-ready 只冻结真实可替换接口，不把 declared-but-unavailable 计作优化结果；
- O1/O2 的真实算法实现是独立研究路径，不阻塞当前 naive-first 承诺。

“每阶段不超过两小时”在本文中专指下列微阶段。原 Stage 4、Stage 7 等主题阶段成为多个
微阶段的集合；只有集合的最终声明阶段通过，才允许更新 capability 或 coverage。

- Stage 0、Stage 1a、Stage 2、Stage 3 已有 checked evidence 和独立 baseline；
- Dense forward、静态 prefill/decode/ragged profile、persistent state、统一
  GlobalAction→lower/link→strict runtime 主路径已经存在；
- Stage 4 已按 S4.0–S4.9 正式冻结：
  - PD-F、PDS TP1→TP1、PDR TP2→TP1 均经过同一 typed carrier→GlobalAction→
    lower/link→finalizer→ProgramIo→simulator 主路径；
  - PDR 使用 8 个 segmented K/V transfer、64 个 segment、2 条 endpoint route，
    state handoff 为 1024B；TP2 collective 与 state transport 的 D2D 证据分别闭合；
  - 三个 case 均完成两次真实运行且 digest 一致，makespan 分别为 11201、6187、10912；
  - `notes/frontend/baselines/stage4-pd-v1` 保存每 case 15 份可重建 raw evidence，
    不保存 NPUP；anti-forgery freezer 已从 production case 和两份 runtime log 重建通过；
  - Stage4 case matrix 为 `stage4_ready=true`，仅升级 `s1.pd` 与 `s1.kv_handoff`；
    能力边界仍是 timing/state-transport exact，`model_functional=false`。
- Stage 6 已完成 N6.0–N6.3c：train-forward/CE IR0 与解析 oracle、DP2×TP2 placement/N4、

- Stage 5 online/RegionCall 不属于 Stage 4，仍未开始；
- Stage 6 尚缺 N6.4 之后的 CE fixed ABI、统一 artifact/runtime、八 case 同 epoch和
  optimization-ready 收口，因此 S1-N 尚未完成；
- Stage 1b 只有部分 root/view/lifetime 字段，尚无通用 contained view、reuse allocator、spill 和
  region-relative 宽地址闭包；

不含 online）；不得声明 S1-N、Stage 1b、S2-N、S3-N 或 S1-R complete。

## 3. 两小时时间盒规则

### 3.1 固定节奏

每个微阶段从首次源文件修改开始计算墙钟时间，最长 120 分钟：

| 时间 | 工作 |
|---:|---|
| 0–15 分钟 | 只读定位、冻结输入/输出/负测和文件所有权 |
| 15–75 分钟 | 最小 production 实现；每个完整 patch 后立即 syntax gate |
| 75–100 分钟 | focused unit、解析式或单 target selftest |
| 100–115 分钟 | 一个必要 adjacent、public export、diff/style 审计 |
| 115–120 分钟 | 写 checkpoint，标记 DONE、PREVIEW 或 BLOCKED，释放文件所有权 |

到 120 分钟仍未完成时必须停止；剩余工作拆成新的 `x.y+1` 微阶段。禁止通过删负测、扩大
allowlist、更新 golden 或静默 fallback 伪造完成。

### 3.2 日常门禁

| 微阶段类型 | 必跑门禁 | 延后门禁 |
|---|---|---|
| schema/producer | `py_compile`、focused positive/tamper、diff-check | 大回归、runtime |
| 共享 interface | 上述门禁 + 1 个直接 legacy adjacent | 全 frontend |
| Python lowering | focused byte/reloc/role + 1 个旧路径 adjacent | C++ aggregate |
| C++ ABI/prim | 单 target build + 对应 selftest | 全量 CMake/ISA aggregate |
| runtime case | production builder/finalizer/resolver/runtime 双跑 | 其他 TP/case |
| evidence/freezer | strict reload、disk-derived rebuild、no-clobber | 无；本片即里程碑门禁 |

TP1/tiny shape 是日常主门禁；TP2/TP4、full C++、大 runtime 和 baseline 被拆成独立微阶段。
单个命令的 timeout 必须低于该微阶段剩余预算。执行环境或审批连续失败两次时，本片标记
BLOCKED，不再盲目重启长命令。

### 3.3 并行与文件所有权

- 最多三条实现线和一条集成线；每条线拥有互不重叠的 production 文件；
- schema → producer → validator 可以流水并行，但消费者不得针对未落盘字段猜 ABI；
- shared `__init__`、版本表和最终 integration test 由集成线统一修改；
- 任何 breaking ABI 都必须在同一微阶段列出版本闭包；无法在两小时内闭合时先停在新
  producer 前的明确 boundary，不保留半迁移 wire。

## 4. 不可削减的建模合同

### 4.1 唯一 pass 顺序

```text
IR0 spec/template
  → LogicalExpand（IR0→IR1 边界的瞬时 expanded view）
  → Placement
  → FusionPartition
  → InterDiePolicy / StandaloneCollectivePlan
  → 完整 per-rank Action DAG
  → ProjectToIR2
  → IntraDiePolicy
  → GlobalActionDAG
  → ordinary / standalone / fused 三类 lowering
  → ProgramLinker
  → 单一 ProgramArtifact / 单次 simulator
```

LogicalExpand 不是第四个公共 IR。训练 microbatch/PP 的确定性展开位于 IR0→IR1 边界；IR0
携带 TrainStructure，但不把展开后的节点序列反写成第二份逻辑真相。lowering 不得重选 peer、
chunk、route、barrier 或 policy。

### 4.2 必须保持的精度边界

| 要求 | 本计划中的强制规则 |
|---|---|
| typed workload | 新 op 必须同时有 workload、shape、validator、独立 oracle 和 timing/cost contract |
| naive exact | deterministic、content-addressed、真实 route/容量，无隐式 fallback |
| 单一时间线 | 禁止把 FWD/BWD、PP stage、P/D 或 A2A 分开模拟后求和 |
| 内存真实 | 禁止无限 SRAM；必须建模 backing、lifetime、reuse/spill 或明确容量失败 |
| 通信真实 | 保留 rank/chunk/stage/phase/bucket/token/route lineage 和 observed bytes |
| 优化可替换 | compiler/runner 只能通过 registry 建 policy；无 factory 时严格 Unsupported |
| 证明分层 | timing、transport-functional、model-functional 分开，不越级声明 |
| digest | 只在 reviewed epoch 重冻结；测试变红不能直接更新 golden |

明确禁止：forward×3、FlashAttention backward=3 个普通 GEMM、每权重一次 AR、ZeRO 只缩放
byte、optimizer 常数延迟、recompute 只挂 flag、MoE 使用 `rand()`、请求 ID 冒充 KV payload、
equal-TP 冒充 reshard、split simulation makespan 求和。

## 8. Stage 1b：内存、复用、spill 与宽地址

现有 IR2/BufferABI 已有 `storage_id`、`alias_of`、region、offset 和半开 lifetime；IR1 已有
BLOCK region 与 `spillable`；artifact 已有 ALLOC/FREE。下列微阶段复用这些底座，不新建第二套
allocator 或 runtime。真实缺口是通用 contained view、free-list reuse、spill transaction、TASK
外 scope 和 region-relative 宽地址。

| ID / 上限 | 目标与产物 | focused 退出门禁 |
|---|---|---|
| 1b.0 / 60m | 冻结 MemoryContract vNext：TASK/LAYER/MICROBATCH/STEP/PERSISTENT、root/view、residency、spill、region-relative address | schema 正反例和 breaking 版本闭包；禁止先改 golden |
| 1b.1 / 90m | lifetime scope/owner 坐标 schema | `[start,end)` action-order 投影；跨 layer/MB/step 伪 scope 拒绝 |
| 1b.2 / 90m | contained root/view，显式 offset/extent/alias lineage | 越界、环、跨 core/region、错 dtype/layout、重叠写拒绝 |
| 1b.3 / 90m | 从 TaskBufferUse 独立重算 live interval/scope 的 oracle | 漏 consumer、提前 free、错误延长 scope 均拒绝 |

## 19. 每片 checkpoint 模板

每个微阶段结束必须写同一格式的机器可读或 Markdown checkpoint：

```text
slice_id:
status: DONE | PREVIEW | BLOCKED
wall_time_minutes:
files_changed:
schema_versions:
positive_gate:
negative_gate:
adjacent_gate:
first_real_failure:
explicit_boundary:
capability_change: none | <exact key old→new>
next_slice:
```

规则：

1. `DONE` 只表示当前微阶段，不自动表示父 Stage 完成；
2. `PREVIEW` 必须写下一层第一个明确 Unsupported/Schema boundary；
3. `BLOCKED` 必须保留可解析文件、失败证据和无悬挂进程；
4. capability 默认不变，只有 S4.9、N6.8、11.5/11.7、14.11、AB.3 可提升对应完成状态；
5. 同一失败不得靠修改 expected message、扩大 wildcard 或更新 digest 规避。
