# Stage 2 开发报告：S1 Dense 前向算子闭包

## 1. 阶段状态

阶段 2 的 D2-0 至 D2-5 已完成。D2-1/D2-2 已闭合 typed schema、完整 Dense forward IR0/IR1、
TP1/2/4 placement 和独立 oracle；D2-3 已闭合 Action/IR2、schedule/global、fixed record、linker、
C++ codec/finalizer 与 backend timing cost；D2-4 已用 production builder、finalizer、ProgramIo 和
npusim 双跑 LOGITS TP1/2/4；D2-5 已发布 checked baseline
`notes/frontend/baselines/stage2-dense-forward-v1`。该完成状态只声明 Dense forward 的端到端
timing execution、解析 work 与 traffic/accounting exact，不声明 compute-functional 或
model-functional 正确性。阶段 1b 仍是大模型/训练的地址扩宽、reuse/spill 内存门禁，不是本阶段
tiny 64 KiB case 的前置条件。

## 2. 需求理解与范围

本阶段把当前 transformer block 主干扩展为完整的 LLaMA 类 Dense forward：

```text
token ids
  -> embedding
  -> L x {RMSNorm -> QKV -> RoPE(Q/K) -> attention -> O -> residual
          -> RMSNorm -> gate/up -> SwiGLU -> down -> residual}
  -> final RMSNorm
  -> LM head
  -> logits | greedy sampling | CE-forward template
```

必须补齐 typed workload、shape、参数状态、FLOPs/ops、通信量、KV bytes、真实 backend cost 和
统一 artifact 时间线。public producer 在本阶段仍只接受 infer；CE forward 仅冻结可供 Stage 6
使用的内部 typed contract，不开放完整 train input。

本阶段明确不包含：decode/ragged E2E、真实 PD/KV handoff/reshard、训练反向、optimizer、PP、
大地址/reuse/spill、tied-weight transpose/alias、随机/top-k/top-p sampling、optimized policy 或
模型 functional token/loss。完成 Stage 2 也不等于 S1-N 或 S2-N 完成。

## 3. 完成状态与保留边界

- vocabulary、RMS epsilon、packed-QKV RoPE 与 logits terminal 已贯通 IR0 至 runtime；
- full-forward 图、15 类 parameter state、4 类 KV state、TP1/2/4 placement 与 oracle 已 exact 闭合；
- exact Attention/RoPE、embedding lookup、greedy sample 已有独立 fixed record、codec 与 timing cost；
- RMSNorm weight 是真实 DATA operand；INT32 只进入合法 TensorValue/BufferABI 路径；
- ProgramIo 对 artifact SHA、HBM/SRAM seed/probe、resolver 与两次 runtime marker 建立闭包；
- GREEDY 仅支持 TP1；TP2/TP4 在缺少跨 rank terminal 规约时机器化 fail closed；
- CE forward 仍是 schema-only，投影/lowering fail closed；训练、decode/ragged、optimizer 与 MoE 不在本阶段；
- Stage 1b 的地址扩宽、reuse/spill 仍未实现，因此不能把 tiny case 外推到大模型容量结论；
- 禁止把 timing/checksum 证据冒认为 token、logits 或 loss 的模型数值正确性。

## 4. 冻结的模型与解析式

### 4.1 Model vNext

Stage 2 model 必须显式携带：`V`、`tie_word_embeddings`、`rms_norm_epsilon`、
`rope_theta`、`rotary_dim` 和 `max_position_embeddings`；infer workload 必须显式选择
`logits` 或 `greedy_sample` output。首版要求 `rotary_dim == DH`，且只接受 untied embedding/head；
`tie_word_embeddings=true` fail closed，因为当前 MATMUL 没有 RHS transpose/alias ABI。

参数元素数按下式唯一重算：

```text
Q = (NH + 2*KVH) * DH
P_layer_linear = H*Q + H*H + 3*H*I
P_layer_norm   = 2*H
P_total = V*H + L*(P_layer_linear + P_layer_norm) + H + H*V
```

RoPE 常量不计模型参数。首片把它冻结为 analytic/on-chip constant；如果后续放入 HBM，必须
新增独立 constant identity，不能伪装成 parameter。

### 4.2 Forward work

```text
F_gemm_layer = 2*M*P_layer_linear
F_lm_head    = 2*M*H*V
F_attn_layer = 4*query_key_pairs*NH*DH
F_gemm_total = L*F_gemm_layer + F_lm_head
F_attn_total = L*F_attn_layer
```

RMSNorm、RoPE、SwiGLU、embedding、sampling 和 CE 的 vector/SFU/memory ops 分项报告，不把
它们混进 GEMM FLOPs。每个 backend cost 必须从 typed workload 重算，前端不得注入 cycle。

### 4.3 Attention 与 KV

Attention workload 必须显式包含 mode、causal、query tokens、context sum/max、query-key pairs、
logical/rank KV read bytes 和 write bytes。Prefill causal pairs 为 `M*(M+1)/2`；decode pairs 为
`context_sum`。KV 状态仍由 Stage 1a 的显式 state access/DMA 闭合，不能添加虚假 compute
operand，也不能把 ProgramIo seed/probe 计入 LSU traffic。

## 5. 冻结的 tiny 数值门禁

统一 case：`V=32,H=16,I=32,NH=4,KVH=4,DH=4,L=2,T=8,FP16,untied`。

- unique parameters：6,224 elements，12,448 B；
- per-layer linear parameters：2,560 elements；
- GEMM FLOPs：每层 40,960，LM head 8,192，总计 90,112；
- causal pairs：每层 36；attention matmul FLOPs：每层 2,304，总计 4,608；
- TP1/2/4 rank GEMM FLOPs：`90,112 / p`；rank attention FLOPs：`4,608 / p`；
- 每个 AG/RS logical tensor：256 B；每层固定 2 AG + 2 RS；
- 每层 rank/group payload：TP1=0/0，TP2=512/1,024 B，TP4=768/3,072 B；
- prefill KV logical write：每层 512 B，两层 1,024 B；read=0；
- logits terminal node count：TP1=25，TP2/TP4=33，其中 collective=8；
- greedy terminal 只在 TP1 增加 1 个 node；TP2/TP4 greedy 在没有跨 rank terminal 闭包前
  必须 fail closed；
- parameter declarations：`15p`，KV declarations：`4p`；
- placed parameter bytes：TP1=12,448，TP2=14,656，TP4=19,072。
- LOGITS `(nodes, values, edges)`：TP1=`(25,41,28)`，TP2/TP4=`(33,49,36)`；
- GREEDY TP1 `(nodes, values, edges)`=`(26,42,29)`；
- IR0/IR1/oracle/N4 合并门禁 81/81 通过；N5 保留 6 个必须由 D2-3 恢复的旧正测红线。

这些数值必须分别由 graph/oracle/placement 重算，不能由同一个自报总数字相互证明。

## 6. 架构与后端边界

可复用的后端能力只有：

- untied LM head 的 exact `M x H @ H x V` MATMUL；TP>1 时使用显式
  `SEQUENCE_PARALLEL_REPLICATED_WEIGHT` partition，即 token/M 维分片、权重和 V 维复制；
- RMSNORM，但必须补真实 norm-weight data operand；
- SwiGLU 的 concat `2N -> N`；
- 旧 ROPE 不可直接复用：完整图保留单一 packed QKV value，必须由新的 exact ABI 只旋转 Q/K
  prefix 并原样透传 V。

必须新增 versioned exact backend contract：

- `ROPE_QK_EXACT`：packed QKV 中只旋转 Q/K，不把 V 计为旋转工作；
- `ATTENTION_EXACT`：按 query-key pairs 计费，不静默改变旧 ATTENTION；
- `EMBEDDING_LOOKUP`：INT32 index + FP16 table/output，不能冒充 one-hot GEMM；
- `GREEDY_SAMPLE`：FP16 logits -> INT32 token；
- `CE_FORWARD`：FP16 logits + INT32 label -> FP32 loss。

mixed-dtype 算子使用专门 record operand schema。ProgramIo 仍只证明边界数据搬运和 checksum；
`model_functional` 必须保持 false。
