# N0 后端能力闸门报告

本文记录“Naive Dense 静态前向 MVP”在进入前端 lowering 集成前，对现有
`ProgramArtifact → config_helper_program → npusim` 路径完成的能力审计、最小修复和
可重复验证。它只证明 N6 所需的后端积木已经可用，不代表完整 Dense 前端、Swizzling 或
优化片上调度已经实现。

## 1. 需求理解与形式化

首个融合目标是 TP=2、SP 打开的行并行 partial GEMM + ReduceScatter。N0 将其缩成一个不
依赖前端生成器的后端契约：

```text
rank 0 partial(chunk 0), rank 1 partial(chunk 0)
  → rank 1 --raw bytes--> rank 0
  → rank 0 按 [rank 0, rank 1] 次序做 FP16 input / FP32 accumulate
  → FP16 RNE output，rank 0 持有 canonical chunk 0

rank 0 partial(chunk 1), rank 1 partial(chunk 1)
  → rank 0 --raw bytes--> rank 1
  → rank 1 按 [rank 0, rank 1] 次序做同一归约
  → rank 1 持有 canonical chunk 1
```

冻结的数值契约为：

- 输入和输出是 IEEE binary16；
- accumulator 是 IEEE binary32；
- SUM 严格按 rank-major 顺序逐项执行；
- 每次 binary32 加法以及最终 binary16 转换均为 round-to-nearest, ties-to-even；
- NaN 规范化为 binary16 `0x7e00`；
- P2P 只传 raw bytes，不让 transport 解释浮点 dtype 或执行 reduction。

## 2. 软件架构决定

N0 没有放开跨 Die collective core group。首版统一后端使用已有跨 Die P2P endpoint，
在目的端把各 rank 的 partial 放入连续 rank-major SRAM staging，再执行独立
`LOCAL_REDUCE`：

```text
ProgramArtifact
  ├─ MATMUL                 timing record
  ├─ DTE_RECV / DTE_SEND    UINT8 raw-byte endpoint
  ├─ DTE_WAIT               explicit completion
  └─ LOCAL_REDUCE           FP16 → FP32 → FP16 SUM/RNE
       ↓
config_helper_program → strict Prim → unified SRAM data path
```

这样把 transport 与数值语义解耦，同时避开“跨 Die group 被当成单 Die collective
group”这一错误抽象。后续 `IsaRegionLowering` 必须生成已经规划好的 peer、buffer、wait
和 local reduction；不能回调 legacy collective planner 重选算法。

## 3. 最小实现

### 3.1 新增后端能力

- 新增 public/stable `Opcode::LOCAL_REDUCE = 0x43`。
- 新增版本化 `LocalReduceOperands`，显式携带 input/accumulator/output dtype、
  reduce op、rounding、rank order、input count、element count、stride 和源/目的地址。
- V1 只接受 `FP16 / FP32 / FP16 / SUM / RNE / RANK_MAJOR`，地址必须是 FP16 对齐的
  absolute SRAM 地址，stride 必须等于一个 rank 的 payload bytes。
- record codec、Program validator、semantic relocation、lowering、Prim wire 和
  `config_helper_program` 均已接通。
- `Collective_data_v1_prim` 的 wire dtype code 3 显式映射为 FP16；FP16 仅允许
  key-zero 的 standalone local reduction，不改变既有 whole-artifact collective 语义。
- 数值实现使用位级、确定性的 binary32 RNE add 与 binary16 RNE encode，不依赖 host
  浮点环境或编译器 fast-math。
- 若 artifact 声明了 SRAM region，Program validator 会同时验证 source/destination 的
  完整访问 span 位于某个声明 region 内。

### 3.2 手写后端 fixture

`npusim_program_fixture --frontend-n0-tp2-rs` 生成一个 core 0 与 core 16 的单一
`ProgramArtifact`：

- 两核各有一个 FP16 MATMUL timing record；
- 两个反向 P2P flow，各 32 bytes；
- 四个 WAIT；
- 两个 owner 各执行一个 2 ranks × 16 lanes 的 `LOCAL_REDUCE`；
- active/terminal/expected ACK/expected DONE 都显式包含 core 0 与 core 16；
- input/intermediate 的 task allocation 与 weight/bias persistent allocation 显式隔离，
  防止 timing-only MATMUL 的静态数据初始化污染功能 oracle 区域。

fixture 输出严格单行 manifest，runner 会拒绝字段缺失、未知字段、地址/region 配置不一致或
算子数量变化。

## 4. 验证流程与结果

### 4.1 单元与数值验证

以下能力均有正例和非法输入负例：

- opcode manifest、record encode/decode、wire encode/decode；
- absolute relocation 和 SRAM span；
- lowering 到 strict Prim；
- Prim 的真实 SRAM read/reduce/write；
- rank-major 输入顺序；
- 普通数、正负零、抵消、subnormal/normal 边界、RNE 偶/奇 tie、NaN、正负 Inf、
  finite overflow。

runner 的 CPU oracle 只使用 FP16 bit pattern 与有理数，不使用 host float。

### 4.2 集成验证

执行命令：

```bash
python3 -B llm/test/frontend/integration/run_n0_backend_gate.py \
  --npusim build-debug-final/npusim \
  --program-fixture build-debug-final/npusim_program_fixture \
  --hardware llm/test/sram/hardware_numa.json \
  --simulation llm/test/sram/simulation.json \
  --mapping llm/test/default/mapping.spec \
  --runtime-root build-debug-final
```

结果：

- artifact 两次隔离生成完全相同：1986 bytes；
- artifact SHA256：
  `dcdb064c6c5305d679a026e277498f140893ff5628a97a25fa4bc9b8922391b1`；
- 两次隔离 runtime 的规范化摘要完全相同：
  `c0a3c5015204590a491e6146a48766d08773f60429195334687c845dd28e037d`；
- 两个 owner output 逐 bit 匹配 CPU oracle；
- 两核 staging 与 outbound buffer 逐 byte 匹配；
- output payload 外所有 sentinel 保持不变；

- endpoint、timing sideband、collective、token/event、router 和 D2D residual 全为 0；

  `[FRONTEND N0 BACKEND] PASS: 2-die TP2 dual-owner RS`。

## 5. 能力结论

| 能力 | 状态 | 结论 |
|---|---|---|
| Program encode/decode/CRC/validate | supported | N6 直接复用 |
| 单 artifact、单 helper、ACK/DONE | supported | 双 Die gate 已验证 |
| 跨 Die standalone P2P | supported | raw UINT8 bytes；显式 peer/FSM/token |
| async endpoint + WAIT | supported | 两个反向 flow 无泄漏 |
| FP16 MATMUL timing | supported | 可进入统一 timeline |
| FP16 local SUM, FP32 accumulate, FP16 RNE | repaired | 通过新增 `LOCAL_REDUCE` 提供 |
| FP16 endpoint dtype/reduce | intentionally unsupported | transport 保持 raw bytes |
| 跨 Die whole-artifact collective group | blocked for MVP use | 前端必须展开为 P2P + local reduce |
| GEMM functional payload | unsupported by current timing model | N0 由 P6 probe 预置 partial；不得声称 simulator 算出了 GEMM 数值 |
| 双核完整 trace interval | trace limitation | metadata 含两核；代表核有完整正时长 interval，双核正确性由最终状态摘要证明 |
| Swizzling/ring/tree/route search | out of N0 scope | 只保留前端 policy 接口 |

## 6. 前端可复用接口与硬约束

N6 可复用：

- `ProgramArtifact`、`ValidateProgramArtifact`、`EncodeProgramArtifact`；
- `DteSendOperands`、`DteRecvOperands`、`DTE_WAIT`；
- `LocalReduceOperands` 与 `Opcode::LOCAL_REDUCE`；
- SRAM region/label、allocation/bind/free、semantic relocation；
- `ProgramControlEnvelope`；
- `npusim --program` 的单 `config_helper_program` 路径。

前端必须继续满足：

1. P2P 的 bytes、peer、FSM/channel、token、source/destination 必须由 Action DAG 和 schedule
   决定并一一配对。
2. rank-major staging 的物理顺序必须与 `LOCAL_REDUCE.order` 一致。
3. owner layout 必须保持 canonical，或携带完整 permutation/inverse permutation。
4. finalizer 只分配最终 ID 和做 relocation，不得重选 collective algorithm、peer 或 schedule。
5. timing validation 与 functional validation 分开报告；完整 Dense E2E 不能把预置 partial
   描述成 GEMM functional execution。

## 7. 阶段退出判断

N0 的 U3-T/U3-F 后端前置能力已通过，且现有 Program/collective/endpoint 回归无退化。
因此 N6 不再被“缺少 FP16 本地 reduction 或跨 Die endpoint”阻塞；N1–N5 仍须按阶段完成
schema、逻辑图、placement、Action DAG 和物理 schedule 后，才允许进入统一 lowering 集成。
