# N2 Dense IR-0 与逻辑展开开发报告

## 范围

N2 将已经校验的 analytic Llama-like Dense 推理配置依次转换为：

```text
ExperimentSpec → IR0Template → ExpandedIR0Bundle(profile → IR0)
```

当前实现支持：

- FP16 Dense 前向、任意 `L >= 1`；
- 一个或多个 canonical 静态 profile，每个 profile 拥有独立 IR-0；
- `TP=1, SP=false` 的 replicated 图；
- `TP=p>1, SP=true` 的列并行/行并行、AllGather/ReduceScatter 图；
- 每层独立的权重、节点、候选、KV effect token 与 alias ID；
- 层间直接使用前一层 `residual2` 输出，不插入 copy 或伪 input；
- 两个语义候选：`O → RS1` 与 `Down → RS2`，仅声明候选，不选择实现。

`logical_expand` 返回前执行完整的三层验证：单图 Dense IR-0、Fusion candidate
语义，以及 template-to-bundle provenance/结构验证。PassManager 到此阶段停在
`LOGICAL_EXPANDED`。

本报告不包含 placement、IR-1、物理 group/route、FusionPlan、IR-2、lowering、
backend artifact 或 simulator E2E；这些属于 N3 及后续阶段。

## 解析公式与样例门禁

设 token 数为 `M`、隐藏维为 `H`、中间维为 `I`、查询头数为 `NH`、KV 头数为
`KVH`、头维为 `DH`、TP 度数为 `p`。

- QKV 宽度：`(NH + 2*KVH) * DH`。
- 每层线性参数：
  `H*(NH+2*KVH)*DH + H*H + 2*H*I + I*H`。
- 每个 GEMM 的逻辑 FLOPs：`2*M*N*K`；TP 并行时对应 rank-local shape 计算
  rank FLOPs。
- prefill attention pairs：`M*(M+1)/2`；decode pairs：`context_sum`。
- attention 两次 matmul FLOPs：`4*pairs*heads*DH`；softmax 元素数：
  `pairs*heads`。rank 统计使用 `heads/p`。
- FP16 activation 逻辑字节 `B=2*M*H`。每个 AG/RS 的 rank 逻辑 payload 为
  `B*(p-1)/p`，group payload 为 `B*(p-1)`；每层有两个 AG 与两个 RS。

固定样例 `H=256, I=512, NH=4, KVH=2, DH=64, M=32, p=2, L=1` 的门禁值：

- 参数量：`589824`；
- 线性 GEMM：逻辑 `37748736` FLOPs，rank `18874368` FLOPs；
- 四个 collective：rank payload 合计 `32768` bytes，group 合计 `65536` bytes；
- prefill pairs `528`；attention matmul 全局/rank FLOPs `540672/270336`；
- softmax 全局/rank 元素数 `2112/1056`。

## Fail-closed 范围

以下配置不会静默降级：

- `TP=1, SP=true` 或 `TP>1, SP=false`；
- token、query heads、KV heads 或 intermediate extent 不能被 TP 整除；
- mixed prefill/decode 或不能唯一确定 attention 工作量的 profile；
- profile 与 instance role 不兼容、decode `context_sum=0`；
- 非 Dense、训练、MoE、非 FP16 等 schema/template 范围外能力；
- 非直接 row-parallel GEMM → SUM ReduceScatter、错误 boundary/contract、非凸、
  effect/alias 不安全、漏配或重叠的 Fusion candidate。

## 测试与退出条件

Focused N2 集成测试：

```bash
cd llm/test/frontend/unit
PYTHONPATH=/workspace python3 -m unittest test_n2_pipeline.py
```

完整 frontend Python 单测：

```bash
PYTHONPATH=/workspace python3 -m unittest discover \
  -s llm/test/frontend/unit -p 'test_*.py'
```

CMake 的 `frontend_python_unit` 已使用同一 `unittest discover` 规则，无需新增测试清单。

N2 退出条件为：真实 `ExperimentSpec` 经 PassManager 连续执行 `build_ir0` 与
`logical_expand`；两张 receipt 的 digest 连续；输入不变且重复编译 digest 稳定；bundle
及其中每张图通过三层 validator；上述固定样例参数、FLOPs、collective 与 attention
解析值全部匹配。
