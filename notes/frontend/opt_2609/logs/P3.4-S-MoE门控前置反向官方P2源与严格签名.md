# P3.4-S：MoE 路由梯度前置反向的官方 P2 source

## 本阶段目标与交付

在原两层、两步、1×2 Die Mesh / EP2 TRAIN 生产 P2 计划之上，提供**显式 opt-in 且按原 source 完整重签**的 SCORE_WEIGHT_BACKWARD_PRE_DISPATCH 来源。原静态 trace、原 `compile_flexible_moe_baseline` 的 action/flow/state、旧 producer 和 artifact ID 完全保留；只有新 source 携带 StageP 已签的 scored top1 新 case ID、逐 token 原 P2 assignment 导出的五字段非零 INT32 route blob（4×5×4=80B），以及对外部共享 dCombined 的**具名需求**。

本阶段修改官方 `schema/flexible_moe.py` 增添 `MoeRectSignedTop1TrainSource`、独立 `SHARED_DCOMBINED_IMPORT` 与 `SCORE_WEIGHT_BACKWARD_PRE_DISPATCH` action kind，并在官方 `FlexibleMoeExecutablePlan.validate_against` 增添严格的 `signed_source` opt-in 分支。新 `validate_against_signed` 对原 P2 计划和签名源**独立重新编译**并比对整个计划，避免通过只改状态或重签单一伪 action 接受缺失因果路径。原生产 lowering 调用的默认 `validate_against(spec)` 继续拒绝新 producer；若把带新 action 的计划重标为旧 baseline producer，即使 ID 按计划语义仍有效，旧分支也明确拒绝，因此现阶段没有伪造的可执行 manifest。

新 `passes/moe_signed_router_train_source_plan.py` 从真实旧 P2 TRAIN action 顺序编译：rank0 forward `WEIGHTED_COMBINE` 后添加依赖原 combine 的共享 dCombined import；随后 score-weight backward 前置 action 依赖 import 与 forward combine。rank0 原 BACKWARD_GRADIENT SEND 改为直接依赖新前置 action，rank0 有 token 的 local expert DGRAD/WGRAD 亦直接依赖它；rank1 的 SEND→RECV/WAIT→EXPERT_DGRAD 因依赖链得到相同支配。**原** late `COMBINE_BACKWARD` 留在 BACKWARD_DX 回流和本地 DGRAD 之后，不能用 late action 充当前置 dExpert producer。每条受影响 action 和 terminal reference 按新的 deps 重新签名；flow 的远端真实 bytes、状态绑定、所有参数声明与优化器路径不变。显式编译入口位于旧 `passes/flexible_moe.py`，默认编译入口不变。

这里 `SHARED_DCOMBINED_IMPORT` 只表示「真正共享 backbone backward 输出必须接到本 source」，字符串 `shared_dcombined_producer_ref` 与 `shared_full_model_manifest_ref` **目前不是**真实 GlobalActionDAG / BufferABI / linked ISA 中已验证的物理生产者。80B route blob 也尚未有实际 ProgramIO SRAM 输入，公开 0x27/0x28 与 0x28 两个物理 FP16 输出尚未注册为 NpuSim 运行路径。本阶段是官方 P2 action source 的严格因果合同，**不是完整 MoE training、不是梯度数值验收，也不是可执行 full-model runtime**。状态 `M1 MoE TRAIN = blocked`、`functional_execution = false`。

## 开发与验收

测试使用 `test_moe_full_train_ep_placement.py` 的真实 32MiB HBM/128KiB SRAM、真实 EP2 两层两步生产 `compile_moe_sequence` 单元，而非改变原 16MiB/64KiB 低容量 case。新测试同时比对原 unit P2 与重新编译的 baseline ID/manifest，检查四个 `(step,layer)` 各自 signed source ID、80B 完整原 assignment trace、rank0 import/score 32B/48B/48 logical FLOPs、rank1 无伪新 action、remote BACKWARD_GRADIENT SEND/local expert reverse 支配边和 late dX combine 留存。

负例包括新 plan 缺 signed_source、旧 plan 虚绑定 signed_source、带新 action 的计划冒用旧 producer 名称、生产 `lower_link_flexible_moe_production` 未绑定后端明确拒绝、对前置 action 重签后去共享 import 依赖、接回 late combine 造环、篡改真实 route expert 字段，以及重签计划 ID 却篡改 carrier 文件容量以独立验证 canonical 重编译比对。路由字段按实际有符号非负 INT32 限制；不得用截断或拆入 record literal 冒充80B全读。

运行命令：

```bash
python3 -m unittest llm.test.frontend.unit.test_moe_signed_router_train_source_plan.MoeSignedRouterTrainSourcePlanTest -v
python3 -m unittest llm.test.frontend.unit.test_moe_signed_router_train_source_plan.MoeSignedRouterTrainSourcePlanTest llm.test.frontend.unit.test_flexible_moe llm.test.frontend.unit.test_flexible_moe_production -v
```

原新签名五条首次 11.535s 全通过；扩展为两层两步、实际旧 lowerer 拒绝和旧 producer 伪装负例后六条聚焦 **6/6 PASS，12.088s**。旧 inference/SGD baseline 与新版本组合运行 **27/27 PASS，36.052s**，覆盖100种矩形编译、真实旧生产 linked manifest/ProgramIO、fan-in 和原2×3 ID。未执行 C++ native/finalizer/NpuSim，因为本阶段的新增 producer 尚无真实0x27/28后端，默认生产路径必须拒绝。
