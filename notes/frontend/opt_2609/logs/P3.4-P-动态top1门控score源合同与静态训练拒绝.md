# P3.4-P：动态 top1 signed router score 数学合同与旧静态训练拒绝

## 真实源缺口

原 v1alpha1 MoE trace 的每条 `MoeRectTraceAssignment` 显式冻结 token→expert/home/slot 以及 `gate_weight_f32_bits`（默认 FP32 1.0）；P2 TRAIN 同时按 router FP16 H×E 状态创建 GATE_WGRAD→FP32树SUM→GATE_SGD。现生产 GATE 的 MATMUL score 落进后续expert RETURN/weighted-combine公用的 `.output` workspace；`WEIGHTED_COMBINE` 仅 LOCAL_REDUCE/input_count1 复制 `.output`，不读取 score；`COMBINE_BACKWARD` 不产 dScore(k,E)；`GATE_WGRAD` 把(k,H)的 backward_by_rank 当(k,E)的上游并做FP16 MATMUL→cast。固定的权重1.0与路由选择都不依赖trainable GATE参数，因此旧默认训练不可能从loss计算真正非零gate梯度，已有expert StageO 原生0x25 PASS并不解决此处。

## 独立版本化模型与实现

新纯 source 合同 `moe_dynamic_signed_top1_router/v1alpha1` 对旧静态case显式生成**不同**动态score案例ref，原公开旧case及其 P2/TRAIN leaf源码和optimizer均保持原状并持续fail closed。新模型冻结的是离散 top1专家选择的导数，不冻结 GATE参数；score由真的FP16 forward GATE MATMUL `s(k,E)=X(k,H)×W(H,E)` 独立score tape产生。该动态score版本明确用选中专家原始有符号 score `s[t,selected]` 加权真正按 token 路由重排过的专家返回值 `y[t,h]=s[t,selected]×expert[t,h]`；GATE score其余expert分量仍存在。反向对被冻结的选择计算 `dScore[t,selected]=dot(dCombined[t,:],expert[t,:])`、其余score导数0，`dExpert[t,:]=s[t,selected]×dCombined[t,:]`；native0x25 WGRAD真实FP16 `X(k,H)` + FP16 `dScore(k,E)`→FP32 `dW(H,E)`，随后EP门控FP32汇聚才可SGD。承诺是 timing/访存/血缘合同（functional=false），没有声称数值梯度 oracle。

实现 NEW `passes/moe_full_train_router_score_source.py` 从已编译的真实 P2 TRAIN step0/1×layer0/1、rank0/1 源trace/actions/states生成8条 `MoeTrainableRouterScorePath`，逐token保留索引、expert选择/home/slot；rank0每段真实交错 EP0/1 四token、H4、E2，对应score tape16B、dScore16B、expert返回32B、dCombined32B、原FP16 gate参数16B、FP32 gate梯度32B，rank1无source token，明确score与WGRAD零work但仍参与后续全局32B梯度同步。GATE/combine/GATE_WGRAD算量各按P2原声明验2mHE/2mH/2mHE FLOPs。外部static gate weight若不是FP32 ONE，此动态案例严拒静默忽略。整个版本身份/逐token路径严格重算，不能手改专家选择或将新case ID伪替换为旧ID。

四个独立物理门禁严拒原StageO生产leaf：没有单独保留的 GATE score BufferABI；weighted combine没有 score 和按route table gather的真实expert RETURN BufferABI/物理输出；combine backward没有消费正确专家返回及 dCombined 的 dScore producer；router gate WGRAD仍是旧FP16 MATMUL+cast而非源X/dScore/output的native0x25。未来正路径需要逐源token实物 route table 与score、expert-return、weighted-combined、dCombined、dScore 的不同FP16 BufferABI和精确Relocation/AddressOperandBinding tensor slice闭包，以及native0x25的(m,n,k)=(H,E,rank_rows)、FP16/FP16/FP32物理合同；只添动作标签或改变状态字段不能通过。
