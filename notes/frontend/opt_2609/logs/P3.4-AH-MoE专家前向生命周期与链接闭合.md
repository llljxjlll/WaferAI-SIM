# P3.4-AH — MoE 专家前向生命周期与链接闭合

本阶段只推进 EP1 两层 `MOE_EXPERT_FORWARD` 的物理片段，不提升完整训练门禁。输入沿用已签名的 IR1 / GlobalActionDAG / ScheduleSet；每个专家动作具有两个独立、归属明确的 schedule scratch 根（gate/up concat 128 B、SwiGLU activated 64 B）。

- 原生 leaf 为四组 `SRAM_BIND + MATMUL/MATMUL/SWIGLU/MATMUL`，共 8 条 payload 记录。`CommandFragment.validate_against` 逐条检查源 workload 参数、5 个公开 BufferABI、2 个 scratch BufferABI、源引用及第二投影的 64 B 输出位移。
- 官方 `add_fixed_sram_lifecycle` 从 ScheduleSet 取 scratch，不使用未签名的叶内地址；两层 leaf 各经装饰得到 17 条记录（3 个 ALLOC_AT、8 个 payload、6 个 FREE），且均通过 DAG 相对校验。
- `lower_program` 的 `MOE_EXPERT_FORWARD` 分支使用同一 leaf。linker 和 linked manifest 的对应窄分支将专家 SRAM_BIND/compute relocation 及 scratch 生命周期绑定到 source-bound BufferABI；普通 COMP 链接路径保持原校验。
- 负测把第二 MATMUL 的 concat 输出位移从 64 B 篡改为 0，DAG 相对校验拒绝。
