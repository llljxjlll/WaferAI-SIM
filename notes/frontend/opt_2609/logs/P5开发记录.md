日期：2026-09-14

## 目标与边界

本切片为 `1≤H,W≤10` 的全部 100 个矩形和 Dense/MoE 推理/训练四类负载建立版本化 schema/preflight 报告，共 400 个 case。每个 case 都调用统一的 `WorkloadRunRequest` 和 `materialize_workload_preflight`，没有用手写摘要代替 placement、graph、transport 或 memory planner。

本切片不调用 finalizer、resolver 或 NpuSim。所有 report 和 matrix 的 runtime 状态固定为 `not_measured`；preflight capability 只声明 `schema_only`，因此 materialization 状态保留 `unsupported` 并包含 `family.runtime`，不能由 400 个静态 case 推导 runtime support。

四类 case 共用固定的两层 FP16 tiny 模型维度：hidden=4、intermediate=8、attention/KV heads=4、head_dim=1、最大序列 8；MoE 使用 4 experts、静态 top-1。推理执行 Prefill 2 token 加 2 个 Decode step；训练执行 2 个完整 SGD step。

1. `mesh_scaled_all_dies`：60 个 shape、240 个 family case。根据物理 rank 数选择可整除固定模型的 TP，MoE 再选择合法 EP，其余为 DP；所有 Die active。

10×10 的四个 family 均走全 100-rank 映射，作为本切片的代表性大 mesh preflight canary。

## P5.4/M1：有界 P2P session admission 与 2×2 Dense runtime

日期：2026-09-15

### 目标与最小复现

目标是在不修改 `MAX_BUFFER_PACKET_SIZE=3` 的前提下，关闭 2×2/TP4 Dense
Prefill→Decode→Decode 在 core 12 报出的
`P2P endpoint receive session capacity exhausted`，同时保留真正依赖后续
`DTE_WAIT` 的非法超额 stream 的 fail-fast 行为。

逐 token 审计三段 linked stream 后确认，fused `DTE_RECV` 后均紧跟同 token 的
`DTE_WAIT`，每 core 的异步 receive 峰值为 1，lowering 没有堆积未等待的 receive。
真实根因是同步 TX 的指令完成与传输退休是两个时点：`TryRetireSync` 在 local send
完成后允许主 record worker 前进，但 session 仍保留到 completion ACK 到达。TP4
连续三个同步 send 可占满三个槽；下一个 receive 到达时，旧实现立即抛错，虽然独立
NoC/ACK 处理线程能够在稍后安全释放这些槽。

最小 C++ 复现构造三个 `local_retired && !acknowledged` 的同步 TX session，证明硬
容量仍为 3、第四项仍被 runtime 拒绝，而任一 completion ACK 可独立释放一个槽。
另一独立 fixture 用一个未执行 WAIT 的异步 RX 占满容量，证明这种状态只能由本 core
后续指令释放，不能在当前指令中等待。

### 实现

`P2pEndpointSessionRuntime::AdmissionState()` 提供三态 admission：

- `READY`：存在空闲 session 槽；
- `WAIT_FOR_TRANSPORT`：容量已满，但至少一个 TX 已完成 local retire、只等待独立 ACK；
- `REQUIRES_LOCAL_RETIRE`：容量已满且没有可由独立 transport 进展释放的槽。

production Worker 的 send 与 receive 在第二种状态等待 `ev_p2p_progress`，收到 ACK
后重新检查并 admission；第三种状态继续抛出原有 capacity 错误，避免阻塞在释放槽位
所需的未来 `DTE_WAIT` 之前。send 的 SRAM/HBM source read 可能让出 SystemC 调度，
因此在 source read 前和原子 `IssueSend` 前各执行一次 admission。链路事件缓冲、每
wave planner 上限与 `MAX_BUFFER_PACKET_SIZE` 均未改变。

### 测试结果

- `cmake --build build-debug-final --target npusim -j2`：PASS；
- `npusim --p2p-session-selftest`：230 checks PASS；
- 原失败 2×2 finalized 三段产物：PASS，KV bytes 为
  `4096→5120→6144`，三段 marker、one-shot drain 和唯一 `SIM_RESULT` 闭合，
  makespan 88,111 cycles；core 0/4/8/12 的 P2P residual 均为 0，shared timing
  residual 为 0；
- 1×1 finalized 三段回归：PASS，KV bytes 为 `512→640→768`，唯一
  `SIM_RESULT`，makespan 46,787 cycles，shared timing residual 为 0；
- `git diff --check`：PASS。

本切片证明的是上述 1×1/TP1 与 2×2/TP4 Dense 三段同实例 runtime。它没有改变任意
mesh 的能力声明，也没有扩大 endpoint 或链路容量。
