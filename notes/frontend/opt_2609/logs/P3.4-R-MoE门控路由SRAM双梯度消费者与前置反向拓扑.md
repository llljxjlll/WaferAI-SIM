# P3.4-R：MoE route SRAM、dExpert 消费与前置反向依赖

## 目标与必要的时序纠正

沿 P3.4-Q 真实 top1 expert/home/slot 源，必须在同一物理时间线中令0x27/0x28真正读取一份 route table，dScore/dExpert各占独立FP16输出，且dExpert按EP分组进入专家首个DOWN DGRAD。审计现行 `passes/flexible_moe.py` 原生产P2图发现P3.4-P/Q未检查的阻断：`BACKWARD_GRADIENT SEND→RECV→EXPERT_DGRAD→BACKWARD_DX SEND/WAIT→COMBINE_BACKWARD` 是已有依赖顺序。旧 `COMBINE_BACKWARD` **在专家DGRAD之后**，因此原P3.4-Q几何 workload 若把0x28绑旧action，再把其dExpert输出作为专家输入，将形成读取先于生产的依赖环；原P3.4-Q的29/29源布局回归不构成可执行反向数据流证据。

新版本必须在真实共享模型的dCombined生产后、`BACKWARD_GRADIENT SEND`及本地专家DGRAD之前新增独立 `SCORE_WEIGHT_BACKWARD_PRE_DISPATCH` source action：保留 forward score 和真正expert RETURN，0x28产 dScore及已score加权的dExpert，远端专家用原P2 rank0→rank1 BACKWARD_GRADIENT grouped Flow完整发送/接收、本地专家直接消费分组，之后保留原 late `COMBINE_BACKWARD` 汇合EXPERT_DGRAD的DX回流、门控梯度和SGD。不能挪旧action或改标签冒充源先后。`passes/moe_full_train_router_pre_dispatch_dag.py` NEW-only virtual topology proposal按每step×layer独立 dCombined producer引用添加前置action、BACKWARD_GRADIENT SEND/本地专家DGRAD新边，DFS检查真实环、缺producer、缺send/local消费、remote DGRAD间接支配、旧late DGRAD/DX前驱保留；**该virtual图不等于MoeRectPlan/GlobalActionDAG/IR1**，现P2官方生产action并无前置kind及共享dCombined producer，`require_production_source`严格拒绝。

## 独立物理work与source-to-buffer门禁

- NEW-only `schema/passes` source seed 从原P2实际 `(token,source_rank,selected_expert,expert_home_rank,slot)` 每token按五个little-endian UINT32/INT32字段一次派生，四token源负载 **80B**，源SHA/完整字节、非零expert/home/最后slot均核实；不得把 route table 当嵌套record literal或者在ProgramIO和prim profile手写两份trace。当前 `artifact_manifest.LiteralValue` 只接受 `tuple[int,...]`，旧P3.4-P `_route_table`要求tuple嵌套，正是尚无合法动态record表示的另一项精确生产缺口。真正新public算子还要为route读增加**独立第4/第6输入地址**，versioned route地址语义建议ID22、0x28第二独立dExpert输出ID21，禁止复用AdamW的13–20角色；0x28 score/return/dCombined/dScore/dExpert五地址以外实际还须 INT32 route第六地址。
- `moe_full_train_router_route_sram.py`严格入口：route INT32 80B 必须 BORROWED、非alias且SRAM absolute BufferABI closure；0x27/0x28都要有精确同地址的完整80B relocation + INT32 TensorSlice（不能藏于 literal）；ProgramIO必须同source seed完整80B、两独立OWNED FP16 dScore16B/dExpert32B 各有AFTER_PROGRAM full-span probe，两个输出的真实nonzero uint16 SRAM地址不重叠。原0x27/0x28 C++/Python生产codec、外部 record 和ProgramIO未实现，所以当前旧leaf严格 FAIL；没有独立source签名实体不能宣称物理播种。
- `moe_full_train_router_dexpert_handoff.py`对四step×layer P2 source将rank0 localEP0 assignment.0/2 分组16B offset0、remoteEP1 assignment.1/3 分组16B offset16；后续真实0x28 dExpert全32B输出→local EXPERT_DGRAD首个DOWN MATMUL正段、remote原BACKWARD_GRADIENT DTE_SEND源addend16→EP1 DTE_RECV单独expert upstream16B addend0→首个DOWN DGRAD。检查每条 record的typed BufferABI/ABSOLUTE symbol/relocation/exact tensor slice与本地/远端原source refs一致。旧生产0x28不存在，严格拒绝，不能以P2几何正例提升runtime。
- NEW-only `moe_signed_router_native_work.h/.cpp`只含未注册的独立C++原生work+float参考oracle。0x27四实际地址route80B+score16B+return32B→combined32B，读route80B+FP16 48B/写FP16 32B、32 logical EXU FLOPs；0x28六实际地址route80B+score16B+return32B+dCombined32B→dScore16B+dExpert32B，读route80B+FP16 80B/写FP16 48B、32 EXU+16 vec=48 logical FLOPs。其参考算术必须消费源签route bytes后按home/slot gather，dScore只对选中专家做dot，dExpert score×dCombined后按专家home/slot写；当前NpuSim/prim没有此数值执行，不能当生产functional计算。所有跨度16B对齐、实际uint16核心SRAM范围、不重叠且无最后token缺损。只读核既有 `NpuBase::serialize`发现严格Prim wire metadata可存三32bit地址，每段额外四个30bit命名参数；新增未注册 `BuildMoeRouterForwardPrimProfile/BuildMoeRouterBackwardPrimProfile`分别给metadata score/return/combined 或 score/return/dCombined，并在5/7命名参数中保留 `ROUTE_ADDRESS`、`ROUTE_BYTES`、`K/H/E` 和反向独立的 `DSCORE_ADDRESS/DEXPERT_ADDRESS`，自测检查真实80/16/32B地址不混写。共享公共record/PrimId仍未接入。
