# P4.4-R24：Dense 推理 TP6 扩展矩形双 Fresh 与受管清理

日期：2026-09-18。承接 [R23](P4.4-R23-Dense推理TP6十八KiB低HBM外存原生闭环.md)，把固定 TP6、两层 Dense、Prefill + 2 Decode 的低 HBM 外存验收入口从三个列举形状扩展到任意合法的 1..10 矩形，前提是物理 Die 数至少为 6。正式源仍只激活六个计算 Die；空闲 Die 可以承载物理路由。这个改动不意味着全 Die 活跃或任意 TP 已支持。

## 开发与检查

- 双 Fresh 审计按物理网格计算六个活跃 Die，并逐项核对源级 placement、原生 core、HBM home、真实 external DMA、D2D 包、KV 版本和三个 segment 的 finalizer/ProgramIO 产物。3×3 使用 `[0,1,2,6,7,8]`；其他合法几何采用源级固定模型相同的等距物理编号规则。输入在创建输出目录前检查 canonical 格式、每边 1..10 和 Die 总数 ≥6。
- 新单测把 2×3、3×2、3×3、1×6、6×1、4×7、10×10 的审计 Die 列表与生产源 placement 对比，并覆盖非 canonical 或不足六 Die 的拒绝。2 项通过，`git diff --check` 通过。源码提交 `d36d07df`。
- 3×3 在 18,432B/Die 下，同模型 resident-only 因 Die0 需要 19,536B 被拒绝，报 `memory_capacity_exceeded`；offload 两套独立完整源物化及每套两次原生 NpuSim 均通过。六个实际运行 Die 为 `[0,1,2,6,7,8]`，对应 Core `[0,4,8,24,28,32]`。resident/offload 的有用图摘要均为 `bb5541d06bdd8d440b15e9371eac7d691fd1c747f7a11004c057d8d6e9e3e45d`。
- 3×3 每次原生运行记录 390 笔 external DMA、72 个 KV probe、外存读 762,048B/写 48,384B、D2D 收/发各 26,112 包；makespan 129,062 cycles。KV 版本为 0→1→2→3，分页最高地址 17,088B，低于 18,432B 物理 HBM 窗口。两套独立报告字节完全一致。报告标记 `functional=false`，此处只验收 timing 模式的物理执行和状态版本，不据此宣称数值正确。

3×3 的紧凑审计收据见 [JSON](P4.4-R24-Dense推理TP6扩展矩形3x3双Fresh收据.json)；原始 `full_fresh_evidence.json` SHA256 为 `b9db3157e03b54bc9a69d37f76647faa890e407b20914673a9c3e81865d280a5`，两个独立报告 SHA256 均为 `1a2fe562b79696e89b3d4b65f07dd72b780ae49f6f107d44a992f7042030717a`。使用 `build-debug-final` 的 NpuSim，SHA256 为 `a80a5208a2176ad80ae7aa286f15ec98f94c1bb8f0f5091c16ca4aa5d388fae1`。

4×7 的同一模型、同一 18,432B/Die 硬件也完成双独立完整物化，每套均含两次原生 NpuSim，报告逐字段一致。实际计算 Die 为 `[0,5,10,16,21,27]`，Core 为 `[0,20,40,64,84,108]`；D2D 收/发各 54,528 包，makespan 143,867 cycles。resident-only 同样报 `memory_capacity_exceeded`；390 笔 DMA、72 个 KV probe、外存读 762,048B/写 48,384B、KV 版本 0→1→2→3 均通过。紧凑收据见 [4×7 JSON](P4.4-R24-Dense推理TP6扩展矩形4x7双Fresh收据.json)；原始完整审计 SHA256 为 `0f77331c1256fe2e58a56733d10bb1da23827cc88eb45a0ffdaec70ab5cc3423`，两个独立报告 SHA256 均为 `cabafad09dbe66b6c334c944ec24ed460cd15f67183a61478aac015288440d51`。

本轮实验均由 `scripts/frontend_tmp.py` 的受管 evidence job 启动，设置 4 GiB 上限、5 秒检查间隔和失败任务 2 小时 TTL。3×3 与 4×7 审计收据落盘后分别 `release`，回收 107,911,405B 与 110,402,487B；受管临时目录和 `build-managed` 各只剩约 8 KiB 标记，当前原生运行必需的 `build-debug-final` 保留。后续每个矩形继续执行相同的“受管运行→审核紧凑收据→显式释放”流程，避免在 `/tmp` 或 `build` 长期累积原始程序、JSON 和重复 NpuSim。

这只是 M2 固定 TP6 推理补充矩阵中的一个新增物理形状。M1–M3 四类负载主矩阵、全 Die Dense 推理 Embedding tile、MoE EP2 全训练和数值正确性仍须单独完成与验收。
