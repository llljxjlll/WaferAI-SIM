# P3.2-R21：TP4 非紧密归约 V3 原生 stride 与 SRAM 读取

日期：2026-09-16。延续 [R20](P3.2-R20-TP4两步训练原生物理门禁与SRAM对齐开发记录.md) 的真实 TP4 固定 SRAM 64B 对齐阻断。生产链接 `/tmp/dense_train_tp4_20260916_aligned_native/full_tp4_two_step.linked.json` 中单 rank 输入为 32B，但四个真实 BufferABI offset 分别为 0/64/128/192B；不能为了通过 C++ 校验把 NpuSim hardware 的 64B allocation alignment 改小或让 primitive 继续按32B读取。

原生实现：`LOCAL_REDUCE` codec 保留旧紧密布局的 V1 record payload，放行仅当输入 stride 至少覆盖逻辑元素、按 dtype 对齐、最终物理字节跨度不溢出且单输入不能声明非紧密 stride。`program_format` 用 `(count-1)*stride+input_bytes` 检查源 SRAM 区域，`record_lowering` 不再丢弃 stride。`Collective_data_v1_prim` 新增非紧密 rank-major V3 wire（六段 wire 不扩容，仅 V3 才使用原保留的64bit stride 字段）；V1/V2 保留原 wire/行为，V3 禁止单输入、非法步长以及损坏保留字段。实际 SystemC SRAM 每 rank 读取 `base+rank*stride`，仅取该 rank 的逻辑32B，再按原算法聚合，不把物理 padding 当成数据。C++ finalizer 多 BufferABI 闭包按严格的各 rank offset/逻辑 view/完整源 extent 核对；该共享文件的最终代码已随并行 MoE finalizer 提交 `091cdfd2` 入库。

独立隔离构建 `/tmp/tp4-stride-build`：`npusim_program_finalizer` 对上述 17MiB 真实链接源成功，产物 `/tmp/tp4-stride-aligned.npup` 821000B、SHA256 `e7cd3fb7751c22c35062fc8dbf758b441c6fbef957a58a6ffc2653ffc88b4610`，报告显示四核、6456 record、10968 relocation、绑定 linked digest `ef61f4867f92c4043f0da2ec4d2c3d8eb305e277ab24bdd18501cb527822bee1`。`/opt/cmake/bin/ctest --test-dir /tmp/tp4-stride-build -R '^(isa_v1_selftest|collective_data_v1_prim_selftest)$' --output-on-failure` 两项 exit0；归约原语 20 项检查包含四 rank 各32B、物理64B间隔的真实 SRAM 值结果、V3 编解码与 stride 过短负测；ISA 综合测试覆盖 codec roundtrip、dtype 错位、最终源物理一字节越界与 lowering。旧二进制原有 FP32 测试把 `+Inf + -Inf` 无规定的 NaN 符号位硬比为正号，运行前对照失败 1/16；仅在测试中忽略该符号位，仍逐位比较其余数值、NaN payload、时延，改后 20/20 全通过。
