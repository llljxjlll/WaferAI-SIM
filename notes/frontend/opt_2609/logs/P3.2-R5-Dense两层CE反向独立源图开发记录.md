# P3.2-R5：Dense 两层 CE 反向独立 dLoss 源图

日期：2026-09-15。范围：M1/P3.2 的真实源图增量；**仅 CE 反向语义 IR0，不计完整训练成功**。

## 目标和实现

生产模块 `llm/frontend/wafer_frontend/passes/full_dense_training_ce_ir0.py` 复用生产 `build_train_forward_ir0` 已验证的完整两层 Dense TRAIN 前向，原封保留前向所有节点及十五份参数 declaration，并追加 CE_BACKWARD DGRAD 的 typed workload。它将 CE-forward logits 与 labels 的原消费者扩展到反向节点；新 `T0.loss_gradient` 独立 FP32、逐 row、`producer=None`，与前向 CE 所产生的 `T0.loss` 分开；新 `T0.logits_gradient` 为 FP16。前向 CE→反向 CE 有显式 control edge，logits→反向 CE 有显式 data edge。源图原样保留所有 state accesses。源图构造结束运行原版 `IR0.validate`，不以测试 fixture 或 surrogate 替代语义检查。

第一版仅允许真实复制边界 TP=1：原版 Dense CE backward validator 需要输入/输出 replicated，同一 validator 对多层 TRAIN 出于 S2-Lite 单参数限制拒绝，TP>1 必须在真实行分片、局部形状和 physical rank lowering 验证实现后另行开放。

## 验证和边界

`python3 -m unittest llm.test.frontend.unit.test_full_dense_training_ce_ir0`：4/4 PASS。真实 `_spec(1,1)` production forward 图导出的 backward 源图为 27 nodes、45 values、31 edges，保留 15 个原有参数 declaration；重复派生严格相等；检查前向 loss 的 producer 与独立输入 dLoss 的 producer 不混同，检查 CE 的真实控制依赖；负例覆盖 TP4 未实装 sharded loss gradient、改写前向 loss producer、现有生产 DenseIR0Validator 确切拒绝多层 CE-only 训练。无 NpuSim 运行，model functional 不测。

这张图还缺完整 attention/norm/embedding/MLP 等 backbone DGRAD、每份参数 WGRAD、DP sync、各参数 SGD 和第二步读写版本；也没有对应的生产 IR1/Projection/Schedule 对所有新增源任务建立双射。旧计划 `FlexibleDenseTrainPlan` 即使列出每个参数的 backward 模板，也仍明确 `full_model_backward_materialized=false`，必须维持。新 CE-only 源图和其他 scoped physical carrier 不能借名称补齐 M1 训练验收；等生产 DAG 深验证、finalizer/ProgramIO/NpuSim 双独立真实运行与独立覆盖 oracle 均通过才允许标记。此记录属于源码提交批次，实验运行产物维持单独提交批次。
