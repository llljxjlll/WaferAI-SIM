# P5.1-R1：100 矩形 Dense 全 Die 源码构造与运行前校验

日期：2026-09-15。依据《矩形DieMesh端到端训练与推理负载支持完善开发计划》P5.1，先冻结 1..10×1..10 的确定性 Dense 全 Die shape-scaled 主模型源。**本记录只覆盖 L0/L1 运行前合同；真实 NpuSim 成功 case 数为 0，不计入 M3 发布矩阵。**

## 目标与开发内容

为每个矩形构造同一种两层 FP16 Dense 推理：`TP=rows×columns`，全部物理 Die 按行优先参与，`H=NH=KVH=TP`、`I=2×TP`、`DH=1`、`V=max(128,TP)`；推理是每个 Die 对应一个 request 的 Prefill1→Decode1→Decode1。这个 profile 随 mesh 尺寸变化，不替代计划要求的固定模型补充矩阵。每 Die HBM 容量 1 GiB、SRAM 默认 64 KiB；TP6 保留已经实测的 128 KiB/32B 对齐 profile。模型和容量定义都与 case ID 一起由生产 request 物化，输入数组覆盖完整 Fabric/HBM 地址空间。

在 `run_dense_sequence_runtime_canary.py` 新增显式 `--scaled-all-dies` 路径，原固定模型路径及选形仍有效。runner 的实际生产编译以后才检查三段 linked core-stream Die 集合恰为全部 active Die，并记录 `scaled_all_dies`、active/idle/编译后的 Die 身份；随后原生 finalizer、ProgramIO resolver 和 NpuSim 的过程不变。这一新路径尚未执行，因此不能把 runner 可调用性解释成发布成功。

`test_dense_all_die_scaled_model.py` 增加独立来源测试：3×3 的九 Die 和 10×10 的百 Die 均是完整两层/三阶段逻辑图；遍历全部 100 个矩形，逐个检查 Die/TP/拓扑双向 link 算式、完整 active、三段生产编译输入校验、case ID 唯一；范围外 0 或 11 轴拒绝。
