# P3.2-R41：Dense 2×6 十二 Die 两步训练与原生 SRAM 时序输出

在完整两层 Dense、TP6×DP2 的固定硬件配置下，源图 682 个节点，两个 DP 副本各下沉 1884 个片段；物理 DP 梯度任务 1440 条、状态 ABI 180 个、两步参数梯度路径 360 条。源编译、链接、物理梯度门禁和 ProgramIO resolver 均通过，原版 NpuSim 首次真实执行却在 die 8 / core 0 的 `LOCAL_REDUCE` 读取 SRAM 地址 128、48 字节时报告 `first_invalid=128`。

该归约读取 split-K `MATMUL` 的第三个 rank-local partial。原生 program-mode 矩阵乘法只计算时序，不执行旧式隐式输出写入；物理地址跨生命周期复用时，ProgramIO 无法在程序启动前同时初始化全部不同 owner，因此此 partial 在计算后仍无有效字节。`Matmul_f` 在 program-mode 的 payload SRAM 路径上现在只为未初始化的输出写入确定的零字节；已由 ProgramIO 显式初始化的输出保持原有 payload，旧式隐式内存模式保持原状。零字节只代表 timing 输出具备传输/归约可读取的物理 payload，不代表 GEMM 数值正确。

同一原始 NPUP 在修改前报错，修改后仅替换 NpuSim 二进制重放成功：`[SIM_RESULT] makespan_cycles=143843`，ProgramIO 1400 次初始化、24 个探针验证通过，P2P drain 为零。重新编译原生工具完成，`npusim --isa-v1-selftest` 通过；SRAM wire-safe 3 个单元测试、托管临时目录清理 10 个单元测试通过。源码提交 `9b8bce3a`；最终重编译 `npusim` SHA256 与两轮收据完全一致（`61b753a956471f74e7a18320d1aa217a7b08995d771eaf078339b67186b3bc16`）。两次完整、彼此独立的空目录 Fresh 验证均通过，35 字段逐项相同，均为 **143843 cycles**；精简收据见 [R41 收据](P3.2-R41-Dense十二Die双步训练双Fresh收据.json)。

构建复用现有 `build-debug-final` 增量目标，未新增整套 CMake 构建目录。Fresh 作业使用 `scripts/frontend_tmp.py` 的独立 evidence 目录与 4 GiB 预算；空目录运行失败立即释放，原始诊断重放作业提取失败/通过证据后释放约 114 MiB，两轮 Fresh 均在复制精简收据后各释放约 119 MiB；后续新 scratch 构建仍置于 `{tmp}/build`，成功即自动清理。其他旧构建目录仍服务现有任务，未盲删。

这是 M1 Dense TRAIN 的一个 2×6 实例；任意 TP/DP、Dense/MoE 四类全部场景、M2 外存 offload 与 M3 全形状矩阵仍须逐项验证，不能据此宣称完成。
