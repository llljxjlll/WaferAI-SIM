# P3.2 R6：GEMM 权重 FP32 梯度具名物理原语

## 目标和产物

公开 `GEMM_WEIGHT_WGRAD_TIMING=0x25`，映射独立 `PrimId74`。原语读取前向 FP16 `X[k,m]` 和真实上游 FP16 `dY[k,n]`，占用独立 FP32 `dW[m,n]` 物理 SRAM BufferABI，准确计入源读取、FP32 写入/RMW、FMA/EXU/vector 工作。三个非空物理跨度分别为 `2km`、`2kn`、`4mn` 字节，三个16B对齐且互不重叠，维度为正并可表示。公开 fixed 88B wire record 的九字段 DTO、canonical 保留位、opcode/Prim manifest、codec、lowering、ProgramFormat、relocation、finalizer 和生产 Python schema/action/coarse/linker 均已接入。

生产 Dense LM head 的参数反向源现使用独立 `OpKind.GEMM_WEIGHT_WGRAD`、严格 `GemmWeightWgradWorkload` 和 `impl_ref=gemm_weight_wgrad_timing`，输出独立 FP32 TensorValue，源前向节点和源状态 ID 随图携带。旧 MATMUL 的 FP16 结果不再能冒称 FP32 权重梯度。`FullDensePhysicalGate` 要求 source state 的 `(m,n)`、forward rank shape `(k,n,m)`、native record 的 FP16/FP16/FP32 literal、三份独立物理 BufferABI 字节数和 rank 完全吻合；将梯度目标压成 FP16 字节数的负例必须拒绝。现有 GEMM dX 没有独立公共 native opcode，完整训练门禁仍 fail closed。

此原语只实现 **TIMING_ONLY**。它没有数值矩阵乘累加，NpuSim 中 FP32 输出使用明确的 `TIMING_PARTIAL` 零种子作写入/探针，因此 `FUNCTIONAL=false`；不可称为真实数值梯度或完整 Dense/MoE TRAIN。

完整训练仍缺 GEMM dX、Norm/Attention/RoPE/Residual/SwiGLU 逐源 dX、Embedding token tape 至 FP32 table scatter WGRAD 的跨阶段 lifetime、层间 loss 反向、DP/TP 梯度同步，以及 FP32 数值梯度到两步 SGD/AdamW 写回。大的权重 shard 还需生产可见的 SRAM 分块/FP32 聚合。这个一核物理片段不能替代多层端到端训练验收。
