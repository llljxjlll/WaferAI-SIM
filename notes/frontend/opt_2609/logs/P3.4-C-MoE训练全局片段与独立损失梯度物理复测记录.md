# P3.4-C：MoE 训练物理依赖片段与独立 dLoss 的有界复测

日期：2026-09-15。阶段状态：**局部训练链及独立 dLoss 的两层 Dense CE timing 真实运行；完整两层 MoE 训练仍未验收。**

## 目标与本次实现

- 四个既有生产 MoE TRAIN block（step0/1 × layer0/1）重新命名动作、SRAM region 及全局 HBM home。新的物理依赖 receipt 精确覆盖每个真实 fragment/core 记录，逐条约束源 P2 SEND→RECV 通信，并将两层四组专家/路由参数 step0 的真实 LSU_STORE 连到 step1 同地址的 LSU_LOAD；共 8 条跨步状态版本边。此 receipt 是物理结构 oracle，不能冒作生产 `GlobalActionDAG`。
- 新的共享反向梯度接口要求 rank0 具名 Dense backward action 真实产出 owned FP16 `tokens×H` SRAM view，并提供 blocking DTE_ISSUE→DTE_WAIT 本地复制到源 P2 的 rank0 MoE backward-gradient carrier（该模型有效数据 `4×4×2=32B`，源 backward-gradient SEND 为 `16B`）。旧 Dense BACKWARD/WGRAD `MATMUL(1,8,8,8)` 重用第一参数的 FP32 scratch，现被该 oracle 明确拒绝，不能冒充共享骨干反向梯度。真正 Dense native 反向 producer、源/目标 buffer 生命周期重签和 bridge 的全局动作仍待实现。
- CE 原 timing carrier 把 forward loss（FP32，SRAM offset 3520）作为 backward dLoss，数学上错误。新 seeded CE carrier 为每行独立 `FP32 1.0` BORROWED dLoss（offset 3584/16B）并在 offset 3648/128B 分配 OWNED FP16 logits-gradient；有界 physical graft 仅把旧 logits/labels 两条 FREE 挪至 CE backward，旧 forward loss FREE 保留，其真实 linked ref 随 fragment 一起重签。原两层 Dense forward `153` 条真实记录增加到 `159` 条，native 0x1F AUX 只绑定新 dLoss ABI。旧三 FREE timing surrogate 仍可用于旧物理结构测试，但专用 seeded graft/API 会拒绝其进入完整训练路径；零 dLoss 被专用 ProgramIO 种子生产合同拒绝。
- 有界 `LinkedProgramManifest.validate` 和 real C++ finalizer/ProgramIO/NpuSim 的执行只验证 Dense 两层 forward→单次 native CE backward **timing**，没有物理 MoE block，也没有全参数反向梯度。通用 full-training merger 已要求真实 IR1、projection、schedule、production GlobalActionDAG 与 `LinkedProgramManifest.validate_against`；独立物理 receipt 只用于辅助核对，不被填入 `GLOBAL_ACTION_DAG` 输入摘要。
