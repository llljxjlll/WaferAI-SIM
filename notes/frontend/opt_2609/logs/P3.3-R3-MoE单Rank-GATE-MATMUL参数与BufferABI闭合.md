# P3.3-R3：MoE 单 Rank GATE MATMUL 参数与 BufferABI 闭合

## 问题

单 Rank `flexible_moe_production` 把 legacy GATE `MATMUL` 参数硬编码为
`(1, 32, 1, 16)`。public finalizer 按 `(B,m,k,n)` 解释四元组，
因此 data operand 的访问量为 `k*n*2 = 32B`。1×1 full-model fixture 的
真实维度是 `m=4,H=4,E=1`，GATE 权重 BufferABI 只有 `H*E*2 = 8B`，
finalizer 正确拒绝了这组不一致的生产记录。

## 修复

GATE 记录现在从已签名 action/spec 生成参数：

```
(1, len(action.assignment_refs), spec.hidden_size, spec.expert_count)
```

1×1 full-model fixture 因而得到 `(1,4,4,1)`。finalizer 推导的
input/data/output 访问量分别为 32B/8B/8B，与实际 activation、GATE 权重和
输出 dense view 一致。现有 GATE WGRAD 参数未在本修复中扩展。

## 严格回归

- 实际 1×1 full-model compile 后，segment 0 的两条 legacy GATE MATMUL
  都是 `(1,4,4,1)`，两份权重 BufferABI 都是 8B。
- production `npusim_program_finalizer` 接受该完整 full-model manifest。
- 将其中一条 GATE data binding 的 dense view 从 4 个 FP16 元素缩为 3 个，
  重新签名 manifest 后，finalizer 必须以
  `payload byte extent does not fit its dense view/root` 拒绝。
- `test_flexible_moe_single_rank_finalizer`：3/3 PASS。
- `test_flexible_moe_production`：15/15 PASS；代表矩阵显式覆盖
  1×1、1×2、1×3，inference/train 均通过。
- `test_moe_full_model_compile_sequence`：11/11 PASS。
- 精确源码和测试路径通过 `git diff --check` 与 `py_compile`。

本日志只记录 GATE 参数/BufferABI 修复及其 finalizer 回归，不发布完整
native mesh matrix 或 M1 声明。
