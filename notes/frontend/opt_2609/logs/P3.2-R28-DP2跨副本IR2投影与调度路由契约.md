# P3.2-R28：Dense DP2 跨副本 IR2 投影与调度路由契约

日期：2026-09-16。对应源码提交 `af0d5536`、`5055af4a`，均只包含 `schema/ir2.py`。目标是在既有 Dense TP2×DP2 真实 2×2 物理梯度计划和 480 个 N5 sidecar 动作的基础上，将 60 个梯度同步节点接入每个副本正式 IR2 投影，并保证跨副本链路仍以原始源图、物理 N4 路由与任务逐项验证。

- `IR2ProjectionResult` 和每个 `IntraDieDAG` 新增可选、源图绑定的 DP 同步引用；普通 TP1/DP1 的稳定 artifact ID 不变。每个副本严格覆盖 60 个源同步节点，每 Die 严格覆盖本 TP shard 的 30 个同步；每条同步对应 root 5 个或 child 3 个真实 N5 action，并保持 WGRAD→真实 FP32 SUM→两侧 SGD 的依赖。
- 对每个跨副本动作，重建 sidecar、逐项比对 op、payload、origin、shape、值、依赖和 owner；按 IR1 源节点顺序和该梯度 rank program 动作原位顺序校验所有投影顺序。跨副本 SEND/RECV 可能属于不同副本的两个 DAG，当前副本只承载自己合法的本地 flow replica；同时由完整 sidecar 验证两端物理路径、方向和字节。旧 TP/state flow 仍严格检查全路径。
- 正式 `IntraDieSchedule` 与 `IntraDieScheduleSet` 增加可选的 N4 DP 物理路由计划；仅在对应 DP 投影引用一致时接受，分别校验本地 route binding 和本副本的 flow role，保持普通投影原有全路径校验。副本投影中另一副本的空 Die shell 不承载梯度任务，因此逐 Die 调度不给该 shell 注入 DP 物理路由。
