# P5.6-R2：修正核几何后 1×16 Dense 四次原生运行

日期：2026-09-16

## 范围

在 P5.6-R1 修正 frontend/native 每 Die 核网格与 C2C 端口绑定后，重新执行 `1x16`、TP16、两层 Dense Prefill → Decode → Decode resident-HBM 完整序列。源码固定在提交 `eba0bbaf`，finalizer、ProgramIO resolver、NpuSim 和 simulation 配置固定为独立工具包 SHA。

本轮启动两个独立输出根；每个输出根重新物化/编译，并在内部独立执行两轮 finalize、resolve、NpuSim，因此共有四次原生执行。该结果是超过既有 1..10 单轴 envelope 的 Dense resident inference 样本，不代表 M3 四类负载矩阵完成，也不代表 `16x1` 已验证。

## 重新打开审计

完成后重新读取两根目录的 `evidence.json`、四份 `hardware.json`、四份 NpuSim stdout、12 个 NPUP 和 12 个 ProgramIO sidecar，并再次调用冻结源码的 `observe_runtime()`。四次执行全部满足：

- native core grid `2x2`，物理 Die grid `16x1`，core stride 为 4；
- 实际有 LSU 工作的 physical Die 为完整 `0..15`；P2P drain core 为 `0,4,8,...,60`；
- 30 条相邻有向链路完整覆盖 `0↔1↔...↔15`，每条 `data_in > 0` 且 `data_in == data_out`；
- 汇总 D2D 为 `130560` in / `130560` out；
- 三段闭合为 `[(0,0),(1,0),(2,1)]`，one-shot drain 为 `(3,1)`；router、D2D、P2P timing residual 全部为 0；
- KV bytes 为 `4096 → 8192 → 12288`，三段 probe 均通过；
- 每次只有一个 `SIM_RESULT`，makespan 均为 `322335` cycles；
- 每个 NPUP、ProgramIO 和 hardware 的重新计算 SHA 均与各自 receipt 一致；四次 observed 证据完全相同。

两个完整输出根的 wall time 分别为 `2527.231s` 与 `2525.907s`，frontend peak RSS 分别约 `2.42GiB` 与 `2.49GiB`。

## 结论

修正后的 `1x16` 已不再把 16 个逻辑 rank 错映射到 4 个物理 Die；四次实际 NpuSim 执行均覆盖 16 个物理 Die 和全部 30 条有向相邻链路。它可计作 M3 Dense resident inference 的单轴扩展成功点。M3 仍需完成四类负载的 100-shape resident/offload 双运行矩阵、反向 `16x1` 或其他扩展形状，以及训练与 MoE 的对应范围。
