# P3.4-H：MoE 训练共享/专家参数真 EP2 物理绑定和 HBM 容量

## 目标与公开案例

在 P3.4-G 已构建的两层完整 MoE 前向 TRAIN 源图（TP1×EP2、V16/H4/I8、两个专家/top1、FP16 三投影、SGD 两步）上，先把真实 shared Dense 参数与原生产 MoE 片段的 router/专家参数绑定至**同一硬件配置**，逐物理 die/层校验源 StateABI、参数切片、全局 HBM 容量、SRAM 区和真实 D2D 路由。低容量配置必须拒绝，不可通过增加测试夹具容量假称旧 case 已支持。

原生产 `workload_case_654e78a45d4e4c60` 的 MoE P2 `memory_plan.capacities` 每 die HBM 16MiB，原两层 Dense 前向 fixture 64KiB SRAM；真实原MoE leaf 的 expert StateABI 是各 die **HBM0..192**、router **4096..4112**，layer0/1 leaf 甚至沿用相同 state_ref 和地址，而 Dense 共享参数在 die0 从 HBM0 起。已有版本化 TRAIN namespace 实际重签公式 `die.base + 16MiB + layer×1MiB + source StateABI.address`；故原16MiB case 的任何正 work专家源状态物理地址均**超容量**。原MoE source两条物理SRAM region `(4096,36864B)` 和 `(40960,36864B)`，完整训练 namespace 再加4096B区偏移后 region 最高到 **81,920B >64KiB**。旧16MiB/64KiB源按容量合同必失败，不能把其 `memory_plan` 峰值几KiB误当地址偏移可用范围。

为达到具有可执行来源的新物理 profile，在不修改原模型尺寸或负载计算的情况下，生产 preflight 从头编译一个**新的公开 request** `workload_case_f698249222425f2d`：同模型、路由、TP1/EP2、V16、两步SGD，显式 resident HBM 且 SRAM spill 禁止；每 die P2 HBM 容量32MiB、实际 HBM `HbmAddressSpace(die0:[0,32MiB),die1:[32MiB,64MiB))`；两 die SRAM profile 各128KiB；Dense 两层 forward 编译也从该 hardware/spec 与 die0 32MiB 空间重建。因现有 `WorkloadRunRequest.case_id` **不包括独立的硬件/profile capacity**，新的 typed `moe_full_train_physical_case_*` 额外精确签 request digest、P2 memory_plan ID、MoE full IR0 ID 和实际 placement context ID；不同真实硬件不能借同一 workload 请求 ID 冒名。

## 具体实现和物理证据

新 `MoeFullTrainHbmLayout` 对 11 个源 Dense shared StateDecl 重签 TRAINABLE/read_write，保留原生产 Dense forward StateABI 的 die0 物理 HBM home；对四份 router 权重和两层×两专家×三份 gate/up/down 权重，严格绑定原 E2E version0 `TensorValue.logical_rank`、生产 StateABI 的 die0/die1 expert aggregate **192B**、router replica **16B**，把 gate/up/down 真 64B 分别映射到 aggregate offset0/64/128。源 router 独立的两Die16B物理ABI各有真实 source state_ref；同 ID 的 layer leaf通过 layer0/1 真 namespace 重新签名。同层 expert 物理 HBM die0 layer0从16MiB、layer1从17MiB起，die1对应全局48MiB、49MiB起；router依同层原片段的4096B offset，所有地址均落各自32MiB物理空间、不碰真实shared Dense 11份参数。该稀疏 namespace 暂需超过17MiB单Die地址范围，未来低HBM必须版本化**真正更紧密的生产 relocation/page**，不能用P2 peak或旧16MiB案例冒充支持。

新 `MoeFullTrainEpPlacement` 从实际 fabric directed link/port/resource 能力构造源二维 physical EP group `(TP1,EP2)`，rank0→die0 /rank1→die1、X first 真两向 D2D route和source容量峰值，独立签 physical case/context；产官方 `PersistentStateManifest.create` 的**27 个真实 HbmBinding**：die0共19份（11 shared +8 EP），die1共8份EP，HBM region/64B对齐/每项source bytes/物理不重叠均经过生产 schema 校验。当前 `group_registry._scopes` 和 `place_train_forward_ir0` 仍限定一维 TP，按 TP×DP=1 die并以 TP shard_index 决定每状态 die；这会把专家1错误地绑到 die0。新增 typed EP组与manifest是下一真实IR1输入，**没有放宽旧 Dense placement**。

用相同新case和实际128KiB SRAM，production `namespace_moe_training_unit` 对四个原 MoE TRAIN linked leaf 真克隆 CommandFragment、动作/BufferABI/StateABI、state bindings、HBM program symbol defs；四unit 的每Die router/expert StateABI `(die,address,size)` 与新全模型布局逐项精确相同，source rank policy必须显式 `rank0_shared_spine`，默认仅 gate-all-reduce flow 的旧单算子profile不足以做真实TRAIN backward cut。上述是实测生产 namespace 重签路径，尚未 graft 共享 CE/attention/normalization 或构造完整 global DAG。

## 测试、故障注入与界限

新同硬件 source 完整正例、四训练unit 真 production namespace重签、旧16MiB/64KiB真实SRAM峰值拒绝、旧16MiB/128KiB真实HBM16MiB越界拒绝；故障注入删一份原 shared Dense 参数、层1错复用层0 home、缺 expert 三投影任一64B切片、错绑源 StateABI state_ref、缩小签源capacity、伪造 context digest 或 D2D route，**10/10 PASS**。新 full physical group和生产 PersistentStateManifest由原 signed source重算，不从夹具状态标签自证。

**训练仍 BLOCKED**：官方 TrainPlacedIR1 / Projection/Global DAG 二维 EP+DP 尚未接此物理状态清单；完整 shared Dense + router/expert backward 真梯度 producer、native FP32 WGRAD、route/top1 梯度数学合同、SGD状态版本0→1→2、合成 LinkedProgramManifest、C++ finalizer、ProgramIO 与双fresh one-shot NpuSim尚未达成。独立 MoE namespace 的四leaf schema-valid与地址一致不能作为 full-model训练验收；不宣称数值梯度functional验证。下一步先让新版 EP-aware IR1 builder/source validator 与这个真实group/27状态 home双射，并将所有共享与MoE backward节点连接单时间线、实际finalizer对含shared状态的完整source重签程序。
