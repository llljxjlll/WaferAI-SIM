# P3.2-R3：Dense 训练交叉熵反向物理片段

后续语义纠正（见 `P3.2-R3-B-Dense训练独立dLoss种子开发记录.md`）：本段工厂将 CE 前向的 **FP32 loss 数值输出**当作 CE 反向的 FP32 upstream，这是只能检验时序与ABI的 surrogate，**不是独立 dLoss**，不得把本段算作完整训练的真实 loss→梯度链。已另新增真实独立 per-row dLoss buffer + 非零 seed 的物理片段，但未生成完整 train runtime。

## 目标与开发

将原生 `CROSS_ENTROPY_BACKWARD`（0x1F）接在真实两层 Dense 训练前向的原生 `CROSS_ENTROPY_FORWARD`（0x1E）之后，消费同一 Die/同一 Core 上原有 FP16 logits、INT32 labels 和 FP32 逐行 loss，而不是重新造一个无数据依赖的训练算子。原 CE 前向在 core-order 40 后释放这三个 buffer，反向需要延续至 order 41；必须同时重签三个 BufferABI 的 `lifetime_end_exclusive=42` 和 ID，并将原三条 FREE 改由后向行动拥有，不能只移动 core-stream 的记录位置。

新增 `llm/frontend/wafer_frontend/passes/dense_training_ce_phase_carrier.py`，输入已校验的真实 forward `LinkedProgramManifest` 与 CE tape、一个 caller 提供且校验的 CE_BACKWARD `GlobalAction`，以及新梯度 buffer 的真实物理 SRAM ABI、地址/label/region 定义。输出 schema-valid `CommandFragment`、ProgramSymbolDefinitions、准确的 AddressOperandBindings、三旧→新 BufferABI ID 映射和三原 forward FREE→新 backward FREE 的 `LinkedRecordRef` 映射。前向的原 logits/labels/loss 数据保留，backward 在同 Die SRAM off 3584、长度 128B、FP16、owned buffer 写 logits gradient。物理梯度要转成 FP32 后才能供后续 WGRAD 使用，不能直接假设它已经是 FP32。

真实 1×1/两层 Dense 训练前向 producer 的 CE tape 为 logits off3328/128B、labels off3456/16B、loss off3520/16B，真实 SRAM region 容量 65536B。新片段记录准确按同一 backward action prefix/payload/suffix：`SRAM_ALLOC_AT(grad)`、`SRAM_BIND(3个前向输入/1个梯度输出)`、原生 `CROSS_ENTROPY_BACKWARD`、`SRAM_FREE(grad,loss,labels,logits)`；三个旧FREE对应 backward fragment 记录索引 6/5/4。生产 `LinkedFragment` 的 compute 合同要求 SRAM_BIND 和 native opcode 相邻，漏掉 SRAM_BIND 的初版原型没有通过这一合同审计，现已补全；沿用链接清单同一个 `_lifecycle_payload_indices` 实测 action 41 的 ALLOC/FREE 角色与四 BufferABI 闭包均成立，返回严格 payload `[1,2]`。

源身份纠错：`GlobalAction.source.dag_id` 是 **ScheduledDagRef.dag_id**，片段 `CommandFragment.source_global_dag_id` 是独立生产 `GlobalActionDAG.id`。最初原型误把前者放进片段源字段；现增加必填 `source_global_dag_id`，明确拒绝 ScheduledDagRef 原值，调用方将原 forward scheduled DAG 加入真实新 backward action 后重新签署 GlobalActionDAG，并给全部 forward/CE/backward 片段传播该新 global DAG ID。单独测试输入可用已存在的真实 forward GlobalActionDAG ID 检验两个身份不会混淆；这**不代表**测试已经生成包含 backward action 的最终新 GlobalActionDAG。

## 测试及当前边界

`python3 -m unittest llm.test.frontend.unit.test_dense_training_ce_phase_carrier.DenseTrainingCePhaseCarrierTest llm.test.frontend.unit.test_dense_training_ce_backward -v`：**11/11 PASS**，其中新7个真实 forward 输入和五项负向地址/容量/依赖/ownership/source-ID 测试均过；原生 opcode 工厂4/4过。测试校验七条实体片段记录的操作码和同一 action owner、三个前向原 symbol、四 input/output 真实 relocation、所有 early FREE 的 typed 替换、owned FP16 梯度地址与 live 前向 buffer 的重叠拒绝、ScheduledDagRef 不可冒充 GlobalActionDAG 的负例，及 `_lifecycle_payload_indices` 对真实 backward `GlobalAction` 的生命周期验收。

当前仅构成**可供完整时间线联接的 CE backward 物理片段**。尚未生成含真实两层 Dense 前向、每层 norm/attention/MLP 实体反向与专家梯度、CE 后向、SGD/HBM 版本0→1→2的一份完整 production `GlobalActionDAG`/`LinkedProgramManifest`；未做此训练片段的 C++ finalizer、ProgramIO 或 NpuSim 运行。此前1×4/TP4 两步 Dense SGD timing 证据仍只有 gradient-matmul motif。本段**不计入 M1/M2 全模型训练运行矩阵**，`functional=0` 的时序执行不能证明数值梯度或权重更新。
