# P3.4-M：专家梯度真实上游 BufferABI 与原生 FP32 生产门禁

## 本阶段目标与原始失败

Stage L 严格接上了12份 expert gate/up/down E2E v0→v1→v2 参数/SGD 源 lineage，但当前生产 step0/layer0 `EXPERT_WGRAD` action `flexible_moe_action_0a61e38745e5d206` 的实际记录仍是 `SRAM_BIND→MATMUL datatype=FP16`，其 `data_address` 来自 `rank0.backward_gradient` 而非 `rank0.dgrad_gate_up`；其随后五个物理 child 中三个 FP16结果再做 `LOCAL_REDUCE` FP32 cast。`backward_gradient` 逻辑真实梯度仅 `(k2,H4)`/16B，gate/up 的所需独立上游却各是 `(k2,I8)`/32B；预分配BufferABI有64B不会改变生产者 TensorValue 几何，更不能使错读成为合法。现将两类错误分别交给独立门禁拒绝。

## 真实源记录与具体开发

新 `moe_full_train_named_wgrad_operands.py` 从当前同源 P2生产 `MoeCompileSequence` 四块真实TRAIN step/layer LinkedManifest，不从手写地址推断每份必要物理operand：查 `EXPERT_FORWARD` gate `MATMUL` 所读取的 dispatch activation，forward `SWIGLU` output 与 down `MATMUL` 对同一 `expert_activated` 的真实消费，`EXPERT_DGRAD` down `MATMUL` 读 backward_gradient，及 child `SWIGLU_BACKWARD_TIMING` 对 `dgrad_gate_up` 的真实产出。逐记录按 `RecordOperand` symbol/ref、`AddressRelocation.addend`、`AddressOperandBinding` BufferABI ID/TensorSlice 和 `ProgramSymbolDefinition(ABSOLUTE_ADDRESS)` 的 `binding_id`、Die/core/storage span 双向闭包，确保这几份 producer 对 gate/up/down 的声明是原有真实 SRAM 物理实体。前向生产 record 可声明覆盖比逻辑切片大的预分配buffer；真正新native0x25必须逐个用**精确**slice而非只匹配root标签。

每层EP0/EP1的实际k=2，gate/up `X=activation`(16B)、`dY=dgrad_gate_up` 两独立切片 `(offset,size)=(0,32B)/(32B,32B)`；down `X=expert_activated`(32B)、`dY=backward_gradient`(16B)。三个物理`0x25 GEMM_WEIGHT_WGRAD_TIMING`输出FP32 expert-gradient同一P2 state ABI各单独128B slice offsets0/128/256，geometry `gate/up(m4,n8,k2)`、`down(m8,n4,k2)`，每expert需384 FLOPs/384B真实FP32 output。验证器的Gate/Up输入门禁独立于native输出门禁，旧MATMUL→cast不能靠声明 FP32 BufferABI 混过。

## 测试和结果边界

`test_moe_full_train_named_wgrad_operands`在真实生产复物化的 two-layer/TP1×EP2/E2E v0 case 上，分别正验12份必要 forward/DGRAD/SwiGLU-backward source spans，负验原生产 gate/up 实际 H 形上游错用、原MATMUL/LOCAL_REDUCE无法充当0x25、删除最后一层down或gate、交换两半upstream切片以及将down FP32输出重叠up offset。运行：

```bash
python3 -m unittest -q llm.test.frontend.unit.test_moe_full_train_named_wgrad_operands
```

同真实同模型硬件生产source复测 `Ran 15 tests in 31.390s, OK`（新oracle5项+该测试模块引入的StageH旧放置10项）。初版门禁把前向预分配整块root BufferABI view误当必须等于逻辑16B切片，因此 producer oracle提前拒绝真实前向；修为producer读/写 ABI view **覆盖**真实逻辑span，且未来原生0x25必须 exact view，再完整同版复测全PASS。未软化 native输出门禁。

此阶段必须**诚实标记 MoE training physical WGRAD blocked**：当前旧lowerer没有任何12份source-backed0x25，在原硬件中不可冒称expert SGD被真实梯度驱动。不能以源validator成功、训练片段状态、TIMING_ONLY 原生R6 standalone 或分段耗时拼接发布完整两层两步训练。
