# P5.1-R5：固定全局 TP6 模型的矩形源映射

日期：2026-09-15。M3 要求将固定 global workload 的布局变化与随 Die 数扩大模型的 smoke 分开。此前 `--scaled-all-dies` 对全部100种1..10×1..10形状使用 `H=16×Die数`，因此其构造通过不能证明固定模型可跨矩形运行。本记录新增独立 `--fixed-global-tp6` 入口；状态为 **source/preflight only，10×10 native runtime 尚未执行，M3 未完成**。

## 开发

复用原来的两层 Dense TP6、FP16、H48/I96/NH6/KVH6/DH8、Prefill6 与两次 Decode、六个 request，不修改模型、算子、步骤或原 3×3 的空闲中行映射。对于1..10内物理 Die 数至少六的矩形，选择六个严格递增的 row-major Die ID `floor(i×(Die数−1)/5)`，让固定模型跨越大矩形；3×3 固定保留已实跑的 `(0,1,2,6,7,8)`，六 Die 形状固定保留全参与。10×10 的固定模型使用 `(0,19,39,59,79,99)`、另94个物理 Die 空闲。`--fixed-global-tp6` 与 `--scaled-all-dies` 同时指定时立即拒绝，避免混淆测量范围。所有输入继续经过真实 mesh Fabric、HBM backing、模型/profile 和 IR0 的原生产校验。

## 测试与边界

专属测试对3×3、10×10 分别核对相同模型维度/三段步骤、真实 Die Fabric、active/idle、模型+backing preflight，并对三个段各运行 `build_ir0→logical_expand`；边界小于六 Die/超过旧 envelope 被拒绝，既有1×6、6×1、2×3、3×2 ID不变；所有 **90** 个1..10合法六 Die 及以上矩形都有互异 case ID、严格六个不同物理 Die、同一个固定模型维度签名。与 scaled100和旧 runner 一起回归 **9/9 PASS，80.382s**。

这些是源构造和前端展开，不是生产 full compile/finalizer/ProgramIO/NpuSim。未测试10×10的长路径 D2D 传输、内存地址分配、真实运行时间、双独立 fresh，也未测试少于六 Die的固定 TP6 模型；后者本身逻辑并行非法。M3 必须补全四family、100形状、resident/offload、双跑和超过10×10的实际案例；当前本记录对那些验收条目贡献 **0 次实际执行**。

后续真实CLI检查发现R5提交版本仍被旧 `fixed_shapes` 白名单在编译前拒绝；具体失败收据、入口修复和门禁测试见 [R5b](P5.1-R5b-固定TP6真实CLI形状门禁修复.md)。R5的90矩形helper/source结论保持，R5版本的10×10命令入口不能运行。
