# P3.2-R7b：GEMM 输入 FP32 梯度公共生产桥接

目标：将 R7 NEW-only `dX[K,M]=dY[K,N]·W[M,N]^T` 的具名 timing 契约接成公共外部 ISA 与生产物化片段，验证真实 FP16 权重 HBM 来源、上游 dY 物理源和独立 FP32 dX BufferABI。此阶段只证明 timing/资源路径，不生成数值梯度。

## 开发结果

- 公共 `RecordOpcode.GEMM_DX_TIMING=0x26` 对应独立 `PrimId::GEMM_INPUT_DX_TIMING=75` 和 `gemm_input_dx_timing`；88B fixed wire/DTO、opcode/Prim manifest、codec、record lowering、ProgramFormat、relocation、native finalizer、Python `artifact_manifest/action/coarse/linker` 均有真实具名映射。record 严格验证 FP16 `W[M,N]` `256`B、FP16 `dY[K,N]` `128`B、FP32 `dX[K,M]` `128`B，SRAM 地址16B对齐、跨度非空/不重叠/不越过profile；K/M/N均正。forward X只作为 source/tape witness，不伪造为此 Prim 的第三输入。
- 两层 Dense head 源 IR0 的反向节点用 `OpKind.GEMM_INPUT_DX` 与 `impl_ref=gemm_input_dx_timing`，输出真实 FP32 `dHidden[K,H]`，保留前向 head StateDecl READ 和 CE backward dLogits producer 的源引用。FullDensePhysicalGate 新增源 GEMM shard/rank几何、三件BufferABI类型/字节/存储隔离、与源StateABI相同的单次HBM LSU_LOAD、LOAD先于dX、DAG依赖和真实先行dY producer 门禁。完整训练仍因其他反向原语未闭合而fail closed。
- Scoped 一核载体将权重 `SRAM_ALLOC_AT` 与 `LSU_LOAD` 放进独立 `STATE_IO` action，拥有 FP16 StateABI HBM `READ_ONLY` 源地址 `0x1000`、256B。计算 action 在加载后使用同一个W SRAM BufferABI，非零 dY有128B borrowed SRAM host seed；FP32 dX拥有独立128B terminal allocation与 AFTER_PROGRAM EXACT probe。载体通过 `LinkedProgramManifest.validate` 和 native finalizer。

- 最终隔离 `/tmp/p3-r7-public-dx-build/npusim --isa-v1-selftest` exit0、stdout40,398B：manifest/factory1261、record codec1363、具名Prim75 12、ProgramFormat669、record lowering422、config helper207均pass。`npusim_program_finalizer_selftest`全套exit0，含0x26两核正例及ABI/geometry负例。
- `python3 -m unittest` 四个相关模块26/26 pass，覆盖 source head dX、真实weight shard/rank、FP32 dX拒绝FP16-sized footprint、FP16 weight类型错误、存储复用错误、旧MATMUL反向不能冒名、生产Python固定record正负；MoE时间线旧常数回归由其owner修成按真实记录长度验证，未篡改R7源码。
- 无数值梯度计算：dX最终零值仅是TIMING_PARTIAL的明确种子；没有逐层完整反向、gradient sync/update闭包，不能称Dense/MoE端到端训练通过。
