# P4.4-R1：Dense 推理外存核几何修复与完整双 Fresh 入口

## 目标和源代码变化

修复生产 `run_dense_inference_paged_offload_runtime_canary.py` 的 1×1 单 Die HBM 不足配对：此前前端 Fabric 每 Die 2×2 核，但原生硬件 JSON `x=4`、缺 `y`，NpuSim 默认 4×4 核。单 Die 的 runtime core0 恰好仍在物理 Die0，真实外存流量不因此消失，但 profile 不符合 M1/M2 同一硬件几何合同。现从前端 Fabric 推出 native `x/y=(2,2)`，明确实际 `die.x/y=(1,1)`，并对每个 paged 段在 finalizer 后运行原生 ProgramIO resolver 检查 initialization/probe 数。运行入口对当前进口 Python 源和 finalizer/resolver/NpuSim/simulation 工具在进出口按字节 SHA-256 绑定，漂移时不输出成功收据。

新增 `run_dense_inference_paged_offload_full_fresh.py`：将同一模型、同一固定低 HBM 12288B、resident-only `memory_capacity_exceeded`、paged 成功配对在两个全新目录和独立 Python 进程中完整重物化；每次都重新编译三段有用图、重链 paged manifests、finalizer 六个 source/paged 产物、原生 resolver 三段、ProgramIO、两次 NpuSim replay。上层要求两次源/工具 closure、模型/有用图、hardware、sidecar、linked、NPUP、ProgramIO、实际外存 KV 状态和真实 `[PROGRAM_MEMORY]` 物理 core0 完全一致。单个原入口内的两个 NpuSim 进程只是 native replay，不能冒充两次完整物化；上层入口解决这个具体证据缺口。

## 已完成的实际诊断

新几何/ProgramIO resolver 的第一次完整独立物化诊断在 `/tmp/m2-dense-infer-geometry-fullfresh0`：同模型 resident-only 12288B HBM 因 `memory_capacity_exceeded` 拒绝；paged hardware 实际 `x=2,y=2,die={x:1,y:1}`，三段 paged ProgramIO resolver 均 exit0；两次原生 NpuSim replay exit0，`[PROGRAM_MEMORY] core=0 lsu_issued=65 lsu_completed=65`，65 笔非零 external DMA 完成、12 个 KV ProgramIO probe、version0→1→2→3 的字节 `0→512→640→768`，DMA drain 残留零，makespan 57,996 cycles，`functional=false`。实际 `build-debug-dense-infer-pager/npusim` 工具 ELF 为 `U main`/`T sc_main`，与后来在新 MoE 源中发现的 selftest `main` 污染风险无关。此诊断在加入 source closure 之前执行，因此**不是两次完整独立物化的正式 M2 case**，亦未证明 Dense/MoE 四类八形状或训练 AdamW。下一步在冻结源 worktree 运行新增双完整 Fresh 入口、核对原始四次 NpuSim stdout 与全部产物，之后再给本阶段追加正式结论。
