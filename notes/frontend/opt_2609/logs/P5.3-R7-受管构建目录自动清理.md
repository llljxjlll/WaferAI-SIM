# P5.3-R7：受管构建目录自动清理

日期：2026-09-17。现有 `scripts/frontend_tmp.py` 已对 `/tmp` 下明确受管的实验任务提供容量上限、成功自动删除、失败限时保留与待审阅证据显式释放。本次新增 `scripts/frontend_cmake.py`，将 CMake configure、build 和可选原生/单测检查放在同一个受管任务中，使中间 object、编译临时文件和构建目录共享容量预算；成功后整个任务自动删除，失败默认仅保留 24 小时供诊断。仓库 `.gitignore` 忽略 `/build-managed/`，不会误提交大型构建目录。

日常原生工具构建示例：

```bash
python3 scripts/frontend_tmp.py --root /workspace/build-managed --max-gib 12 run \
  --name native-check -- python3 scripts/frontend_cmake.py \
  --source . --build-dir '{tmp}' --target npusim \
  --jobs 4 --check '{tmp}/npusim' --isa-v1-selftest
```

如需在后续 Fresh 中继续引用构建工具，可将外层 `run` 指定为 `--kind evidence`，审阅并复制需要保留的确切二进制和 SHA 后执行 `release`。失败目录按 `--failure-hours` 由下次同根任务或显式 `prune --apply` 清理；对 `/tmp/waferai-frontend-managed` 与 `/workspace/build-managed` 分别运行 `prune --apply`。两种根目录均需由受管工具创建和标记；不会扫描、删除未标记的工作树或既有冻结证据。

验证：`python3 -m unittest llm.test.frontend.unit.test_frontend_tmp llm.test.frontend.unit.test_frontend_cmake` 共 7 项通过。新测试真实配置、编译并执行一个小型 CMake C++ 目标，验证成功后无构建目录残留、失败任务按零小时 TTL 删除、独立脚本拒绝未受管的 build 路径。
