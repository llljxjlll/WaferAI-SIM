# P5.1-R8：全模型 Dense 推理原生物理 Die 审计与双 Fresh 矩阵驱动

## 本阶段目标与交付

新增 `llm/test/frontend/integration/run_dense_native_mesh_matrix.py`：默认逐个运行 M1 指定的八个形状，每形状在两个新目录、两个独立 Python 进程中调用已实现的完整两层 Dense Prefill→Decode→Decode 生产 runner，并在 NpuSim 结果返回后审核真实物理 Die placement、KV 与 D2D 路由、源代码/工具/硬件/ProgramIO/NPUP绑定。驱动接受明确形状子集，1..10 全形状未来可逐项传入；尚未交付 100 形状的完成收据、断点续跑或四负载主矩阵。输出根目录必须全新，避免旧结果复用冒充 Fresh。

审核器直接读 NpuSim `[PROGRAM_MEMORY]` 中实际发出 LSU 的 runtime core ID，按收据中前端与原生一致的核网格 stride 推出物理 Die。要求它与各段 logical core Die 精确相等，故历史 stride16/前端stride4的假阳性会被拒绝。按 NpuSim 本机约定，列号增大为 `E`、行号增大为 `N`；每个 D2D link 必须相邻、方向合法、data in/out 配对，所有活跃 Die 的物理邻接链路上都有非零流量。三段原生 KV 标记必须各出现一次、`pass=1`、字节递增并等于源签署边界，最终 makespan 唯一且正数。每段 linked/NPUP/ProgramIO 和硬件文件字节必须匹配源签 SHA；两次完整 `source_tool_binding.json` 与结果语义必须一致，只允许实际 wall time/RSS 等非语义计时波动。
