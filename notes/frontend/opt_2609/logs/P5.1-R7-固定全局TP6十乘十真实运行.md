# P5.1-R7 固定全局 TP6 在 10×10 Die Mesh 的真实运行

状态：**固定两层 Dense resident 推理案例双独立 fresh 通过**。此处只计入 M1 的这一推理子族；训练、MoE、超 HBM resident 的推理与训练及完整 M1/M2/M3 验收不由本切片证明。

## 目标与生产入口

在真实 10×10 物理 Die 阵列上运行**同一固定模型**，只激活全局 TP6 的六个 Die，不随物理阵列扩大模型或 TP。钉住提交 `e1c3b5e66d60b505952551fcf76b103e122403ad` 的独立 clean detached worktree `/tmp/m1-fixed-tp6-10x10-freeze`，用原生产入口 `python3 -m llm.test.frontend.integration.run_dense_sequence_runtime_canary --fixed-global-tp6 --mesh-size 10x10`，分别向两个空目录完整重新 materialize、compile、三段 finalizer、三段 ProgramIO resolver、一次真实 `npusim --program-sequence`。两个输出目录分别是 `/tmp/m1-fixed-tp6-10x10-geometry-fixed-fresh0` 和 `/tmp/m1-fixed-tp6-10x10-geometry-fixed-fresh1`，没有复用第一次编译或物化产物。

负载为两层 Dense，`H=48, I=96, NH=6, KVH=6, DH=8`，6 个 request 的 Prefill 6 token 加 Decode 2 步。活动 Die 为 `[0,19,39,59,79,99]`，其余 94 个 Die 是真实硬件配置内的 idle Die。三段依次为 Prefill、Decode1、Decode2，KV 在同一程序序列内延续。

入口 runner SHA-256 为 `ad24f27034e2b9341b75ee2c1bf8e19346d8317c2964d52a87de98d9cb52fe8d`；前端 `minimal_hardware()` fixture 为 `45e34e4c601c1ab7ee395838f9fc971bf24e6ec7cdb58e18f05bd840edd6addb`。仿真配置 SHA-256 为 `337f5bc3f195489e8c6ef8830d83ce709a3e79a434401bd545504bf543420afb`。冻结旧工具及其 SHA-256：finalizer `76a7e61d8b7fd4f49d225d5927d224b6198de9ddf9f1ba397dbe51d314dd25d8`、native ProgramIO resolver `29e8fb38cace40beca5efdfba53ae520f04e71d088ffdc4648a868f7bfb03763`、NpuSim `1090f93f8eb787a117804e33622a9a53dc656b2098ccbb29e1ed612f90bab5cd`。双轮前后 `nm -C` 对该 NpuSim 显示 `U main`、`T sc_main`，其真实 SystemC 入口及两份非空 stdout 排除了隔离自测 `main` 的静默 exit0。

提交 `e1c3b5e6` 将 native 核网格和四边 C2C 索引绑定到生产 Fabric，并公开编译收据中的前端/原生核步长。**本次从两个全新空目录重跑**。修复后 native `hardware.json` 为 `x=2,y=2,die={x:10,y:10}`，N/E/S/W 四边 C2C `idx=0`。三段所有 core binding 均为 `(逻辑Die, runtimeCore, native实际Die)=(0,0,0),(19,76,19),(39,156,39),(59,236,59),(79,316,79),(99,396,99)`，严格通过 `runtime_core_id // 4 == logical_die_id`。这项硬门禁是本案例从“逻辑10×10”升级为“真实物理10×10”的关键。

## 能力边界与后续

本切片证明固定两层 Dense、固定全局 TP6 的 resident 推理能在真实 10×10 矩形 Die Mesh 上执行 Prefill→Decode→Decode，保持跨段 KV，包含 94 个 idle Die 和 18-hop D2D。这是物理程序、内存字节和时序运行证据；没有数值 logits 正确性证明。不能由这一成功推断任意 mesh/任意模型、完整训练链、MoE 或超 HBM 外存训练/推理均已端到端完成。完整两层两步 Dense 训练还须逐源串通 loss→所有反向梯度→FP32 参数梯度→同步→SGD 状态回写，并通过完整模型的严格物理门禁与真实 NpuSim。
