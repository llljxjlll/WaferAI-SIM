# P3.2-R4：Embedding 表和 Norm gamma 的物理 FP32 权重梯度 Timing 原语

## 目标与范围

为完整 Dense 训练物理路径补两个独立具名、strict-only 的内部 C++ Prim：`PrimId72 EMBEDDING_TABLE_WGRAD_TIMING` 与 `PrimId73 NORM_GAMMA_WGRAD_TIMING`。它们声明实际 per-core SRAM BufferABI，输入类型、地址、逐 rank 形状和派生工作量均必须合法。它们只计时，不写数值梯度；跨 TP/DP 的 FP32 参数梯度求和由后续外部 program 明确执行。离散 INT32 token 索引没有数值 dIndex，因此 Embedding 唯一导数是从 FP16 dHidden 按索引 scatter 到 FP32 table gradient。新增 ID 均为 `PrimVisibility::INTERNAL`；外部 Opcode、record schema、finalizer、frontend lowering 和端到端训练运行尚未接入。

## 开发内容

- Embedding strict wire 参数显式绑定 `ROWS`、`LOGICAL_ROWS=ROWS*TP`、完整 vocab、vocab tile 起始与行数、hidden、table SRAM byte address，以及最多 16 个有序 `INDEX00…INDEX15` 的真实 INT32 source trace。未用 trace slot 必须为 0，全部 active token ID 必须落在完整 vocab 内；该 tile 至少有一个选中 index。长 sequence 和大词表通过多个不重叠 tile program 组合。tile 外的 index 仍合法，但该 Prim 不更新这一 tile，交由对应 tile 处理。
- 四份独立 typed BufferABI：INT32 indices、FP16 source table tile、FP16 dHidden/upstream、FP32 table-gradient tile。所有 byte 地址 16B 对齐、范围在 16-bit SRAM 内、各 span 不重叠，FP32 目标按 `VOCAB_ROWS*HIDDEN*4` 精确计算。每个匹配 index 派生真实 source weight row 与 FP32 gradient row 的物理地址；重复 token 会落到同一 FP32 目标，work 明确暴露 `selected_rows`、`unique_weight_rows`、`row_collisions`，按 index-routing 与 FP16 scatter/FP32 read-modify-write 两步计时，保留 typed byte 读写量。
- Norm gamma strict wire 要求 FP16 forward activation 和 FP16 upstream 分离输入、独立 FP32 `(HIDDEN,)` gamma gradient 输出。`ROWS` 是当前 rank 局部行数，`LOGICAL_ROWS=ROWS*TP`，`MODE=0/1` 为 RMS/Layer；按 mode 导出归一化 vector/SFU 与 FP32 按行累加工作，目标 byte 数 `HIDDEN*4`。这与原 `NORM_BACKWARD_TIMING` 的 FP16 dX 输出是不同 physical gradient。
- Prim manifest、factory 和 ISA inventory 增加两个内部 COMPUTE 项；外部旧 opcode/schema 与 `build-debug-final` 没有改动。源文件是 `llm/include/prims/weight_gradient_timing_prims.h`、`llm/src/prims/comp_prims/weight_gradient_timing_prims.cpp`，独立 strict wire 自测是 `llm/src/isa/weight_gradient_timing_prim_selftest.cpp`。

## 真实验证

在独立 `/tmp/p3-r4-weightgrad-build` 配置 Debug 并构建 `npusim`，执行 `npusim --isa-v1-selftest` 完整 EXIT 0：manifest/factory **PASS 1223** checks、旧 record codec **PASS 1266** checks、旧 Norm/Attention backward Prim **PASS 17** checks、新 weight-gradient timing Prim **PASS 21** checks、record lowering **PASS 398** checks，其余 ISA 子项也均通过。首次完整测试发现清单 COMPUTE 计数仍为 43；新增两个内部 COMPUTE 后校正为 45，重新构建并复跑完整 EXIT 0。输出仅留本地 `/tmp/p3-r4-weightgrad-isa.stdout`，不提交 build 或仿真临时产物。

新自测的真实 Embedding 非零索引为 `17,17,65`；vocab tile `[16,24)`、H8，两个 17 分别路由到 FP16 source SRAM byte `272` 与 FP32 target byte `2080`，`selected_rows=2`、`unique_weight_rows=1`、`row_collisions=1`、trace/scatter/FP32 accumulate work `3/16/16`，INT32/FP16/FP32 spans `12/128/48/256` bytes，FP32 read-modify-write `128` bytes。真实 factory 创建和 strict wire round-trip 维持该 trace 与地址；保留位、篡改到 out-of-vocab 的 wire ID、越界 source index、未使用 slot 非零、tile 超 vocab、重叠 SRAM 和 FP32 tile 超 16-bit SRAM 均被拒绝。

Norm gamma 正例 H16、rank ROWS2、TP4，FP16 activation/upstream 各64B、独立 FP32 gamma gradient64B，归一化/累加/SFU work `66/32/2`、FP32 read-modify-write256B；factory、strict wire、taskCore work 均验证。保留位、wire 篡改 logical rows、错误 TP rank 形状、FP32 输出重叠与非法 mode 均被拒绝。

## 后续接入条件

这两个 Prim 目前是内部计时和物理合同；`INDEXxx` 是 strict Prim wire 的 source trace 声明，真正前端 lowering 还需把程序 index Buffer 的 INT32 数据与 trace 一致性证明确立。未来 public record/schema/finalizer 接入需提供这四份 Embedding SRAM 实体、FP32 gradient 的初始化和读改写生命周期，并按 tile 合并；Norm gamma 需提供对应正向 activation/upstream tape 和 FP32 参数梯度跨 rank reduce。这些工作不在本次通过证据内，不能据此声称完整 Dense 训练、数值梯度或任意 mesh 矩阵已经通过。
