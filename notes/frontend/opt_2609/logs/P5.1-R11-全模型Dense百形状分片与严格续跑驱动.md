# P5.1-R11：全模型 Dense 百形状分片与严格续跑驱动

## 目标与开发内容

`run_dense_native_mesh_matrix.py` 从 M1 八形状顺序执行器扩展为 M3 Dense resident inference 的确定性100形状执行底座。`RELEASE_SHAPES` 严格按行优先生成 `1x1..1x10,2x1..10x10` 共100项；`--all-release-shapes --shard-index I --shard-count N` 用原序号取模得到互斥、无遗漏、无重复的分片。保留 `--shapes` 用于小范围实际验收。每个 shape 仍必须两个完整 Fresh，并复用 P5.1-R8 对实际 hardware、物理 Die、邻接D2D、KV、linked/NPUP/ProgramIO与源签的审核。

新增 fail-closed `--resume`。矩阵根目录首次写 `matrix_binding.json`，绑定驱动源码SHA、选中shape的有序全集、分片参数及 finalizer/resolver/NpuSim/simulation 实际字节SHA；已有目录只有在显式 `--resume` 且binding逐字段相等时才可打开。每个已有case不直接信任旧 `case_evidence.json`，而是重新读取两个 Fresh 的原生 stdout、hardware及全部三段产物，重算审核结果并与JSON规范化内容精确比较；缺失、字节漂移、工具漂移、分片变化均拒绝。最终 `matrix_receipt.json` 同时记录binding SHA、应完成与已完成shape，只有完全相等才写 `status=verified`。

## 测试和当前范围

聚焦回归9/9 PASS：100形状集合精确性、7分片并集/互斥/序号归属、非法分片与重复shape拒绝、双Fresh缓存重新打开、缓存收据篡改拒绝，并保留真实物理Die stride、硬件尺寸、横纵方向、非相邻link和NPUP字节漂移负测。`py_compile` 与 `git diff --check` PASS。此前1×2双Fresh真实运行已由相同审核器通过并记录在 P5.1-R10；本阶段没有把未运行的99个shape标成通过。

该驱动只覆盖 Dense resident inference。M3的 Dense offload、Dense训练、MoE推理/训练四类主矩阵仍需对应的完整模型adapter和实际执行；本驱动的100形状定义、分片与续跑机制可复用，但不能用schema或空收据替代1,600次实际运行目标。
