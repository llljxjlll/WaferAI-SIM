# P3.2-R3-B：Dense 训练 CE 反向输入独立 dLoss 与物理 seed

## 实际问题

旧 `P3.2-R2/R3` 原生 CE 反向记录将前向 `CROSS_ENTROPY_FORWARD` 所写的 FP32 逐行 `T0.loss` **数值输出**同时当成 `CROSS_ENTROPY_BACKWARD` 的 FP32 upstream，即误将 loss value 当成 `dLoss`。其 `SRAM_BIND`/地址/物理生命周期虽在 timing 片段级可验证，但**数学训练语义错误**；此前部分文档把它称为 loss gradient 需撤回。现有 `DenseIR0Validator._validate_cross_entropy_backward` 明确要求 `loss_gradient.producer is None`，不能将计算出的 forward loss 作为 CE backward 的 upstream。早期 carrier 保留并标注 `timing surrogate`，全模型 train gate 必须拒绝。

## 改动与物理合同

`passes/dense_training_ce_backward.py` 新增 `build_dense_training_ce_backward_from_loss_gradient(...)`，从原生产前向 CE record 的真实 logits/labels、行数/TP/vocab 派生原生 0x1F，严格拒绝以其 FP32 loss 输出 symbol 冒充独立 upstream。新增 `dense_training_per_row_loss_gradient_seed(rank_rows)` 产每行 FP32 的非零 `1.0` 物理 bytes (`00 00 80 3f`)，仅提供真实 ProgramIO 初始化所需 payload；不从 timing 片段声称实际已运行数值训练。

新独立 `passes/dense_training_ce_seeded_phase.py` 接受 caller 的完整 typed 前向 tape、可校验 CE_BACKWARD GlobalAction、另一个 independently signed `GlobalActionDAG.id`、两份 caller 实际物理 SRAM BufferABI + address/label/region definitions。真实 1×1/两层 Dense 前向所用 logits off3328/128B、labels off3456/16B、forward loss off3520/16B；独立 `BORROWED FP32` per-row `T0.loss_gradient` 在 off3584/16B、`OWNED FP16` logits gradient 在 off3648/128B，均小于该真实 region 容量65536B。种子要在整段程序开始前写入，所以新 dLoss 地址不与任何早于后向的物理 forward write 占同一截面；新 FP16 输出不与须保留的前向 tape 重叠。

native 0x1F 的三个输入严格是**前向原物理 logits、labels 和新 dLoss**，输出新 FP16 logits grad。原 CE 前向 `SRAM_FREE(loss)` 仍留原位；只将原 logits/labels lifetime 从41延长到42、更新ABI ID并把各自 FREE 映射为新 CE backward index7/6。action41 新记录严格是 `SRAM_ALLOC_AT(dLoss)`、`SRAM_ALLOC_AT(logitsgrad)`、`SRAM_BIND(3 inputs /1 output)`、`CROSS_ENTROPY_BACKWARD`、`SRAM_FREE(grad,dLoss,labels,logits)`；所有新 BufferABI/实体地址 relocation 与同一 action prefix/payload/suffix 匹配。返回的 `loss_gradient_seed` 是正确 nonzero ProgramIO 候选，片段目前尚未生成实际 ProgramIO sidecar。

ProgramIO/NpuSim 写入顺序的只读源码审计：`llm/src/frontend/program_io.cpp::ApplyBeforeSimulation` 对 SRAM 使用 `AccessUnit::DebugSeed` 真写 bytes；`RegionTable::AllocateAt` 与 `Sram_lifecycle` 只修改分配表/label，没有清零 payload 的代码。因此预载 off3584 非零 bytes 被后续 ALLOC 覆盖的担忧按**源码推断**不成立；最终仍必须通过带正式 sidecar 的真实 finalizer/ProgramIO/NpuSim 验收，不能仅靠源码断言称 runtime。

## 测试与退出条件

`python3 -m unittest llm.test.frontend.unit.test_dense_training_ce_seeded_phase.DenseSeededCePhaseTest llm.test.frontend.unit.test_dense_training_ce_backward.DenseNativeCeBackwardTest llm.test.frontend.unit.test_dense_training_ce_phase_carrier.DenseTrainingCePhaseCarrierTest -v`：18/18 PASS（新 seeded L2源正/负5/5，native factory6/6，旧surrogate7/7）。新测试在实际链接两层前向上核对三路输入 symbol、原loss FREE保持、仅两条 logits/labels FREE 延迟、Byte `1.0` ×真实4行、BORROWED/OWNED 与FP32/FP16 ABI，且使用真实链接生命周期校验 `_lifecycle_payload_indices` 得到严格 payload `[2,3]`；负例拒绝 seed 与原loss物理write重叠、旧forward loss symbol冒充新source、错误 ownership 或错误每行 ABI 大小。既有 surrogate 测试仍成功，但只证明其旧片段 ABI 验证，不计入完整训练。

**仍未验收 M1/M2 全模型训练**：当前生产 train IR0 validator 一见 CE_BACKWARD 即走 tiny S2-Lite 专用合同（强制 TP1、一 CE、一 LM-head WGRAD、一 SGD，禁止各层backbone梯度），现有两层/TP4 forward 尚无相同图中实际 CE/每层 reverse/optimizer 的真 IR1、Projection、ScheduleSet、GlobalActionDAG.deep validate。新的 dLoss 还需正式 ProgramIO nonzero seed 与 NpuSim 执行、FP16→FP32 明确 cast、norm/attention/RoPE/embedding/residual 等每层实体 gradient 及两步 trainable state store→load。`functional=0` 时不能主张训练数值/收敛；本阶段只交付更正确的物理梯度输入合同。
