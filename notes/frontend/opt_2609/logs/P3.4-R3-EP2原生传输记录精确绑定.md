# P3.4-R3：EP2 源传输与原生 DTE 记录精确绑定

日期：2026-09-18。源码提交 `4179f536`。承接 [R2](P3.4-R2-EP2节点Rank与签名跨Die传输合同.md) 的 rank/路径/字节计划，验证现有 P2 MoE dispatch/return 是否已有可消费的原生传输记录。

## 目标与开发

`MoeEp2RankPlan` 对四笔跨 Die 激活值传输，现在分别绑定已签名 P2 flow 的 SEND、RECV、WAIT action，并要求 WAIT 依赖精确 SEND/RECV；dispatch 的 PACK→SEND→WAIT→expert forward 以及 return 的 expert forward→SEND→WAIT→weighted combine 都必须存在。新增 `build_moe_ep2_native_transport_proof`，从对应 step/layer 的已链接 P2 manifest 查找每笔 action 唯一的 `DTE_SEND`、`DTE_RECV`、`DTE_WAIT`。证明记录保留 fragment、Die、local core、stream 内索引和 action ID，并核对 SEND/RECV 长度与源 tensor 字节数相等。冻结的两层 TP1×EP2 profile 每步有四笔 dispatch/return 传输，每笔 16 B；两个 router 权重的跨 Die 读取不在现有 P2 flow 内，明确等待后续独立的状态搬运实现。

## 测试与结论

用 `scripts/frontend_tmp.py --root /tmp/waferai-frontend-managed --max-gib 1 run` 包装定向单测，`test_moe_full_train_ep2_native_transport` 与 `test_moe_full_train_ep2_rank_plan` 合计 **26 项通过**，覆盖 step0/step1、两层的四个原生 flow、字节与核心归属，以及缺少或伪造记录引用的拒绝。`git diff --cached --check` 通过。

这证明现有 **P2 分量 manifest** 含有匹配的 DTE 记录，尚不表示完整 MoE 训练 program 已链接或在 NpuSim 上执行。下一步需要让普通 IR2 节点按 source rank 选择性投影，接入 Die1→Die0 的 router 权重状态传输，并把 P2 transport、shared forward/backward、expert backward、参数同步和更新串进同一可执行时间线。现有 IR2 验证要求普通节点在整个 execution group 上复制，不能仅修改 rank 字段绕过；M1/M2/M3 的 MoE 训练验收仍未完成。

## 临时与构建目录控制

本轮只运行内存内的源图/manifest 测试，未新建 CMake 构建树或大型 JSON。新测试在 1 GiB 有界受管 scratch 中运行，成功后其任务目录自动删除；阶段末分别对 `/tmp/waferai-frontend-managed` 和 `/workspace/build-managed` 执行 `prune --apply`。build-managed 只剩约 8 KiB 标记文件；受管 tmp 约 74 MiB 为仍需显式 release 的已有 evidence，不按压力自动删除。后续新构建使用 `frontend_tmp.py --root /workspace/build-managed run` 包装 `frontend_cmake.py`，构建、检查与自动清理位于同一受管任务；已有集成脚本依赖的 `build-debug-final` 等树继续保留。整个流程只清理有标记且符合生命周期条件的任务，不触碰 `/tmp` 下的旧冻结证据。
