# P3.4-Q：top1 门控专家 RETURN 物理布局与 0x27/0x28 双输出原生协议

## 目标与源合同

P3.4-P 的新版本只冻结 top1 专家选择，不冻结 router W(H,E)，因此训练必须先保存真实 signed score(k,E)，按 token/expert/home/slot 读正确的专家返回值、动态score加权，反向同时产选中expert的 dScore(k,E) 和送往EXPERT_DGRAD的 dExpert(k,H)。旧生产 `WEIGHTED_COMBINE` 用一个 LOCAL_REDUCE 复制公用 `.output`，各EP expert RETURN若都接收起始0可能覆盖；只为0x27/0x28新增timing操作名、把gate/up参数梯度换成0x25不能救回该数据流。

新增纯NEW `passes/moe_full_train_router_return_protocol.py` 从P3.4-P动态score合同及四真实 step×layer P2 source plan 推导 rank0 四token `expert_index`交错0/1、物理 home=EP0/EP1、同专家slot0/1。每段 expert FP16返回2token×H4=16B，home0本地 group base0、home1远端group base16，整个source-owned `expert_return_tape` 32B按home分段、不用增加P2聚合flow数。P2真实EP1→rank0 `MoeRectFlowStage.COMBINE` assignment.1/3两token逻辑16B且 source/home 精确；本地gate/up/down EXERT_FORWARD down result未来应写同tape前16B，远端DTE_RECV在同BufferABI addend16写后16B。逐token signed score→expert→combined 字节offset依次 `(0,0,0),(6,16,8),(8,8,16),(14,24,24)`；真实route table必须按专家home/slot寻址，而不能按回传顺序直接把返回值当source行。新 `require_physical_return_transport` 独立查实际 BufferABI、ABSOLUTE symbol、DTE_RECV和本地down MATMUL relocation/tensor slice exact；当前生产没有 `.expert_return_tape`，明确FAIL，不能因源几何正测发布runtime。

NEW `schema/moe_router_signed_weight_workload.py` 规定版本化源绑定的0x27 weighted forward读取 score16B + returned expert32B→combined32B；真score加权按P2已有 forward 2kH=32 FLOPs。0x28 score backward读取 **FP16三输入**score16B/return32B/dCombined32B，写**两个独立FP16 OWNED梯度**dScore16B/dExpert32B，不许只产dScore而专家反向仍吃未加权上游；该版本依据 selected expert dot 的2kH与expert上游scale的kH共3kH=48逻辑FLOPs。旧P2 `COMBINE_BACKWARD` 此时声明0 FLOPs，未来必须在**新versioned source/case**把它显式变更为48，不能向旧case偷偷添加正工作量。所有路由组连续不重叠、实际slot gap-free、源token唯一按序、selected expert和home合法、操作dtype和前后源action ID严格校验。`passes/moe_full_train_router_native_protocol.py`把这两份源 workload从真实score+RETURN 逐step/layer重签为四组带稳定ID pair，确认0x28的两种梯度分别同score、expert返回字节对齐。
