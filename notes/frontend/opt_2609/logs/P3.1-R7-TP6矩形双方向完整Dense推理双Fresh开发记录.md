## 目标与具体开发

不改变模型，在完整 2×3 与 3×2 物理矩形上把同一 FP16、V128/H48/I96/L2/NH6/KVH6/DH8 两层 Dense 负载分配到六个 Die、TP6。六个 request 均 Prefill6，然后各执行两次 Decode1；模型输入为静态 token trace、timing_execution=true，不声明 logits 或训练梯度的数值功能正确性。生产编译仍通过 compile_dense_e2e_sequence_runtime_profiles、既有 IR/lowering/linker、finalizer、ProgramIO 和 NpuSim；三段在同一模拟实例连续执行，末段才终止。两方向的模型、逻辑图每个 op/step/layer 计数及 per-Die HBM 1 GiB 完全一致。

运行器在启动与模拟完成时分别对实际进口的 llm/frontend/wafer_frontend 与 llm/test/frontend Python 文件及四个实际执行工具逐文件 SHA-256 签名；若启动时已进口的源码或工具字节发生漂移，即使 backend 输出成功也拒绝 verified。只有真实三段 marker、独立 KV 公式、一次 drain、一次 SIM_RESULT 及工具绑定同时成立才写 source_tool_binding.json，编译收据先标 not_measured，运行后改 verified。绑定包含生产输入、逐段 linked manifest、NPUP、ProgramIO 和 hardware 的 SHA-256。

## 四次独立真实执行

每个方向从两个空目录各自重新物化、编译三段、执行三次真实 finalizer、构造并验证三份 typed ProgramIO，再各自执行原生 resolver 和一次真实 NpuSim，完全没有复用前次 NPUP、manifest、sidecar 或模拟进程。执行收据：

| 物理 mesh | fresh0 输出目录 | fresh1 输出目录 | 两次模拟 makespan cycles | 全流程 wall seconds |
|---|---|---|---:|---|
| 2×3 | /tmp/m1-tp6-bound-2x3-fresh0 | /tmp/m1-tp6-bound-2x3-fresh1 | 142,995 / 142,995 | 398.831 / 430.573 |
| 3×2 | /tmp/m1-tp6-bound-3x2-fresh0 | /tmp/m1-tp6-bound-3x2-fresh1 | 146,328 / 146,328 | 398.000 / 433.589 |

四次均 EXIT 0，收据 runtime_status=verified。每种方向两次的 source request SHA、workload case ID、sequence digest、三段 linked manifest/NPUP/ProgramIO SHA、hardware SHA、启动时 288 个进口 Python 文件逐文件 SHA 及四工具 SHA 完全相等；跨不同方向的 case/sequence 随物理映射改变，不把不同映射强行当成同一产物。四工具共同 SHA：finalizer 76a7e61d8b7fd4f49d225d5927d224b6198de9ddf9f1ba397dbe51d314dd25d8；NpuSim 1090f93f8eb787a117804e33622a9a53dc656b2098ccbb29e1ed612f90bab5cd；ProgramIO resolver 29e8fb38cace40beca5efdfba53ae520f04e71d088ffdc4648a868f7bfb03763；simulation config 337f5bc3f195489e8c6ef8830d83ce709a3e79a434401bd545504bf543420afb。

每次模拟均按 0、1、2 完成三段，final 标记分别 0、0、1；一次资源 drain 为 segments=3 one_shot=1、一次 SIM_RESULT。基于实际模型 KVH6、DH8、L2 和六 request 的 FP16 独立公式，KV 保留边界为 13,824→16,128→18,432 字节，各段 backend digest 与 checksum pass=1；两方向、两次运行在同一步的 KV digest 相同。各段六 Die 的 typed ProgramIO 经原生 resolver 校验 276 initialization / 6 probe；物理 SRAM 配置真实 131,072 字节、对齐 32 字节，uint16 compute wire 地址预算 65,536 字节。聚焦 Python 回归 30/30 PASS、原生 ProgramIO 自测 8/8 PASS。同版运行器还在各自独立的新目录 /tmp/p3-r7-old-1x1-runner-regression、/tmp/p3-r7-old-2x2-runner-regression 完成旧 1×1、2×2 各一次完整生产编译、原生解析和真实 NpuSim EXIT 0，验证新硬件 preflight 和 KV 独立公式不破坏旧入口；这两种旧形状只有一次此次版本的执行，不能充当发布主矩阵的双独立执行。

## 范围及下一步

这四次只验一个固定 resident Dense 推理模型的 2×3、3×2 TP6；之前的 1×1、1×4、4×1、2×2 负载不因本次绑定自动成为同一发布 source/tool 版本的八形状主矩阵。当前推理为静态 trace 的真实时序执行，logits functional=false。继续按计划补两层 Dense full backward/loss/两步 SGD 与 MoE 推理/训练，以及 3×3、10×10 主形状；之后分别在真实低 HBM 下验证四类 external restore 和 AdamW/checkpoint，最后完成 100 形状及规模扩展。任何 family 缺失均不能称 M1/M2/M3 完成。
