# P3.2-R29：Dense 训练 DP2 跨副本 N5→N6.5 统一链接

## 目标与真实范围

对固定两层、两步 SGD Dense TRAIN 的 2×2 DieMesh（TP2×DP2）构建单份源图、两份真实放置副本和一个原生时间线。60 个真实 FP32 WGRAD 同步实例分别从本地 WGRAD 出发，按真实跨 Die SEND/RECV、WAIT、root FP32 SUM、反向广播 WAIT 再连接到所属副本 SGD；不得以普通 COMP、本地 TP 集合或占位时间片代替。

本记录只声明已通过源图、N5 物理调度、两副本 N6 原生片段和 N6.5 单 manifest 严格链接。C++ finalizer、ProgramIO、NpuSim 尚未通过，因此 **不声明 2×2 端到端训练或双 Fresh 已完成**。

## 开发内容

- 官方 N5 投影重建 N4 `DenseDP2RoutePlan`，在每个副本的实际 Die 上绑定 480 个精确源任务（每梯度 root 5 个、child 3 个），包含跨副本 flow route、SRAM 使用、WGRAD 生产端和 SGD 消费端。调度及 GlobalActionDAG 接受的仅是 source-backed DP 侧写，其他 collective 路径维持原强校验。DP1 的空侧写不改变原 artifact identity。
- `lowering/dense_dp_sync.py` 对每个梯度的 N4 `RankProgram`、N5 源任务和 GlobalAction 逐一检查，按实际多 core 日程生成 DTE_ISSUE/WAIT、DTE_SEND/RECV、FP32 LOCAL_REDUCE。所有 RECV/WAIT 必须一对一共享真实 token；每个片段精确认领源动作。`passes/lower_program.py` 将 DP 梯度单独编组，原有 TP standalone 计划不承载这些动作。
- `lowering/linker.py` 先从两份严格验证的副本源动作和原生片段统一推导 DTE FSM、peer core 和 token，再对局部 manifest 保留结构/状态/ABI 核验，最终只允许真正共享的 DP flow FSM 跨副本同名。新增的 `dense_dp2_route_plan` manifest 输入 digest 锚定真实 N4 路由源；源程序严格重建完整 linked manifest。
- `schema/artifact_manifest.py` 仅准许正且 4 字节对齐、源自 DP collective 精确 region 的 FP32 SUM 记录，要求发布的 Train manifest 有唯一 DP route trust anchor、两个源 DAG 各有相同非零数量的 DP 原生片段；链接器内部局部中间产物仍接受强类型结构核验。
