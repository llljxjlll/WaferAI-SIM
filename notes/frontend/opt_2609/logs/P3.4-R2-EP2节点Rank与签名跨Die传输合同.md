# P3.4-R2：EP2 节点 Rank 与签名跨 Die 传输合同

日期：2026-09-18。源码提交 `c67deb03`。承接 [R1](P3.4-R1-EP2共享反向源与物理OwnerRank.md) 已验证的两层、两步 TP1×EP2 前向及共享反向候选，建立下阶段真实 SEND/RECV lowering 必须消费的 rank/传输合同。

## 目标与开发

现有普通 IR2 projector 对整个 EP group 扩展每个计算节点，无法区分 rank0 的共享主干与 rank1 的 expert；直接放宽 2D group 的 SRAM 调度检查会让共享计算在缺少参数 home 的 Die1 上错误执行。新增 `build_moe_ep2_rank_plan` 从原 IR0/IR1、EP owner HBM binding、物理双向 route 和已签名的 MoE P2 sequence 推导每个节点的计算 rank，以及所有跨 Die 值的来源、消费者、方向、路径和真实字节数。

在现有冻结两层模型中，38 个节点只有每层 expert1 位于 rank1；其余共享主干、router、dispatch、combine 及已实现的 CE/head/共享反向位于 rank0。每层精确需要三笔跨 Die 值：rank1 router 权重→rank0 router、rank0 `dispatch1`→rank1 expert1、rank1 expert1 输出→rank0 combine。两层合计六笔；小模型每笔 16 B。四笔 dispatch/return 与源 P2 sequence 的精确 flow ID、方向和字节数绑定；两笔 router 权重读取与 rank1 StateAccess/HBM home 绑定，等待显式 state transport。整个计划的来源 IR1 ID 与 P2 sequence ID 均需匹配。

## 测试与边界

`test_moe_full_train_ep2_rank_plan` 完整执行 13 项，通过 step0/step1 的 38 节点、六笔传输、双向物理路径、四个 P2 flow 对照；改动传输字节、删去返回值或替换 flow ID 的计划被拒绝。随后泛化实例 ID 而保留源模型约束，定向两步测试再次通过。`git diff --check` 通过。

这项交付是**来源校验过的传输计划，不是原生传输执行**。尚需把选择的 rank 接入 IR2，并把四笔 P2 dispatch/return 与两笔参数读取转为真实 SEND/RECV/状态搬运和完成事件；之后再完成 EP2 combine/expert 反向、参数同步、SGD、双步 ProgramIO 与 NpuSim Fresh。R1 观察到的 2D EP group 调度拒绝仍是正确门禁，不能据此宣称 M1 或 M2 MoE 训练通过。
