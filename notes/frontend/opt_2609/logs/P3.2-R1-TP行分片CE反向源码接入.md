# P3.2-R1：TP 行分片 CE 反向源码接入

日期：2026-09-15。对应计划 P3.2 完整 Dense 训练中的 loss→backward 前置合同；本记录仅是 **IR0 源码的一段真实依赖**，没有 production IR1、NPUP 或 NpuSim 运行，不能计入 M1 训练主 case。

## 目标与实现

已有两层 Dense TRAIN forward 包含独立的 CE-forward，`CrossEntropyForwardWorkload` 在 TP>1 时把 token 行按 TP 分片、词表轴完整复制，`reduction=NONE`。但 `full_dense_training_ce_ir0.py` 先前一律以 TP1 门禁拒绝将真实 CE-forward logits/labels 接到 CE-backward，连 TP4 行分片的合法 per-row 梯度来源都无法在源码图表达。

现在沿用现有 forward graph validator 对完整词表、rank-local row、FP16 logits/INT32 labels/FP32 loss 的严格检查，只解除 TP1 专属门禁。新增的 CE-backward node 对物理 forward 的 logits 和 labels 建显式数据依赖，对另一个 **独立 FP32 dLoss/dLoss 输入** 建输入依赖，输出 rank-local FP16 logits gradient。`reduction=NONE`，所以每 rank 的 dLoss 形状等于自己的 token 行数，未把 forward loss 数值误当 dLoss，也未暗中引入跨 TP 的词表 softmax。若训练选择词表轴分片或已规约 CE，此现有 workload validator 仍拒绝，不受本次改动放行。

## 验证

`PYTHONPATH=/workspace:/workspace/llm/test/frontend/unit python3 -m unittest llm.test.frontend.unit.test_full_dense_training_ce_ir0` **5/5 PASS**。新增 TP4×DP1 case 的 source 是 34 个 forward nodes + 1 个 backward node、logical logits `(4,32)`/rank logits `(1,32)`、dLoss logical `(4,)`/rank `(1,)`；TP2×DP2 source 的 logical logits `(2,16)`/rank `(1,16)` 和独立 rank dLoss `(1,)` 同样通过完整 IR0 graph.validate。原 TP1 正/负例仍通过，loss value 不可替代独立 dLoss 的负例仍有效。

## 未完成与后续
