# P2.4-R2：六 Die SRAM 生命周期与原生 ProgramIO 一致性

> **后续校正（2026-09-15）**：此记录引用的六Die Dense sequence native硬件与编译Fabric核几何不一致；逐core SRAM生命周期及ProgramIO原始观察保留，但不能由它推断六个目标物理Die都被正确执行/路由。详见[P1.1-R1 核几何审计](P1.1-R1-前端原生核几何失配与矩形物理路由修正.md)。

日期：2026-09-15。对应 P2.4、P2.7、P3.1；这是 resident Dense 推理的物理 SRAM 切片，尚未完成 P2 整阶段及 M1。

## 目标与开发内容

用同一固定 FP16 两层 Dense 模型在 2×3 与 3×2、TP6、全部六 Die 活跃的三段 Prefill→Decode→Decode 中验证 SRAM 地址、真实容量和 ProgramIO 的生命周期一致性。模型 H48/I96/NH6/KVH6/DH8，六个 request 各 Prefill6 后两次 Decode1；每 Die HBM 为 1 GiB。

- 原有逐次追加 SRAM 分配使部分 compute relocation 超过原生 uint16 绝对地址。NaiveIntraDiePolicy 新增可选 65,536 字节 wire 地址预算，在物理 SRAM 容量内按真实 lifetime first-fit 寻找地址；ProgramIO 在任务开始前初始化的 BORROWED 输入从时刻零保护到末次读取。默认策略及旧产物身份保持不变，超 live set 或无法在地址宽度内定位时编译期拒绝。
- 固定 SRAM_ALLOC_AT 同时遵守物理硬件配置的 allocation_alignment_bytes。六 Die profile 声明真实 131,072 字节 SRAM、32 字节最小对齐，编译 profile 与 NpuSim hardware.json 相同；Decode 的 96 字节 reduce shard 不满足旧 64 字节 profile，若仍用该 profile，原生后端实际拒绝。没有放宽硬件容量或隐式绕过分配器。
- Python ProgramIoContract 与 C++ ParseAndResolve 一起允许 manifest_linker 的最终 OWNED SRAM 探针使用早先已结束的重叠区间；要求该 probe 为对应 runtime core 最后存活的 allocation，且每个重叠 allocation 在 probe 的 producer 写入前已经结束。较早 live 或非终端 probe 继续拒绝。
- Native ProgramIO 硬件自测入口增加显式期望容量和对齐字段，保留旧参数兼容；物理 SRAM 失败打印 label、offset、base 和 effective alignment 以便准确诊断。

## 原生证据和回归

从空目录分别独立跑 2×3、3×2 各两次完整生产编译→finalizer→typed ProgramIO→原生 resolver→真实 NpuSim。输出依次位于 /tmp/m1-tp6-bound-2x3-fresh0、/tmp/m1-tp6-bound-2x3-fresh1、/tmp/m1-tp6-bound-3x2-fresh0、/tmp/m1-tp6-bound-3x2-fresh1；四次 runtime_status 均由成功收据派生为 verified。每段真实 linked BufferABI 的最高 SRAM offset+size 为 Prefill 35,936、Decode1/2 均 12,832 字节，均小于 65,536 字节 wire 预算；真实硬件 preflight 输出 region=sram capacity_bytes=131072 alignment_bytes=32 region_count=1。各段原生 resolver 均验证 276 项 initialization 和六项 terminal probe；NpuSim 在各段装载时再次原生解析 ProgramIO、linked manifest 与 NPUP。

负例：旧 65,536 字节物理 SRAM 的较大 live staging 编译期拒绝；仅将物理 SRAM 提至 131,072 字节、保持旧无复用地址顺序，真实 finalizer 的 uint16 relocation 拒绝；若保持旧 64 字节硬件分配对齐，真实 Decode 的固定地址分配失败。新地址策略没有改动规格定义的 uint16 指令字段，这些失败仍必须可诊断。P2.6 local HBM 不足与 remote placement 未在本切片完成。

聚焦 Python SRAM 策略、固定模型和 ProgramIO 回归 30/30 PASS；冻结构建中的原生 ProgramIO 自测 8/8 PASS；git diff --check PASS。成功样本使用 32 字节的公开物理 profile，只证明此配置可运行，不意味着任意 SRAM 对齐/大小都适用；训练、MoE、超 HBM 均不由本切片提升能力状态。
