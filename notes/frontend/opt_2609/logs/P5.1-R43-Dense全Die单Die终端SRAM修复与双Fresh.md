# P5.1-R43：Dense 全 Die 单 Die终端 SRAM 修复与双 Fresh

日期：2026-09-17。先前 [P5.1-R41](P5.1-R41-Dense全Die单Die输出生存期与重启续跑.md) 的冻结 1×1 Prefill 已完成计算，但 `P0.logits` ProgramIO 比对 `exact=1, valid=0`，不能进入 Decode，也不能发布全 Die 100 形状。

## 根因与源码改动

真实链接 manifest 中，`P0.logits` 在物理 Core 0 的 SRAM `[4192,4448)`，与三个较早 staging 值的物理区间相交。`wire_address_limit_bytes=65536` 的 Naive allocator 只按普通动作生命周期重用字节；ProgramIO 的 timing 输出却在仿真前预载零值，且 GEMM timing-only 不会把尚未写过的字节变成 valid。由于该终端 root 被识别为复用，ProgramIO 不会预载它，最终零值 SHA 恰巧相同但部分 valid 位为零。原来的注释把现象称作“末端释放”尚不足以解释，真正的物理缺口是终端字节在 earlier staging 复用后没有完整的有效 payload。

源码提交 `85359f91`：对于启用 wire 地址上限的真实终端 owned BufferABI，分配器按与 ProgramIO 一致的 IR1 无消费者集合识别终端，将它的物理字节从程序入口起保护。由于 buffer 分配顺序与动作顺序不同，保护是双向的：先分配的终端阻止后来分配的早期 staging 值复用，后分配的终端也避开全部已有值。没有扩大 SRAM 硬件容量或变更算子图；无合法空间时仍按真实容量失败。新真实编译中 `P0.logits` 地址保持 `[4192,4448)`，与其它 owned root 的相交集合从三个减少为零。

受管临时目录增加 `--dramsys-root`，仅在 job 根创建指向冻结 DRAMSys 配置的 symlink，使 `{tmp}/fresh` 的原生 cwd 能按 `../DRAMSys/configs` 解析；symlink 和 job 随任务清理，冻结配置不被修改。最初两次诊断中的一份因缺少该相对路径在配置阶段中止，另一份因当时只单向保护地址仍在 ProgramIO 阶段失败；定位后均已显式释放，不能计为通过。

## 实际原生验证

使用 Git clean detached worktree `/tmp/p5-dense-terminal-frozen-85359f91`、冻结 NpuSim/finalizer/resolver 和 8 GiB 受管临时任务，从源码独立生成两份全新的 1×1 all-Die-scaled 两层 Dense Prefill→Decode→Decode 程序。两次均在真实 NpuSim 中完成三段并通过 ProgramIO 和 KV 增长核验。冻结审计器重开每份原件，核对全 Die 活跃、实际 Core/Die 路由、三段 NPUP/ProgramIO/硬件 SHA、309 份实际导入 Python 源码与四个原生工具/配置 SHA。两份 `makespan_cycles=17135`，各段 KV bytes `[128,256,384]`。机器可读 [单形状双 Fresh 收据](P5.1-R43-Dense全Die单Die终端SRAM双Fresh收据.json) 标记 `verified_single_shape`，不冒充 M3 100 形状完成。

回归：`test_dense_terminal_sram_lifetime` 用真实 1×1 三段生产编译断言所有 terminal 不与同 Core/region 的任何其它 root 相交；Naive 旧复用、受管临时/DRAMSys、受管 CMake 测试共 12 项通过，矩阵合同与 Naive 基础测试另 28 项通过。GEMM 仍是 timing-only，这些零值 probe 仅证明其 timing payload、生命周期与物理运行合同，不证明数值推理。

## 后续边界与空间

之前全 Die 100 形状分片的冻结源码/工具绑定到旧版本，不可把本修复下的 1×1 Fresh 直接加入旧分片。全 Die 100 形状须重新按同一冻结版本跑完四分片并执行统一审计；在此之前只发布 1×1 修复范围。两份通过的受管 Fresh 暂留供审阅；前置诊断目录已释放。新 frozen worktree 中七份历史大 JSON 经 SHA 核对与旧冻结树硬链接，减少约 275 MiB；当前 `/workspace/build-managed` 标记根无构建缓存，后续 CMake 任务成功后自动删除。
