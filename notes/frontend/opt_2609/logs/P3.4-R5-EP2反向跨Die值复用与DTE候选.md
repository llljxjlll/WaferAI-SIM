# P3.4-R5：EP2 反向跨 Die 值复用与 DTE 候选

日期：2026-09-18。源码提交 `cb728dcc`。承接 [R4](P3.4-R4-EP2双专家反向源与物理IR1.md) 的 41 节点官方物理 IR1，从每个真实 TensorValue 的 producer、consumer、HBM owner 和物理 route 推导 layer1 反向加入后的跨 Die 值使用。

## 目标与开发

新增 `MoeEp2ReverseRankPlan`，对 41 个节点确定 rank，并把远端消费者按 `(value, destination rank)` 合并成唯一物理 payload。两步各有 **7 份 payload、9 个远端消费者**：原六份包括两层各自的 router 权重、dispatch 和 expert return；新增 `dExpert1` 从 Die0 到 Die1。layer1 的 `dispatch1` 同时供 Die1 expert forward/backward，`expert1.output` 同时供 Die0 forward combine/combine backward，因此原 P2 的两笔传输各服务两个消费者，不能重复发送并冒充新的梯度流。plan 对每份真实形状/字节、方向、HBM home、Die 路径与源节点作精确校验；原四笔 dispatch/return 保留已经签名的 SEND/RECV/WAIT 来源。

源图 `dExpert1` 是 16 B。生产 P2 layer1 确实已有 rank0→rank1、覆盖 expert1 两个 token 的 16 B `BACKWARD_GRADIENT` flow；新增候选绑定检查 flow assignment、SEND/RECV/WAIT action 及 linked manifest 中各自唯一的原生 DTE 记录和长度。它是**物理可复用候选**：当前默认 P2 SEND 仍没有与新 IR0 dExpert producer 严格绑定，不能把该记录列为完成的端到端反向传输。计划把来源已绑定的 flow 与候选 flow 分开保存；两笔 router 权重跨 Die 状态读取也继续显示未绑定。

## 测试与结论

真实 step0/step1 源图/物理 IR1/P2 linked manifest 定向回归 **14 项通过**。校验 7 payload/9 consumers、dispatch 和 return 的双消费者复用、`dExpert1` 的 0→1 方向与 16 B 长度、原生 `DTE_SEND`/`DTE_RECV`/`DTE_WAIT` 精确记录及伪造记录索引拒绝；`git diff --cached --check` 通过。第一次断言少计了 dispatch 的反向复用，按真实源图修正为 9 个远端消费者后复测通过。

下一开发门禁是让前置 score-weight backward 的真实 dExpert 输出、该 P2 `BACKWARD_GRADIENT` SEND 的读 buffer、Die1 RECV 与 expert backward 的输入在同一时间线中由官方 BufferABI/依赖连接；并完成 router 权重状态传输。现有候选不能替代 EP2 原生 0x28、完整多 expert 反向、参数同步/SGD、双步 ProgramIO 或 NpuSim Fresh，M1/M2/M3 的 MoE 训练验收仍未完成。
