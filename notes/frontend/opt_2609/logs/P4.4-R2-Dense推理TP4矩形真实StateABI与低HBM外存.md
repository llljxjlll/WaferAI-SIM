# P4.4-R2：Dense 推理 TP4 矩形真实 StateABI 与低 HBM 外存

## 本轮源码合同

本轮把既有 1×1 Dense inference blocking offload 扩到真实 TP4 矩形，正式案例固定为 2×2 Die、每 Die 2×2 core、两层 `llama_dense`（H32、I64、4 attention heads、2 KV heads、FP16）、`prefill_tokens=4, decode_steps=2`。`dense_inference_rect_physical_source.py` 不从逻辑参数聚合量猜物理页，而是逐段读取 production linked manifest 的真实 LSU `StateABI`：每段 4 Die 各 15 个 parameter ABI 和 4 个 KV ABI，共 76 个；每 Die parameter 物理字节 26,944B，最终四个 KV capacity page 共 1,536B。三个段 parameter 身份稳定，KV extent 严格按 256→320→384B 增长；跨三段去重后共有 108 个 ABI 身份（60 个稳定 parameter，加 48 个分段 KV 版本）。76 个物理 declaration 各自拥有 external allocation，总权威容量 113,920B。

同模型 resident-only 仍用同一组每 Die 12,288B `MemoryTierCapacity` 重新物化并必须得到 `memory_capacity_exceeded`。P3 逻辑 rank-local parameter 聚合量是 14,416B/Die；production linked physical parameter 切片量是 26,944B/Die。两者分别是前端逻辑物化与真实链接物理来源，日志不把它们混写成一个容量数字。

`dense_inference_rect_paged_runtime.py` 保留每条有用 record、outer `RegionManifest`、inner `CommandFragment`、stream、binding 和 program symbol 身份，仅把每 Die parameter 分时映射到本地 `[1600,9792)` 的 8,192B weight slot，把四个 KV capacity page 固定在 `[9792,11328)`。它签署四个 runtime core `0,4,8,12` 的 260 个 LSU/DMA gate：每段每 Die 15 次 weight restore，Prefill/Decode 每 Die分别 0/4 次 KV restore，三段每 Die各 4 次 KV writeback。总 external read/write oracle 是 334,592/15,360B。

外存 fabric 遵守 schema 的“一 external capacity 一 service link”约束：单一 `host:0` 131,072B authority 从 Die0 ingress，经 `(0)`、`(0,1)`、`(0,2)`、`(0,1,3)` 四条 connection 到 Die0..3 的独立 12,288B HBM home。native hardware 的全局 home base 直接绑定真实 ABI 地址域 `0/1/2/3 GiB`；每个 backend 和 home window 仍恰好 12,288B。`stack_interleave_bytes=4096` 使这些 base/size 合法对齐，`allow_gaps=true` 只允许四个有界 home 之间的地址空洞，不扩大任何 home。运行收据同时记录 logical capacity 12,288B、native aligned window 12,288B、interleave 4,096B 和实际 paged peak end 11,328B。

这里的 native paged slot 是 production StateABI 执行地址合同。generic external-offload materialization 的 HBM memory-plan peak end 是 4,672B/Die；两者用于不同层次的证明，不能把 4,672B 写成 native slot 的不重叠前缀，也不能用对齐后的地址路由窗口冒充更大可用容量。

## 严格负例和诊断

第一次真实 2×2 production compile 目录未生成 native 成功收据：runtime builder 只用 outer region id 登记 record，而 linked stream 使用 inner command-fragment id，第一条真实引用即 fail-closed。修复后 record map 同时接受已签名 outer/inner identity，并新增冲突负测；保留的 Prefill/Decode/Decode 真 2×2 manifests 的全部引用闭合，记录索引项为 2,124/2,140/2,140。

第二次从零 production compile 在 `/tmp/p4-dense-rect-2x2-native-r2` 完成 physical source、76 spans/260 events sidecar、source/paged finalizer 和三段 ProgramIO resolver，随后 native 配置因默认 1MiB stack interleave 不接受 12,288B home range 而 fail-closed。保留该失败，不计作 native PASS。把 copied hardware 改为 4KiB interleave 后又依次暴露 NUMA gap 必须显式允许，以及 native parser 错把 KV 稳定 384B capacity span 要求等于每段 256/320/384B version extent；现已分别按显式 gap 和“capacity 包含、版本 extent 逐段精确”修正。四个 Die 在首个 LSU gate 同时提交时，旧的单 ingress `queue_depth/max_outstanding=2/2` 继续按合同拒绝第三个请求；矩形生产 builder、C++ 严格解析和 canary 现统一签署 `4/4`，仍保持一个 link 和四条逐 Die route。

修复后的 r2 产物只用于秒级原生诊断，并已连续两次真实 NpuSim `exit 0`：260 个 DMA 全部提交/完成，external read/write 为 334,592/15,360B，48 个 KV probe，版本字节为 0→4,096→5,120→6,144，pending/dirty/pinned 全零；runtime core 为 0/4/8/12，物理 Die 为 0/1/2/3，八条相邻 D2D link 收发平衡，router/D2D residual 为零且 data/control credit 平衡。由于这两次使用公共任务仍在变化期间的混合增量 binary，严格不计正式 Fresh。

原生 `ExternalMemoryRuntimeBridge` 组件负测已把 HBM capacity 固定为 12,288B：地址 12,224 的 64B transfer 恰好到边界成功；相同起点的 128B transfer 多出一个 64B channel block，在 admission 前同步拒绝且 submitted count 不变。该测试走 pager 使用的同一 `ValidateRange` 路径。
