# P3.3-R1：MoE 完整推理矩形编译与 Fabric 核绑定

日期：2026-09-16

## 目标

移除 MoE Prefill → Decode → Decode 完整模型编译链对 `1x2`、两个 rank 和原生每 Die 16 核步长的写死，为后续 M1/M3 矩形实跑提供可审计的 manifest。该阶段只验收生产编译与链接合同，不以编译成功替代 NpuSim 运行验收。

## 开发内容

1. `compile_moe_full_model_inference_sequence()` 接受完整 row-major mesh，严格要求 EP、expert 数和 active Die 覆盖该 mesh，并核对 Fabric 与 HBM address space 的 Die 集合。
2. 从传入 `PhysicalFabric` 的每个 Die `local_core_id=0` 读取 `runtime_core_id`，经 `compile_moe_sequence()` 传给 Flexible-MoE production lowerer。默认旧入口仍保留既有绑定，完整模型入口不再假定 `rank * 16`。
3. full-model linker 从每个 MoE unit 的实际 core stream 集合构造 `by_core` 与 `core_bindings`，不再只复制 rank 1。
4. 某个 expert 在某个静态 Decode trace 中没有 token 时，保留该 rank 的 state stream，省略空的 compute fragment stream，并同步收缩 compute fragment 的 BufferABI core 集合。没有通过增加 token 或改变原始工作量来绕开零工作 rank。
5. `1x1` 没有远端 flow 时，full-model schema 不再强制要求 `DTE_SEND/DTE_RECV`；embedding、attention、local reduce、MoE/head matmul 仍为必需记录。
6. MoE 测试 fixture 增加 `rows/columns` 参数，以同一物化入口生成 1×1、1×2、1×3 请求和逐 Die HBM capacity。

## 测试

- `1x3`：两层、Prefill + 两次 Decode 的完整编译通过；三个 segment 的 executable manifest 均绑定 logical Die `0/1/2`，runtime core 为 Fabric 实际的 `0/4/8`。Decode 中 expert 2 零 token 的阶段没有空 fragment stream。
- `1x1`：同一完整序列编译通过；每段只绑定 runtime core `0`，且 manifest 不包含远端 DTE send/recv。
- 修改文件完成 `py_compile` 与 `git diff --check`。

## 范围说明

当前 MoE production 基线仍要求 `EP == expert_count == mesh rank count`，因此本阶段证明的是 mesh-scaled 全 EP 编译链，并未完成计划要求的“固定模型与物理阵列解耦”。`1x1`、`1x3` 也只有编译/链接证据；只有完成独立 materialize/finalize/ProgramIO/NpuSim 双运行并通过物理 Die、链路、KV 和 drain 审计后，才能计入 M1 MoE inference 的正式 case。
