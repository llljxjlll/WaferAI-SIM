# P1.2/P1.3-R2：3×3 空闲行 TP6 固定模型双 Fresh 真实运行

日期：2026-09-15。对应计划中完整物理矩形阵列内选择计算参与子集、空闲 Die 仍参与路由的能力。本记录解除 [R1 生产编译阻断](P1.2-R1-3x3空闲行TP6固定模型生产编译阻断记录.md) 中同一 case 的前置拒绝；验收范围是 **Dense 推理固定模型补充映射**，不是 M1 的四类主矩阵或 M3 全形状验收。

## 目标、输入与实现

沿用 2×3/3×2 已真实双跑的同一个 FP16 两层 Llama Dense 模型：V128/H48/I96/L2/NH6/KVH6/DH8、TP6，六请求 Prefill6→Decode1→Decode1。物理 Fabric 是完整 3×3、9 Die；logical rank 0..5 显式放在 Die `(0,1,2,6,7,8)`，Die `(3,4,5)` 无计算 core stream，仍保留物理路由与 HBM 地址空间。固定模型、96 个逻辑操作及 KV 生命周期均未为 3×3 复制或缩减。case ID `workload_case_6f58db3b468e72e8`。

本次只修改以下六条已有源码/测试路径，阶段日志另存本文件：

- `llm/frontend/wafer_frontend/passes/dense_compile_sequence.py`：生产入口核对显式 active Die 与物化放置一致，保留完整 9 Die Fabric/HBM；三段 legacy spec 在非全行列映射时生成实际 `EXPLICIT` TP group，mesh ref 精确为 `{instance.id}.mesh.tp`。原有全活跃 row-major `COMPACT` 路径保持原构图方式；模板若自带冲突的 EXPLICIT group 直接拒绝。
- `llm/frontend/wafer_frontend/compiler.py`：RectMesh 全工作负载入口在 `TP<physical Die` 时只接收唯一、长度恰为 TP、Die ID 落在完整 Fabric 内的 EXPLICIT group；部分 TP 的 COMPACT、TP 超过物理 Die 和越界 Die 继续拒绝。
- `llm/frontend/wafer_frontend/legacy_dense_backend.py`：统一兼容性判断只有在 partial mapping 真包含上述 EXPLICIT group 时才可宣称与 legacy static profile 适配，避免默认 COMPACT 错放。
- `llm/test/frontend/integration/run_dense_sequence_runtime_canary.py`：生产编译后逐段检查 linked manifest 的 core-stream Die 集合恰等于物化 active 集合，收据记录 active/idle/实际 core 身份；空闲行不允许幽灵计算。
- `llm/test/frontend/unit/test_dense_six_die_fixed_model.py` 与 `llm/test/frontend/unit/test_rect_mesh_compiler.py`：同模型拓扑、三段显式放置、X-first 跨空闲行路径、部分 COMPACT/越界/冲突 group 负例，以及原全行列门禁语义回归。

## 能力边界与后续

这证明固定两层 Dense **timing-only** 推理可以在 3×3 完整物理阵列上以六活跃 Die、三空闲路由 Die 连续 Prefill+两 Decode 真实运行。它是 P1.2/P1.3 的一个非连续放置补充 case，不能当作 3×3 全 9 Die 主 case；没有验证 Dense/MoE 训练、MoE 推理、offload、AdamW、任意矩形大小、模型数值输出或四类 full-dimension。因此 M1/M2/M3 的发布 completion 仍为 false。下一步将此 EXPLICIT subset 合同接入四类完整图与容量规划，在代表主形状和 100-shape 矩阵上按同样双独立 source-bound 流程逐项实测；逐链路 packet/byte 计数若作为 P1.3 完整验收必需，需增加原生 per-link 观测再验证。
