# P3.2-R45：Dense 二十 Die 双步训练原生双 Fresh

日期：2026-09-18。沿矩形 Die Mesh 计划继续扩大完整 Dense timing 训练的真实运行范围。本轮使用当前源码提交 `0a8deffe` 和固定工具，选择 2×10 物理 mesh、TP10×DP2、两层、两步 SGD。先在 4 GiB 受管 scratch 中完成一次生产编译探针；随后在两个独立空 evidence 目录各自重新执行生产编译、物理梯度门禁、finalizer、ProgramIO resolver 和 NpuSim，未复用探针产物。

三次生产编译均通过 64 KiB wire SRAM 调度。每次源图 1042 个节点、投影 2400 个物理梯度任务、两个 DP 副本各 3124 个原生片段、linked manifest 共 6248 个片段。物理门禁覆盖 300 个参数状态、600 条逐步参数梯度路径、24960 个物理动作、410 条状态版本边和 110 组跨 Core 栅栏；实际物理 Die 为 0..19，合计绑定 50 个运行 Core。

两个独立 Fresh 均以 exit 0 完成原生仿真，makespan 均为 **378788 cycles**。每轮 NpuSim 输出有 600 次 SGD、40 次 CE forward、40 次 CE backward；2450 次 ProgramIO 初始化及 40 个 probe 在 resolved/applied/verify 三阶段均为 `pass=1`，router 与 D2D 链路排空残留为零。两轮的编译/执行收据逐字段一致，linked manifest、物理 DAG、NPUP、ProgramIO 均逐字节摘要一致；stdout 摘要分别记录，不要求两轮日志逐字节相同。完整审计摘要见 [机器收据](P3.2-R45-Dense二十Die双步训练双Fresh收据.json)。每轮总运行时间约 1590 秒，单份 linked JSON 约 145 MB，反映 TP10 的编译和定稿成本。

开发空间继续使用 `scripts/frontend_tmp.py`：每 5 秒检查受管根用量，4 GiB 上限，失败现场按每个 job 自身的 2 小时期限保留；编译探针成功后自动删除。两份 Fresh 原件共约 517 MB，在机器收据审计后以精确 job 路径显式 `release`，现用 `build-debug-final` 不清理。此次只新增范围验证和日志，没有修改生产源码或重新构建工具。

本案例扩大了 Dense timing 训练已实测的 TP×DP 范围；不证明数值梯度正确，不等于推理、MoE、offload、全 100 形状矩阵或 M1–M3 总体完成。Dense 全 Die 2×6/2×7 推理的 Embedding 整表 SRAM 暂存仍需按运行时索引和词表 tile 同时改造 HBM 搬运与 lookup 合同，不能通过仅缩小 DMA 长度消除。
