# P3.4-L：MoE 专家具名梯度源与双步 SGD 版本桥接

## 本阶段要解决的真实来源错位

Stage J 的十二份 expert gate/up/down `GemmWeightWgradWorkload.source_forward_op_ref` 原本是 P3 E2E expert forward operation ID；正式 public IR0/PhysicalNode 的 expert forward ID 则是 `T0.layer{0,1}.moe.expert{0,1}`。两个 ID 不能互作 forward/source 参数读的物理凭证，Stage K 的 0x25 严格源状态门禁会正确拒绝把 E2E ID 直接当 IR0 node。这一阶段新增单独源桥，保存两种身份及映射证据、12 份每投影单独FP32 gradient 源和 E2E step0→step1 参数版本 lineage；Stage J 原始 source/文件和 P1 root 正在绑定的旧 Python 均保持原字节。

## 开发内容

- 对每层、每 expert、每 gate/up/down：以 Stage J 原 operation binding 和 E2E version0 state、Stage G 对应的真实 `MOE_EXPERT_FORWARD` source node、该 node 对精确 FP16 `(m,n)` StateDecl 的 READ 与 Stage H EP owner/HBM Die 一一对应，重签供 public 0x25 使用的 `source_forward_op_ref=真实IR0 node.id`。原始 E2E forward/backward opRefs 分别保留为独立字段，拒绝手写相同标签自证。
- 从生产 `MoeCompileSequence` 每层相同参数组三投影按顺序读取 E2E source `gradient_op→raw_gradient_v0→sync→synced_gradient_v0→SGD→store/parameter_v1`，再与 step1 相同专家组 `parameter_v1→raw_gradient_v1→sync→SGD→parameter_v2` 接成唯一 source 版本依赖；要求原 E2E 参数对象的 `(logical_name,version)` 为 `(name,0),(name,1),(name,1),(name,2)`，版本1 StateVersion ID 前后完全同一实体。
- 对每份权重验证 FP16 原参数 extent64B 与0x25 FP32梯度 output128B，真实 EP owner 对应 physical Die；12份合计两层4个expert各 gate/up/down 三份，避免漏最后一层/最后一份down。Router rank1 zero-work 仍遵 StageJ/P2，不虚构16份 router gradient GEMM。

## 测试和能力边界

新 `test_moe_full_train_gradient_source_bridge` 涵盖十二份真实前向身份与 v0/v1/v2、删除 gate 或末层 down、伪造 source IR0/E2E forward/backward、调包任一 raw/synced gradient/SGD/store/v2、把 public0x25 forward ref 退回 E2E operation ID；均要求 fail closed。运行：

```bash
python3 -m unittest -q llm.test.frontend.unit.test_moe_full_train_gradient_source_bridge
```

初次 `Ran 15 tests in 51.882s, OK` 后补全第二步四个 operation refs 与反例，重新同源码整组复测 `Ran 15 tests in 53.578s, OK`（新Bridge5项、该测试模块引入的既有StageH放置10项）。新源码 `py_compile` 与 whitespace diff 审计通过后仅三条NEW文件本地定向提交，源绑定中的六旧Python保持StageK SHA。

独立只读源码审计还发现生产 `flexible_moe_multi_production.py` 原 `EXPERT_WGRAD` gate/up 旧MATMUL都把 `(m,H)` `backward_by_rank` 作为上游 dY，但真实 `EXPERT_DGRAD→SWIGLU_BACKWARD_TIMING` 已产 `(m,2I)` 的 `gate_up_grad`，正确gate/up各应消费独立 `(m,I)` 上游切片；down 才可消费 `(m,H)`。旧物理MATMUL再转FP32无法替代源精确0x25的真实gate/up/dW生产。该lowerer在Root P1 3×3 fresh source绑定期间完全不编辑，后续须补版本化真正operand ABI oracle、替换并做生产finalizer+ProgramIO+NpuSim反例。

下一版专家物理记录必须按实际源buffer完成三个独立0x25：gate/up 的 `X=activation_by_rank`（dispatch RECV后的FP16 `(m,H)`），`dY=dgrad_scratch_by_rank[rank].gate_up_grad`（真正 `SWIGLU_BACKWARD_TIMING` 输出FP16 `(m,2I)`，gate切片`offset0,size2mI`、up切片`offset2mI,size2mI`）；down 的 `X=projection_activated_by_rank`（前向SwiGLU物理输出FP16 `(m,I)`），`dY=backward_by_rank`（真实grad-dispatch收到FP16 `(m,H)`）。三份0x25各自把 FP32 `(H,I)/(H,I)/(I,H)` 输出写入原P2 EXPERT_GRADIENT buffer内连续的128B切片 `offset=0/128/256`，与源E2E每份 raw→sync→SGD 绑定同一EP owner、实际生命周期与DTE依赖。此处仅为由旧生产源码独立推导的必要operand合同，**尚无修复后的 finalizer/ProgramIO/NpuSim 收据**。

这批是**source-proven E2E 梯度/优化器版本线索，不是运行**。真正完整 MoE TRAIN 还须给每 projection forward activation 和反向 upstream gradient 建独立FP16 tape→真实 producer、FP32 dW SRAM分配与 physical native0x25 对应链接，Router gate 反向、shared Dense backbone 的 norm/attention/rope/residual/head/embedding 全部 source-backed backward，梯度同步 SGDs 与真实 HBM StateABI versions0→1→2，再为两层两步单 Global DAG/schedule/finalizer/ProgramIO/NpuSim 验收。已有R6 native0x25一次 scoped TIMING_ONLY 的非零输入收据不能证实任何专家梯度数值或完整训练。
