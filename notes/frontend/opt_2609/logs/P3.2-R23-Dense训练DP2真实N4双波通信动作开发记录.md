# P3.2-R23 Dense TRAIN DP2 双波通信 N4 动作

在 R22 已通过真实 2×2 fabric 验证的两个 DP 物理组与60条参数梯度路径上，逐路径构造**原生 N4 `FusionAction` 和 `RankProgram`**，不使用本地TP group来代替DP同步。每条路径八个动作：root rank0从自己的真实WGRAD局部复制，child rank1沿实际 XY 路由 SEND，root RECV/WAIT 后以 `ReductionContract(SUM, FP32→FP32→FP32, input_ranks=(0,1), RNE)` 对两份梯度求和，root再沿反向路由SEND同步结果，child RECV/WAIT。两波DTE的 logical_channel/peer/route/FP32 bytes 均通过公开 `_validate_rank_programs` 的互为收发与 event/dependency 严格检查；每个 `ChunkSlice` 的形状、TP offset、字节来自对应原始参数shard，没有固定2048B伪载荷。

测试：`PYTHONPATH=.:llm/test/frontend/unit python3 -m unittest llm.test.frontend.unit.test_full_dense_training_dp2_source -v` 3/3 PASS，并遍历60路径要求每条 `{LOCAL_COPY:1,SEND:2,RECV:2,WAIT:2,REDUCE:1}`；删除一条child SEND严格拒绝缺失配对，同时保留R22的2048B错误字节拒绝。

**当前只生成经过验证的跨副本 N4 动作计划；它还没有纳入 `TrainInterDiePlannedIR1` 或经过N5投影/GlobalActionDAG，也没有任何DP2程序的finalizer、ProgramIO或NpuSim执行证明。** 后续必须携带此计划穿过训练各层wrapper，给真实两副本 SGD建立REDUCE→同步结果的BufferABI和跨Die依赖；现有 `plan_train_forward` 对DP ALL_REDUCE仍严拒。
