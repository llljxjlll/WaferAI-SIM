# P4.4-R21：TP6 18KiB/Die 低 HBM 整块参数窗口可行性

日期：2026-09-17。此记录是原生 pager 开发前的**源级门禁调查**，不是 M2 offload 成功或原生验收。

使用真实固定 TP6、2×3 两层 Prefill+2Decode linked segment `/tmp/m1-dense-fixed-2x3-fresh0/segment_0.linked.json`，SHA256 `d4adc9530cf4fd81e0855e92dcfb279bd22177624c7b68be529e0a41e3555f2f`，由正式 `LinkedProgramManifest` 反序列化和验证。冻结前端 chunk preflight SHA256 `96d3ab8afc320cbf4a7a7810c77b8836f1cd01c6d8e2823f7fa84e5f8de422cc`。六个 Die 各有 15 个物理 parameter StateABI，合计 40,416B/Die，最大两个参数各 12,288B；另有 4 个 KV StateABI，各 576B（Prefill 段）。这些数值取自 linked record 的真实状态源与 LSU 消费者。

同模型、同 2×3 mesh 的正式内存物化预检：`resident_only` 在 12,288、16,384、18,432B/Die 均以 `memory_capacity_exceeded` 拒绝，需求为 19,536B/Die；将 18,432B/Die 与 1MiB 有限 external host 层配对，`external_offload` **前端物化预检**通过，物化 ID `workload_materialization_98f5bfe92312da49`。把 `[0,1600)` 与 `[14016,18432)` 明确保留给非参数状态/工作区后，参数窗口 `[1600,14016)` 大小为 12,416B。生产 linked 消费者预检返回 90 个状态、90 个整块候选、最大 12,288B、所有 offset=0、同一个 HBM 地址 1600；因此此容量 profile 不需要把现有完整参数 LSU 假装拆为 tile。返回值仍明确 `native_execution_admitted=false`。

下一步需把六 Die、114 个 parameter/KV StateABI、真实 KV 跨步容量、外存 backing/队列、DMA gate、物理路由和原生排空接入现有写死四 Die/76 状态/260 gate 的 pager；并在同硬件同模型下做 resident 拒绝与 offload 双 Fresh 配对。18KiB profile 只是消除 *12KiB profile 下单条完整 LSU 大于剩余窗口* 的硬阻断，不能证明其余容量、地址重叠或原生时序已经通过。
