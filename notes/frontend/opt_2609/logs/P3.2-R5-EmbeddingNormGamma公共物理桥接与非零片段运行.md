# P3.2 R5：Embedding 表与 Norm gamma 权重梯度公共物理桥接

时间：2026-09-15 UTC。范围：两个具名 timing-only 权重梯度原语的公共 ISA/前端/物理物化桥接，以及一个独立 0x23 片段真实运行。此记录不证明 Dense 或 MoE 全模型训练，也不证明梯度数值。

## 目标与完成内容

- 公共 compute opcode `EMBEDDING_TABLE_WGRAD_TIMING=0x23` 与 `NORM_GAMMA_WGRAD_TIMING=0x24`，直接指向已有内部 Prim72/73。0x23 只有 INT32 token 索引、FP16 表 tile、FP16 upstream hidden 三个源和独立 FP32 表梯度目标；离散 token 索引没有 dIndex。0x24 使用 FP16 forward activation 与 FP16 upstream，输出独立 FP32 `(hidden,)` gamma 梯度目标，RMS/Layer mode 严格区分。
- Wire 固定 192/92 字节 payload；codec 检查 rank/TP、16 项有效 index trace 与零尾、词表 tile、FP16/FP32 dtype、30-bit profile、四/三个绝对 16B 对齐且不重叠的 SRAM typed span。ProgramFormat、record lowering、finalizer DTO/BufferABI extent、NpuSim runtime relocation 全链路接入。
- canonical IR0 workload 的 `ComputeContract` 角色、`artifact_manifest` impl_ref、coarse 固定 record、linker 物理输入/输出角色映射一致。0x23 的来源角色为 `indices/table/upstream_hidden`，0x24 为 `forward_activation/upstream_hidden`。源码 action/schema/record 不把旧 MATMUL 或 dX 冒充 FP32 参数梯度。
- 内部 Prim 的 `data_size_input` 修为实际三个/两个物理源，使 `SRAM_BIND` 与 NpuSim 真实输入计数一致；NpuBase 加规范 `output` chunk，保留 `skip_output=true`，故仅收费不计算/写出数值梯度。

## 物理失败与修复边界

首次原 NPUP 的 native loader 缺新 variant relocation；接入四/三地址后，`SRAM_BIND` 检出 Prim 输入计数只有一项；随后 NpuBase 检出缺标准 output chunk。严格 ProgramIO 又拒绝 fixture 两核共享 storage root、缺 AUX 分配、SRAM region 名/4096B 大小与硬件不符。真实运行后探针 `exact=1,valid=0`，原因是 TASK 输出已 FREE 或未产生有效字节；独立片段按已验证唯一 FP32 终端输出由 finalizer 提升持久化，并将零输出明确标为 timing-only `TIMING_PARTIAL`，才得到 `valid=1`。这些故障均以真实失败收据驱动修复，未关闭校验。

## 未闭合的完整训练工作

片段来自 ISA selftest 的 scoped source fixture，不是两层 Dense/MoE forward tape 的真实反向时间线。完整训练仍需将原 token BufferABI 生命周期延长至 0x23、保留每层 Norm activation/upstream 来源、真实 attention/rope/residual/swiglu dX 与 QKV/O/gate_up/down/head 的 DX；现有公用 MATMUL 物理输出仅 FP16 extent，不能证明九类 GEMM 参数 FP32 WGRAD。下一原语目标是具名 `GEMM_WEIGHT_WGRAD_TIMING` FP16 activation/upstream→真实独立 FP32 weight-gradient extent 和负测，再接全模型物理门禁。此片段中 FP32 梯度内容是 timing probe 零播种，绝不表示数值 scatter 或训练收敛。
