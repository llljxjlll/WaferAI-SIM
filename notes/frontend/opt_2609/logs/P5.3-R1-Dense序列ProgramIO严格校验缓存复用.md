# P5.3-R1：Dense 序列 ProgramIO 严格校验缓存复用

日期：2026-09-17。P5.2-R3 六个固定 TP6 resident inference 形状的三段 ProgramIO 生成合计约 206–317 秒，是明确的前端 CPU 瓶颈。`build_timing_program_io()` 会对同一个不可变 linked source 作严格校验，紧随其后的 `ProgramIoContract.validate_against()` 又检查相同源/manifest；此前这两个调用不在同一个 `builder_validation_session()` 内，重复递归遍历很深的图。

本轮只把这两个调用包在**每个 segment 独立**的 `builder_validation_session()` 中，不删除任何显式校验，也不跨 segment、Fresh 或进程复用缓存。缓存以 Python 对象 identity 为键、context 退出即清除，源和合同仍照旧验证；最终 finalizer/resolver 和 NpuSim 的独立验证保持不变。源码提交：`78401c33`。

验证：`test_run_dense_sequence_runtime_canary` 1/1、`test_run_dense_native_mesh_matrix` 13/13 PASS。使用同一冻结 1×1 两层 Prefill→Decode→Decode 模型、同一 finalizer/resolver/NpuSim/simulation 与从空目录的两套真实原生执行，基线源码 `/tmp/p5-dense-resident-v3-frozen-6b9664be` 与仅这一处源码变更的隔离副本 `/tmp/p5-dense-pio-memo-bench-6b9664be` 均 exit0。三个 segment 的 linked SHA、NPUP SHA 和 ProgramIO SHA **逐字节一致**，NpuSim 都是唯一 `SIM_RESULT makespan_cycles=46279`，KV digest 也一致。

同一进程构造同一真实 1×1 source 的独立 microbenchmark 也得到 0.605→0.102 秒，合同 canonical JSON SHA256 两次完全相同 `335f684bc45d8955ca57036f9803b57bbb6c00d7d11ba24d63c888a9461d1b65`。完整执行的总 wall 受编译、仿真及并行负载影响，不能据 11.300→11.141 秒宣称整机加速；这一轮可靠结论是该 1×1 ProgramIO 阶段的重复深验被消除且原生产字节不变。固定 TP6 或更大图的性能与产物仍需另做同源码/工具冻结对照，不从小样本外推。

产物：`/tmp/p5-dense-pio-baseline-1x1-6b9664be` 和 `/tmp/p5-dense-pio-memo-1x1-6b9664be`。本改动既不改变模型运行能力，也不能据此宣布 M1–M3 完成。
