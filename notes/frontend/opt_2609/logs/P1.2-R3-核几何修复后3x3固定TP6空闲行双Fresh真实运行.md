# P1.2-R3：核几何修复后 3×3 固定 TP6 空闲行双 Fresh 真实运行

## 目标与结论

此前 [P1.2-R2](P1.2-R2-3x3空闲行TP6固定模型双Fresh真实运行.md) 的 NpuSim exit0 因 per-Die原生4×4/前端2×2 核失配，不能证明物理3×3空闲行路由。此处用冻结修复提交 `e1c3b5e66d60b505952551fcf76b103e122403ad` 与冻结 build-debug-final 三工具，在两个空目录 `/tmp/m1-geometry-fixed6-3x3-fresh0/1`、两个独立Python进程重新完整编译、finalizer、ProgramIO resolver和真实NpuSim。两次均exit0、`runtime_status=verified`，P5.1-R8的原始 stdout/hardware/产物审核一致。

固定同一两层 Dense TP6 模型在3×3物理 Mesh 上只把 Die `0,1,2,6,7,8` 作为计算rank，Die `3,4,5` 保持空闲但转发相邻D2D包；三段 `[PROGRAM_MEMORY]` 发出 LSU 的原生 runtime core按每Die4核精确落在六个活跃物理Die，没有在空闲行复制计算。实际 `[D2D_LINK]` 包括 `0↔3↔6`、`1↔4↔7`、`2↔5↔8` 的非零 N/S 传输，说明跨空闲行的物理多跳路线真的执行，而非只在编译placement里声明。
