# P0.3-R7：Dense 完整训练统一输入与真实前向源计划绑定

日期：2026-09-15。范围：P0.3/P3.2 的**输入与来源验证**；不存在 M1/M2 物理反向成功状态。

原 `ExperimentSpec.train` 严格仅接受 `backward=false,optimizer=none,recompute=none`，用作生产两层 TRAIN 前向 IR0 的精确来源；统一 `WorkloadRunRequest` 则能合法明确请求 `dense_training_e2e`、多 step、SGD/AdamW、mesh 与外部内存。把原 forward-only ExperimentSpec 误当作完整训练请求，会错把前向/optimizer motif 与用户真实训练目标联系起来。

新增 `passes/full_dense_train_request_binding.py`，只为当前真实 `FlexibleDenseTrainPlan` 的 SGD 要求构建独立 `DenseFullTrainRequestBinding`：先对用户请求执行原版 schema.validate，对逐参数血缘 `DenseFullTrainRequirements.validate_against(plan)` 执行独立重派生，再严密比对源模型架构、V/H/I/L、heads/KVheads/head dim/max sequence/dtype，真实 training batch/seq/step、row-major 全阵列 TP/DP/EP/PP 映射、SGD learning_rate/weight_decay、timing 范围。输出绑定 user case_id/request_digest 与实际 plan id/digest、gradient requirements digest，不含 runtime_verified/SUCCESS 字段；尚无对应物理 source task、StateABI、loss/DGRAD/WGRAD/sync/SGD/store 全链或 NpuSim evidence 时不能发布 M1。

此适配器只接受源计划已支持的 row-major 全阵列，非默认 die remap/idle die 映射必须由之后真正 P1 placement source 重建，不以 substring 或换 case id 假定本 source 可迁移。完整训练数值功能尚未实现，`execution.functional=true` 明确拒绝；AdamW 的独立 FP32/master/m/v/step StateABI 和 lowering 尚须新的源合同，不借 SGD 参数模板放行。

验证命令：`python3 -m unittest llm.test.frontend.unit.test_full_dense_train_request_binding llm.test.frontend.unit.test_full_dense_gradient_requirements`，7/7 PASS，独立请求 positive 在2×2/TP2/DP2 两层两步 SGD；故障样本使用新合法稳定 case ID 改模型 vocabulary 或 step_count、非默认 die 映射、SGD LR 漂移、未实现完整 functional，都明拒。本阶段没有 NpuSim 或外部内存运行，源码/日志依先源码后 exps 批次隔离推送。
