# P5.1-R9：核几何修复后全九 Die 真实 Dense 推理双 Fresh

## 目标、结果与旧记录更正

在 [P1.1-R1](P1.1-R1-前端原生核几何失配与矩形物理路由修正.md) 发现此前“3×3 全九 Die NpuSim exit0”实际只使用物理第一行之后，以修复提交 `e1c3b5e66d60b505952551fcf76b103e122403ad` 的独立冻结 worktree，重新从两个空输出目录、两个独立 Python 进程全链编译、finalizer、ProgramIO resolver 和运行 NpuSim。两个 3×3 scaled-all-dies 实际运行均 exit0、`runtime_status=verified`，并通过 P5.1-R8 的直接原生 stdout/硬件 JSON/产物物理 Die 审核，**九个逻辑 Die 0–8 全部对应九个真实物理 Die 0–8**；东西南北相邻 Die 的 24 条有向物理 link 均有非零 data 包。旧 R6 只作为失配硬件运行的诊断原始数据，不能计 M1/M3，本记录是新的有效双独立执行。

## 实际命令和冻结工具

两次相同完整入口，仅 `--output` 从 `/tmp/m1-geometry-all9-3x3-fresh0` 换到 `/tmp/m1-geometry-all9-3x3-fresh1`。使用 `/tmp/m1-native-geometry-freeze` 的绝对 `PYTHONPATH` 与 `build-debug-final` 冻结 finalizer/resolver/NpuSim ELF；旧 ELF `nm -C` 为 `U main`/`T sc_main`，无后来新增的 selftest 主函数污染。配置为 `--mesh-size 3x3 --scaled-all-dies --timeout 900 --compile-timeout 2400` 与冻结的 `p5_behavioral_simulation.json`。
