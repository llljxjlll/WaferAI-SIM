# 应该反映什么规律

1. 训练收益大还是推理收益大
  预期训练侧的 E2E 收益天花板更低，推理侧（尤其小 batch decode）更容易出现负结果，但这个负结果恰恰是 work1 最重要的卖点。
  - 训练一次完整迭代包含 backward + optimizer step，这部分完全不经过融合算子，会直接稀释 E2E 收益——这正是 FLUX 自己的发现（A100 NVLink 训练：63% 算子级 overlap efficiency 只换来 1.04–1.05× E2E）。work1 的训练也报"完整迭代"的话，预期同样会被稀释，且稀释程度取决于 backward/optimizer 占迭代时间的比例。
  - 推理 decode 在 batch=64 这一档，是最可能复现"负结果"的地方——直接对应 DITRON 的实测（batch<128 时 vLLM 反而更快）和 FLUX 的实测（H800 NVLink 上 decode shape 的 overlap efficiency 全线为负）。这两篇论文的共同机理是：互联越强 + shape 越小，融合越无利可图。而 wafer 的 D2D 带宽（1TB/s）远超 NVLink，如果直接套用"互连越强融合收益越小"这条规律，batch=64 的 decode 很可能出现负的算子级融合收益。
  但这正是 work1 定位的关键实验：笔记里已经反复强调（2311–2316 行），wafer 的价值不是"融合收益变得更大"，而是"可隐藏区扩大，让 GPU 集群上会失效的小 shape 场景在 wafer 上重新变得可行"。所以预期的叙事是——GPU 集群上 batch=64 这类小 shape decode 是负结果（DITRON/FLUX 已经实测证明），但同样的 shape 在 wafer 上因为 R/B 比值更优，即使不能给出很大的加速比，也应该能把"负"拉回到"正"（或至少比 GPU 集群的负值更接近 1）。如果 wafer 上 batch=64 依然是负的，那就说明可隐藏区扩大得还不够，是一个需要在 discussion 里正面讨论的结果，而不是失败。

2. Amdahl效应 端到端加速比单算子小 
  训练的 Amdahl 效应来源和推理不同——这是两种不同机制导致的相似现象。
  - 训练：Amdahl 稀释来自 backward + optimizer（不可融合的部分）。这部分和融合算子完全无关，纯粹拉低分母。
  - 推理（尤其 decode）：Amdahl 稀释来自调度/launch 开销，不是不可融合的计算，而是 MPK 消融揭示的"通信重叠本身只贡献 1.1×，大头来自 kernel launch 消除"（笔记规律二）。也就是说，即使把通信完全隐藏了，decode 场景下算子间的调度开销依然是大头。
  两者都会让 E2E 加速比远小于算子级，但训练的稀释更"结构性"（backward/optimizer 时间占比是模型架构决定的，很难通过调度优化消掉），推理 decode 的稀释更"工程性"（launch/调度开销理论上可以通过更好的 runtime 消除）。如果 work1 只做了计通融合、没有像 MPK 那样处理 launch/调度开销，那么 decode 场景的 Amdahl 效应可能比训练更严重（因为训练至少大头计算是有效的，decode 大头可能是调度开销）。这也是为什么 MPK 特意强调"通信重叠在 decode/小 batch 场景根本不是主要矛盾"——如果这个规律在 wafer 上依然成立，work1 的 decode E2E 实验应该也会看到类似现象，需要提前在 discussion 里说明这是 launch/调度开销导致，而非融合算子本身无效。
  
由于数据流架构行为由编译器在编译器决定，所以理论上训练的Amdahl效应应该更不明显

3. 训练 seq_len 2304/36864情况下区别
  这直接对应 Exp 1.1 里你自己建立的达成率预期（笔记 2567–2568 行），加上这次训练用了 TP 紧凑 + EP 非紧凑的混合并行，两个效应会叠加：

|                    | seq_len=2304（短）                                   | seq_len=36864（长）            |
| ------------------ | ------------------------------------------------- | --------------------------- |
| 达成率                | 明显偏低——搬运量小，DTE 固定开销（T_setup+T_lat）占比高             | 紧贴理论曲线——已进入带宽饱和区，固定开销可忽略    |
| TP（紧凑）vs EP（非紧凑）差距 | 被放大——"M 太小"与"非紧凑跳数开销"两个效应叠加，EP 部分达成率明显更差          | 被压缩——两者都接近饱和，紧凑/非紧凑跳数差异占比很小 |
| 绝对 E2E speedup     | 较低，且可能因 GEMM tile 不够（类似 FLUX 的 warp 数太少失效机理）进一步打折 | 较高，是这组实验里最接近理论预期的干净验证点      |

预期结论：如果实测出来 2304 档的 EP（非紧凑）部分达成率明显低于 TP（紧凑）部分，而 36864 档两者差距很小，就同时验证了两条已经写进笔记的结论——"小 M 暴露固定开销"和"非紧凑放大跳数开销"是可加性的两个独立效应。


4. 推理 decode batch_size = 64/512情况下的区别
这里的关键是：decode 里其实有两类融合算子，驱动变量不同——FFN/MoE 的 Dispatch+GroupGEMM/Combine 由 batch 驱动，Attention 的 Flash-Decode 类通信由累计 KV 长度驱动（这次固定在 36864，不随 batch 变化）。所以：
- batch=64：FFN/Dispatch 侧的 M 很小（类似 FLUX 的小 m decode 失效机理），预期这部分收益偏低甚至为负；但 Attention 侧因为 KV=36864 固定不变，收益应该和 batch=512 时差不多（因为它的驱动变量根本不是 batch）。
- batch=512：FFN/Dispatch 侧的 M 变大，预期收益明显改善，越过 DITRON 观测到的 batch=128 阈值后应该转正、甚至可观；Attention 侧收益基本不变。
预期的核心现象：从 64 到 512，E2E 收益的提升主要来自 FFN/MoE 侧，Attention 侧基本持平——这是一个可以直接拆解验证的点（如果做了模块级 breakdown 的话），也是"两个变量组合暴露交叉点"这条规律（规律三）在 work1 自己实验里的具体体现：batch 只影响 FFN 侧的可隐藏区，不影响 attention 侧的可隐藏区，这两者不能被同一个"batch scan"完全刻画，KV 长度固定这个设计选择本身就意味着 attention 侧的行为在这组实验里是一个常量背景，不是变量。


5. dense模型和moe模型应该有什么区别？
- E2E 收益的 Amdahl 结构不同：对应 TileLink 发现（规律一）——dense 模型 E2E speedup 应贴近 MLP 单层 speedup（MLP 主导整体时间）；MoE 模型 E2E speedup 应低于 MoE 单层 speedup（非 MoE 层和 MoE 层各占一部分时间，E2E 落在两者之间），需提前预期，否则结果出来会显得"MoE 支持力度不够"。
- EP 类算子 D （mesh阵列长宽乘积）衰减更慢，但要大 mesh 才能体现：对应笔记 2707–2727 行，Dispatch+GEMM（EP）通信量随 D 衰减是 O(1/√D)，比 GEMM+RS（TP）的 O(1) 平台期慢得多。6×6=36 die 的大 mesh 上，MoE 模型（含 EP 算子）的可隐藏区预期比 dense 模型（纯 TP）保留得更久——若观测到 MoE 相对收益比 dense 更稳健，印证这条理论曲线；但当前设计固定单一 mesh size，只能作为单点参照，验证不了完整曲线。
- MoE 有两个"脏"因素拉低达成率，dense 没有：① 动态路由——集合通信具有动态性（哪些 token 去哪个专家运行时才确定），专家负载倾斜会破坏理论模型的对称性假设（写作.md 1207 行），预期 MoE 实测达成率方差更大、平均值可能系统性低于理论曲线；② DeepSeek-V3 用 MLA，没有标准 attention shape（笔记 2517/2548 行），"MoE·大"这个模型点在 Attention 层的实验天然缺失（22 根 bar 结果展示里"DS-V3 没有 attn bar"，笔记 2642 行已预留此空缺），需在结果展示中明确标注，不能默认它和其他模型一样有完整 Attn+MLP 两组数据。

6. Dense模型和moe模型的并行切分设计
Dense："TP=3×3（紧凑）+ DP=2×2（前向零通信）" MoE："TP=3×3（紧凑）+ EP=2×2（非紧凑，路由通信）"
两者物理上占用完全相同的 36 die footprint，内层 TP 完全一致，唯一的差异就是外层 2×2 这个维度上跑的是"零通信复制"还是"有路由通信的专家并行"。这意味着：
dense 和 MoE 的 E2E speedup 之差，在很大程度上就是直接把 EP dispatch/combine 通信本身的净影响单独测出来了（还叠加了下面第②③点的 MoE 特有因素）。这是一个比大多数论文（笔记规律七指出的"没有单变量解耦扫描"空白）都干净的受控设计，值得在论文里明确点出来。
