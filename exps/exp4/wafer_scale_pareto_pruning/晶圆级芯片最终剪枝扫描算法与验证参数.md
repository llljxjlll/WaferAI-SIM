# 晶圆级芯片最终剪枝扫描算法与验证参数

## 1. 用途与实现边界

本文用于指导agent实现完整扫描与帕累托剪枝。core、计算KGD、HBM/端口、复合矩形和wafer的面积及物理约束应由已有物理模型函数计算，本文不重复这些建模推导；程序必须先生成物理可行点，再执行本文定义的指标计算、联合分组、组内帕累托求解和哨兵插入。

最终配置固定为：

```text
port_placement = clustered
pareto_version = V1
objectives = [wafer_compute, wafer_hbm_capacity,
              wafer_hbm_noc_bandwidth, wafer_min_d2d_bisection,
              core_sram_score]
group_key = [router, N16_or_Nlt16, n_ctrl]
sentinel = one minimum-network-hops point per non-empty group
control_core_is_objective = false
cost_is_objective = false
```

## 2. 输入、输出与单位

### 2.1 输入

程序输入为独立扫描参数的笛卡尔积和一组确定的物理模型常量。所有带宽统一使用GB/s，面积使用$\mathrm{mm^2}$，长度使用mm，容量使用MiB或GB，算力字段名称必须明确GFLOP/s或TFLOP/s。

### 2.2 输出

程序至少输出：

```text
candidate_id
all independent search parameters
physical_feasible and physical_reject_reason
all derived physical fields needed by the five objectives
five V1 objective values
group_key
is_group_pareto
is_sentinel
sentinel_was_new
network_hops_proxy
hardware_cost_proxy                 # diagnostic only
dominated_by_candidate_id           # when available
prune_reason
```

物理不可行、帕累托支配和未被选为哨兵必须使用不同的`prune_reason`。若一个哨兵原本被支配，应同时记录其支配者和强制保留原因。

## 3. 独立扫描参数

### 3.1 完整离散空间

|程序字段|符号|扫描值|取值数|说明|
|---|---|---|---:|---|
|`n_ctrl`|$n_{ctrl}$|$\{1,2\}$|2|单core控制核数；2表示第二个核专门控制DTE|
|`router`|$r$|`base`, `broadcast`, `reduce`, `both`|4|`both`在报告中写作broadcast+reduce|
|`B_link`|$B$|$\{64,128,192,256,384,512\}$ GB/s|6|NoC链路、端口和通信部件目标带宽|
|`K_MiB`|$K$|$\{1,2,3,4\}$ MiB|4|单core SRAM容量|
|`B_S`|$B_S$|$\{256,512,768,1024\}$ GB/s|4|单core SRAM聚合带宽|
|`N_PE`|$N_{PE}$|$\{1024,4096,8192,12288,16384\}$|5|单core矩阵PE数|
|`N`|$N$|$\{4,8,16,32\}$|4|计算KGD的$N\times N$ core mesh边长|
|`e_HBM`|$e_H$|$\{1,2\}$|2|HBM放置边数；2表示相对双边|
|`m_HBM_per_edge`|$m$|$\{1,2,3,4\}$|4|每条HBM边的stack数|

独立参数总组合数：

$$
2\times4\times6\times4\times4\times5\times4\times2\times4
=\boxed{122{,}880}.
$$

core级参数有：

$$
2\times4\times6\times4\times4\times5
=\boxed{3{,}840}
$$

种组合。端口位置不是搜索参数，固定：

$$
\boxed{port\_placement=clustered}.
$$

### 3.2 稳定排序

物理可行点按以下字段顺序升序排序，再从0开始分配`candidate_id`：

```text
(n_ctrl, router, B_link, K_MiB, B_S, N_PE,
 N, e_HBM, m_HBM_per_edge)
```

字符串router应使用一个固定顺序进行扫描和报表输出。建议：

```text
[base, broadcast, reduce, both]
```

`candidate_id`只保证可复现性，不得作为设计优劣指标。

## 4. 剪枝阶段所需衍生参数

物理模型完成后，每个可行点必须至少提供下列字段。表中只列剪枝需要的关系，不重述面积和物理约束模型。

|字段|计算式或来源|用途|
|---|---|---|
|`modules_per_wafer`|$N_D=n_xn_y$|五项wafer级指标|
|`P_mat_TFLOPs`|$P_{mat,Die}=N^2P_{mat,core}$|单复合矩形算力|
|`HBM_capacity_GB`|$e_HmC_H$|单复合矩形HBM容量|
|`HBM_NoC_observable_GBs`|$e_H\min(m\alpha_HB_H,t_HB)$|计算侧可见HBM带宽|
|`D2D_edge_one_dir_GBs`|$\min(dB,512)$|单边D2D单向带宽|
|`wafer_nx`,`wafer_ny`|$n_x,n_y$|D2D截面和距离|
|`A_core`|物理模型输出|分布诊断|
|`comp_die_area`|物理模型输出|成本和分布诊断|
|`module_area`|物理模型输出|几何分布诊断|
|`t_hbm`|物理端口分配结果|HBM可观察带宽|
|`d_d2d`|物理端口分配结果|D2D带宽|

剪枝阶段计算：

$$
P_W=N_DP_{mat,Die},
$$

$$
C_{H,W}=N_De_HmC_H,
$$

$$
B_{H,W}^{obs}=N_De_H\min(m\alpha_HB_H,t_HB),
$$

$$
B_{D,W}^{cut}=\min(n_y,n_x)B_{D,edge}^{\rightarrow},
$$

$$
S_{SRAM}^{core}=\sqrt{\frac{K}{3\ \mathrm{MiB}}\frac{B_S}{256\ \mathrm{GB/s}}}.
$$

固定常量：

|常量|定值|
|---|---:|
|单HBM容量 $C_H$|16 GB|
|单HBM峰值带宽 $B_H$|819.2 GB/s|
|HBM目标利用率 $\alpha_H$|0.90|
|每边D2D PHY单向上限|512 GB/s|
|SRAM容量归一化 $K_{ref}$|3 MiB|
|SRAM带宽归一化 $B_{S,ref}$|256 GB/s|
|浮点相对容差 $\epsilon_{fp}$|$10^{-9}$|

诊断字段：

$$
C^*=\left\lceil\frac{B}{128\ \mathrm{GB/s}}\right\rceil,
\qquad
M_H=e_Hm,
$$

$$
H_{net}^{proxy}=2\frac{N^2-1}{3N}
+\frac{n_x^2-1}{3n_x}
+\frac{n_y^2-1}{3n_y}.
$$

成本代理只用于诊断和哨兵平局裁决：

$$
C_{HW}^{proxy}
=\frac{N_DA_C}{28255.443\ \mathrm{mm^2}}
+\frac{N_De_Hm}{154}.
$$

## 5. 完整扫描算法

### 5.1 阶段A：生成core可行点

```text
feasible_cores = []
for n_ctrl in [1, 2]:
  for router in [base, broadcast, reduce, both]:
    for B in [64, 128, 192, 256, 384, 512]:
      for K in [1, 2, 3, 4]:
        for B_S in [256, 512, 768, 1024]:
          for N_PE in [1024, 4096, 8192, 12288, 16384]:
            core = evaluate_core(...)
            if core passes every core physical constraint:
                feasible_cores.append(core)
            else:
                log reject_reason
```

回归计数：

```text
raw_core_points      = 3,840
feasible_core_points = 1,884
```

### 5.2 阶段B：扩展到计算KGD、HBM和wafer

```text
feasible_records = []
for core in feasible_cores:
  for N in [4, 8, 16, 32]:
    comp_die = compute_die(core, N)
    for e_H in [1, 2]:
      for m in [1, 2, 3, 4]:
        if comp_die violates reticle/area limits:
            continue

        hbm_limits = compute_hbm_shoreline_and_bisection_limits(...)
        if m exceeds either HBM limit:
            continue

        ports = allocate_clustered_hbm_and_d2d_ports(...)
        if ports infeasible or d_d2d < 1:
            continue

        module = build_compute_kgd_hbm_rectangle(...)
        perf = calculate_peak_capabilities(...)
        wafer = tile_module_in_215mm_by_215mm_window(...)
        if wafer cannot contain at least one module:
            continue

        feasible_records.append(all fields)
```

必须逐层`continue`，不能先计算帕累托再删除物理不可行点。当前回归计数为：

|阶段|通过点数|计数口径|
|---|---:|---|
|完整原始组合|122,880|所有9个独立参数的笛卡尔积|
|core可行后扩展|60,288|$1,884\times4\times2\times4$|
|计算KGD光罩/面积通过|27,200|按$e_H,m$展开后的记录计数|
|HBM shoreline与NoC截面通过|5,878|记录计数|
|端口通过|5,878|所有点均满足每边至少1个D2D端口|
|wafer装填通过|5,878|所有点至少放入1个复合矩形|

物理可行率：

$$
\frac{5{,}878}{122{,}880}=\boxed{4.78\%}.
$$

### 5.3 阶段C：稳定编号和指标计算

```text
sort feasible_records by SEARCH_FIELDS
assign candidate_id = 0 ... 5,877

for x in feasible_records:
    x.wafer_compute_TFLOPs = modules_per_wafer * P_mat_TFLOPs
    x.wafer_hbm_capacity_GB = modules_per_wafer * HBM_capacity_GB
    x.wafer_hbm_noc_GBs = modules_per_wafer * HBM_NoC_observable_GBs
    x.wafer_min_d2d_bisection_GBs = min(
        wafer_bisec_x_one_dir_GBs,
        wafer_bisec_y_one_dir_GBs)
    x.core_sram_score = sqrt((K_MiB / 3) * (B_S / 256))
    x.network_hops_proxy = H_die_avg + H_wafer_avg
    x.hardware_cost_proxy = normalized_compute_area + normalized_hbm_count
```

成本归一化参考值必须从全部5,878个物理可行点计算一次并冻结，不能在每个分组内重新计算。

### 5.4 阶段D：建立联合分组

```text
N_class = "N16" if N == 16 else "Nlt16"
group_key = (router, N_class, n_ctrl)
groups[group_key].append(candidate)
```

理论上有16组。当前只有12组，因为不存在$N=16,n_{ctrl}=2$可行点。空组不创建哨兵，也不进入分母。

### 5.5 阶段E：组内帕累托前沿

五个字段全部最大化：

```text
BENEFIT_FIELDS = (
    wafer_compute_TFLOPs,
    wafer_hbm_capacity_GB,
    wafer_hbm_noc_GBs,
    wafer_min_d2d_bisection_GBs,
    core_sram_score,
)
```

带相对容差的比较：

```text
approximately_ge(a, b):
    scale = max(1, abs(a), abs(b))
    return a >= b - 1e-9 * scale

definitely_gt(a, b):
    scale = max(1, abs(a), abs(b))
    return a > b + 1e-9 * scale

dominates(x, y):
    return all(approximately_ge(x[i], y[i]) for i in objectives)
       and any(definitely_gt(x[j], y[j]) for j in objectives)
```

确定性的增量skyline算法：

```text
pareto_front(points):
    front = []
    for point in points ordered by candidate_id:
        if any(other dominates point for other in front):
            continue
        front = [other for other in front
                 if not point dominates other]
        front.append(point)
    return sort(front by candidate_id)
```

所有目标相等但体系结构参数不同的点继续保留。若需要去重，只能删除所有仿真器可见参数也完全相同的真正重复记录，不能只按五维目标向量去重。

### 5.6 阶段F：插入每组一个哨兵

```text
choose_sentinel(group):
    return min(group, key=(
        network_hops_proxy,
        hardware_cost_proxy,
        -wafer_min_d2d_bisection_GBs,
        -wafer_compute_TFLOPs,
        candidate_id))
```

```text
final_by_id = {}
for each non-empty group:
    front = pareto_front(group)
    insert every front point into final_by_id
    sentinel = choose_sentinel(group)
    mark sentinel.is_sentinel = true
    insert sentinel by candidate_id

final_points = sort(final_by_id.values(), by=candidate_id)
```

使用`candidate_id`集合去重。哨兵若已在前沿中不重复计数；当前12个哨兵均为纯前沿之外的新点。

### 5.7 阶段G：输出审计和分布

程序必须输出：

1. 每级物理过滤的输入数、通过数和拒绝原因；
2. 每个分组的可行点、纯前沿点、新哨兵和最终点数；
3. 剪枝前后每个独立参数的取值分布；
4. 五个目标的最小值、中位数、最大值和不同取值数；
5. DTE channel、HBM stack、HBM/D2D端口、面积、装填数、成本和网络距离分布；
6. 最大单项、五指标平衡、最低成本和各分组语义代表点；
7. 被删除点的`prune_reason`，可行时记录一个支配者ID。

“五指标平衡点”只用于报表，不参与剪枝。选择规则为：先最大化五项相对各自最大值的最小值，再最大化五项归一化值之和，最后取较小`candidate_id`。

|$N<16$、单控制核|$(1,base,256,3,768,4096,8,2,2)$|总体五指标平衡点|
|$N<16$、双控制核|$(2,base,384,2,1024,8192,4,2,1)$|验证专用DTE控制核；35.389 PFLOP/s、4.608 TB/s D2D|

$N=16$、双控制核没有物理可行点，程序应报告空组，而不是生成虚构代表点。

## 10. 结果趋向性与后续探索

### 10.1 当前趋向性

1. $N=4$占主导，说明较小计算KGD和较高wafer装填数在五项峰值指标中有优势。
2. 高SRAM容量/带宽较多，说明$S_{SRAM}^{core}$成功阻止候选集完全偏向小SRAM。
3. 192–384 GB/s链路和2–3个DTE channel构成主要通信区间；64和512 GB/s两个极端较少。
4. HBM倾向双边、每边一个stack，体现容量/带宽收益与复合矩形装填损失的平衡。
5. 单、双控制核数量接近主要由分组键产生；只有详细仿真证明双控制核带来通信重叠收益后，才能解释为值得长期保留。

### 10.2 当前缺少的探索方向

- workload执行时间、计算利用率和roofline匹配；
- clustered HBM/D2D端口的最大链路负载、拥塞和P95/P99延迟；
- 专用DTE控制核的发射间隔和计算—通信重叠收益；
- 功耗、功率密度、热热点和降频；
- HBM容量需求、数据局部性和远端访问比例；
- 真实美元成本、良率、封装、冗余和故障绕行；
- 矩阵与vector算力比例独立变化；
- $N=16$双控制核这一当前物理不可达方向。
